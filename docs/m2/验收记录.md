本轮新增/加强的确定性用例：

- 无账号、仅别名账号、无效/过短学号：零网络请求，README 与页面明确不可用；
- 已绑定但无历史快照：仓库直接查询当前学号，2×2 组件刷新按钮可用；
- A 请求在途时换 B、同号改密、删号、清缓存：旧结果被拒绝；B 失败不显示 A；同号历史保留；
- 清理失败：旧值立即隐藏，新仓库/重启后仍隐藏；修复文件后只恢复清理、不自动查询；
- FIRST_SAVE：不属于当前绑定的 v2 与异号 v1 被隔离，之后才允许查询当前账号；
- 同号 v1 迁移保留原时间；异号/损坏拒绝；marker 幂等；marker 已提交但 v2 丢失时从同号 v1 重建；
- 未绑定 v1 不展示也不提前删除；
- 账号失效器清理余额时不反向读取账号读取面（计数为 0）；
- 受控身份面/状态 `toString` 与公开方法不含密码或 `CredentialPayload`；
- 组件无绑定/清理中隐藏旧值，失败保留同账号历史值和绝对时间；
- Compose 页无学号输入框，清理失败后仍保留重试入口；
- Provider/Worker FQCN、刷新 action、唯一任务名保持不变。

## 2. 模拟器设备验证

设备：Lody Android Emulator 面板中的 `upcpocket_api36`（Android 36，x86_64）。
执行前用面板 `list` 确认设备已启动、`occupancy=available`，未接管其他会话；所有 adb 命令
显式使用 `-s emulator-5554`。

### 2.1 覆盖升级

1. 覆盖前应用数据中没有学校账号（`no_backup/school-account/` 为空），安装包仍为旧版 UI：
   首页显示独立“本人学号”输入框，账号页说明“校园卡余额仍按页面输入的学号查询”。
2. 在旧版中保存一个**虚构** 8 位数字账号与虚构密码，只写入本机；未点击余额查询，未联网。
   确认生成 `school-account-v1.enc` 与 `school-account-state-v1.json`。
3. 用最终 `app-debug.apk` 执行 `adb install -r`，**未卸载、未清应用数据**；安装成功，账号密文
   与状态文件仍在。
4. 启动 M2 后账号页显示“已保存，尚未验证 · 20••••01”和“余额查询学号：20••••01。仅由登录名
   整串识别，尚未经过学校身份验证。”；首页余额区显示“当前绑定学号：20••••01”，没有学号
   输入框，提供“查询 / 刷新余额”“前往学校账号设置”“仅清除余额缓存”。
5. 使用 UIAutomator 层级核对：旧版首页存在 `android.widget.EditText`；M2 首页余额区没有
   `EditText`，也没有“本人学号”输入提示。
6. 最终文案修正后重新执行 `:app:assembleDebug`、`:app:testDebugUnitTest` 与 lint，并再次
   `adb install -r`。删除虚构账号后的最终包首页显示“请先设置学校账号”，UIAutomator 统计
   首页 `EditText` 为 **0**；首页说明已改为“按当前统一账号中的本人学号查询”。

### 2.2 2×2 组件

覆盖升级前桌面已有校园卡 2×2 实例，保留未重建。M2 启动后该实例显示：

```text
校园卡
学号 20••••01
尚未查询
已绑定，点击刷新查询
```

说明组件在**没有历史成功快照**时仍从当前绑定得到脱敏学号，并保留可刷新入口。为避免向真实
校园接口发送虚构学号，**没有点击组件刷新，也没有点击页面查询**。

### 2.3 删除账号与组件撤下

在账号页确认删除虚构账号后：

- 账号页回到“未设置；保存后仅在本机加密存储”，显示“本机学校账号与关联个人会话/缓存已删除。”；
- `no_backup/school-account/` 只保留 152 字节的空状态文件，`school-account-v1.enc` 已删除；
- 桌面组件立即变为“未绑定学校账号 / 尚未查询 / 打开应用设置学校账号”，不再显示旧脱敏学号；
- 未产生任何余额缓存文件。

这验证了“删除账号”与“仅清余额缓存”分开，以及换号/删号后组件不等新查询成功就撤下旧值。
设备上的虚构账号已删除，模拟器恢复到验证前的无账号状态。

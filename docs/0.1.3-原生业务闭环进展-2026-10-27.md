## 2. 课表：App 内同步

### 实现

- 新增 `data/school/SchoolScheduleProtocol.kt`：解析学校课表页公开前端使用的
  `GET /timetable/wap/default/get-index` 与 `POST /timetable/wap/default/get-data`（`year`、`term`、`week`、`type=1`）。
  严格校验 `e`、`d`、`termInfo`、`countweek`、`classes`、`course_name`、`weekday`、`lessArr`；
  `classes: []` 是合法空周；缺字段、非数组、非整数、节次越界一律报错；`e=10013` 单独按登录失效处理。
- 新增 `data/school/SchoolScheduleSync.kt`：逐周数据 → 同步计划。连续节次合并；同一课程跨周聚合；
  课程身份优先 `course_id`，没有时用“名称+教师”；周数不足、节次超出当前作息都明确失败，不丢课。
- 新增 `ui/schedule/SchoolScheduleSyncScreen.kt`：
  - WebView 只允许 `https://*.upc.edu.cn` 导航；**只有** `https://app.upc.edu.cn/site/weekschedule/...`
    才挂载数据桥（具名 `ScheduleDataBridge`），CAS/门户页不暴露桥；
  - 固定脚本只请求上述两个端点，`location.origin` 与顶层框架校验；页面跳转/重登会撤销桥并作废未完成请求；
  - 单请求 25 秒超时、响应 2 MiB 上限、串行读取、可取消；任一周失败即停，不写半份；
  - 读取完成才进入原生预览；确认后在同一 Room 事务写入。
- `ScheduleRepository.saveSchoolTerm`：只替换“该学期 + `source=school`”的会话与 `S` 前缀课程；
  保留自定义日程、CSV 导入数据、显示覆盖；重复同步幂等；事务内 `beforeCommit` 失败会回滚。
- 学期日期语义：
  - 已有本地学期：**优先保留用户已保存的开学日**；预览里可修改并会明确标记“用户确认”；
  - 只有所选学期就是学校当前学期时，才使用 `params.startday`（待真实响应核验）或“今天 + 当前教学周”推算；
  - 历史学期没有日期时，预览要求用户填写第 1 周周一后才能写入；
  - 同步不再改写用户选择的每周起始日、学期名或 `isCurrent`；是否设为当前学期由用户在预览里勾选。
- 第 14 节：默认作息仍是 13 节；设置页可手动补第 14 节并填写时间；同步遇到超出作息会列出具体周/课程并停止，
  不静默丢弃。网格/详情/今天页/组件都读取同一份作息。

## 3. 会话与退出

- 新增 `data/prefs/SchoolSessionStore.kt`：**仅图书馆业务 token** 使用 Android Keystore 的 AES-GCM 密钥加密后
  写入应用私有 SharedPreferences；密钥/密文损坏时删除并重登，不崩溃；`allowBackup=false`，不进入系统云备份。
- 「更多 → 学校登录」新增：
  - “记住学校登录”开关（默认关）；
  - 图书馆会话状态；
  - “退出学校登录（清理图书馆 token 与学校 Cookie）”。
- 关闭开关或退出会清除加密副本、内存 token，并按域名过期 UPC 业务 Cookie（app / cas / i / libspace）。
- 图书馆登录页不再 `removeAllCookies()`：成功或销毁只清 `libspace.upc.edu.cn` 自己的 Cookie，不会踢掉课表会话。
- **边界（不夸大）**：课表会话由系统 WebView 的 Cookie 管理，**不是**本类加密的；系统 WebView 的 Cookie
  落盘行为与本机验证见 §5，不能用 Keystore 说成“WebView Cookie 已加密”。CAS ticket / OAuth code 不作为长期令牌保存。

## 4. 图书馆状态

- `LibrarySeatProtocol` 拆分：
  - `parseCurrentReservations`：`data: null` 才是明确的“无当前预约”；`data` 为对象等其它类型报格式错误。
  - `parseHistoryReservations`：必须是 `{reservations: [...]}`；缺数组报格式错误。
  - 记录缺 id / 日期 / 起止时间 / 座位标识直接报错，不再 `mapNotNull` 成空列表。
- 预约核对 `LibraryReservationMatch`：日期 + 完整起止时间 + 座位标识；并要求记录 id 不在提交前集合里，
  避免用旧列表或同时间别的座位证明成功。
- ViewModel：
  - 预约请求失败/超时也会先查询核对；只有核对到**新记录**才显示成功；
  - 核对失败显示“结果待确认”，保留旧列表；
  - 取消请求与服务端最终状态分开；核对失败保留列表与该预约的“待确认”标记，不清空、不自动重试；
  - “我的预约”显示上次成功读取时间、刷新失败原因；没有成功读取时不再显示“没有预约”。
- 空教室查询保持不变，并在模拟器复测通过（见 §7）。

## 5. 待验证与已知边界（必须如实阅读）

1. **课表真实契约未验证**：暂停代码按公开学生页面 `get-data/type=1` 实现；第三方 `astrbot_plugin_upc`
   使用 `get-datatmp/type=1`，并且按 `week` 字段过滤，暗示返回可能是整学期结构。没有本人账号，
   本轮不能确认哪一个/两者的真实行为；已分别记录，未混用字段假设。真机首跑需先看“学期列表 → 第一周预览”
   是否合理，若不匹配会报格式错误而不是静默写错。
2. `params.startday` 只在当前学期作为候选；存在性、语义、是否属于所选学期均未验证。
3. 课表登录后的学期选择、整学期读取、预览确认、日期保留尚未用真实账号跑通；模拟器只验证到登录页加载。
4. 图书馆 CAS 登录、token 交换、馆区/座位、提交预约、取消与“我的预约”核对均待本人账号。
5. “记住登录”只持久化图书馆 token；课表重启复用依赖 WebView Cookie。模拟器未能用真实登录验证重启复用；
   若系统清理 Cookie，会回到登录页，不会伪造成功。
6. 切换账号：图书馆 token 会重新验证并清除旧值；课表接口未提供稳定账号标识，**无法自动识别换号**。
   同一设备换人登录后，旧同步数据仍可能显示；需要用户手动“退出学校登录”并重新同步。此限制尚未解决。
7. 第 14 节需要用户自己填时间；不预置“UPC 官方作息”。
8. 外置导出脚本的严格校验尚未修补（主流程已不依赖脚本）。

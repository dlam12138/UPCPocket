# 隐私与数据说明

UPC Pocket 是非官方校园工具。应用直接访问对应校园服务，不使用本项目自建的数据中转或账号服务器。

当前版本 **2.0.3** 提供“首页 → 设置 → 学校账号”：仅在用户主动点击“加密保存到本机”时，保存当前一个学校账号与密码；默认不保存，也不会把“记住学校登录”开关自动解释为同意保存密码。M2 起校园卡余额只读取该账号中可确认的本人学号，不向余额接口发送密码。M3 起课表认证适配、M4 起图书馆 `libseat` 认证适配可在用户进入对应业务或主动操作时，用该账号完成学校正常 CAS 登录；普通页面、组件和业务数据层不能读取明文密码。

## 学校账号

| 项目 | 说明 |
| --- | --- |
| 保存内容 | 当前一个学校账号与密码的完整版本 |
| 加密 | Android Keystore 中独立 alias `upcpocket.school-account.v1` 的 AES-256-GCM；每次加密使用随机 IV，密文带完整性校验 |
| 存放位置 | 应用私有 `noBackupFilesDir/school-account/`；不进入系统云备份或设备迁移 |
| 明文边界 | 页面输入只在当前操作内存中短暂存在；保存/离页后清空输入，不回显已存密码；不写日志、异常原文、通知或剪贴板 |
| 状态 | 保存成功固定显示“已保存，尚未验证”，不代表学校认证通过；保存动作不自动登录或遍历业务 |
| 修改 | 同账号更新密码会递增本机凭据代次，并使旧业务会话失效；同账号历史缓存是否保留由业务决定 |
| 更换/删除 | 先持久化切换/清理状态，再清理学校会话、Cookie 与能确认归属的个人缓存，完成后才启用新状态；进程中断可在下次启动继续 |
| 不删除 | 个人待办及提醒、个人隐藏座位、专注历史、主题、公开教室数据与用户明确设置的寝室配置 |
| 恢复 | 密钥失效、密文损坏或版本不支持时进入固定的“需要重新保存”状态，不崩溃、不降级明文 |

M2 的校园卡余额只按账号登录名整串符合 8–16 位数字的本人学号查询；不截取、不猜测。账号登录名不是有效学号、未保存、恢复中、换号/删号清理中或密文不可用时，不发起余额请求。余额接口不接收密码，查询成功也不代表 CAS 登录或密码正确。M3 课表与 M4 图书馆是使用已保存密码的在线路径：只在核对后的 `https://cas.upc.edu.cn/cas/login` 表单提交一次；检测到验证码/二次验证时不提交并转为学校正常网页登录。业务成功只表示该业务会话建立，不等同于账号已通过学校全部系统验证。

## 校园卡余额与缓存

| 项目 | 说明 |
| --- | --- |
| 查询目标 | 只来自当前统一账号的受控本人学号；页面、组件、Worker 均不接受 Intent、路由、任务参数或旧草稿中的目标 |
| 接口数据 | 学号；不发送密码、Cookie、账号原文或通用解密结果 |
| 快照 | `noBackupFilesDir/card-balance-v2.json`，含内部 accountId、学号、凭据代次、余额/过渡余额（分）与绝对查询时间；未单独加密 |
| 旧版迁移 | `card-balance-v1.json` 未绑定前不展示；仅当前绑定学号与旧快照整串一致时迁为带归属的 v2 并保留原查询时间；异号、损坏、未知归属删除，不回退展示 |
| 迁移标记 | `card-balance-migration-v2.json` 记录已处理结果，保证幂等和中断恢复；其他账号的 marker 不会被当前账号继承 |
| 清除门闩 | `card-balance-clear-v2.json` 在用户清缓存时先落盘；删除全部成功后才移除。清理失败或进程中退出时旧值继续隐藏，重启后重试，不自动联网 |
| 页面/组件隔离 | 换号/删号后旧余额立即撤下，即使新账号尚未查询成功；同号更新密码保留历史余额并明确标注为历史值，但拒绝旧请求写回 |
| 删除区别 | “仅清除余额缓存”不删除学校账号、密码、图书馆会话或专注/电量/主题数据；“删除学校账号”才清理账密、关联会话与个人缓存 |

## 课表认证、会话与缓存

| 项目 | 说明 |
| --- | --- |
| 认证 | 当前统一账号通过受控认证适配读取一次登录名/密码，只在核对后的学校 CAS HTTPS 表单提交；不把密码放进课表 Repository、普通页面、组件或日志 |
| 失败语义 | 错误密码只提交一次、不循环；网络失败、验证码/二次验证、协议/上游异常分别显示；验证码走学校正常网页登录，不绕过 |
| 会话 | 课表业务 Cookie 使用独立 Keystore alias `upcpocket.timetable-session.v1` 的 AES-GCM 加密，写入 `noBackupFilesDir/timetable/timetable-session-v1.enc`，绑定内部 accountId、凭据代次与保存时间；不保存 CAS 密码副本 |
| 缓存 | 只保存完整成功教学周，按内部 accountId + 学年/学期/教学周归属；含课程名、教师、地点、日期、节次、周次、查询时间与完整性；存放于 `noBackupFilesDir/timetable/timetable-cache-v1.json`，未单独加密，依赖应用沙箱且不进入备份 |
| 失败/空周 | 未查询、认证失败、网络不可用、协议错误与“完整成功且无课”分别显示；失败不覆盖上一次成功缓存，不把错误响应当空课表 |
| 换号/删号/改密 | 换号/删号清理课表缓存与会话，并拒绝旧请求写回；同号改密清掉旧会话但允许保留历史周；所有发布再次核对账号/凭据/业务代次 |
| 离线 | 只显示本账号已成功查询并缓存的教学周；未缓存周不可用，不推测 |
| 网页登录回退 | WebView 只打开学校 HTTPS 域，绑定打开时的账号/业务代次；完成后读取 `app.upc.edu.cn` Cookie 再向学校接口验证，失败不保存，不读取或导出表单值 |
| 页面隔离 | 课程详情只在当前账号/当前周会议记录仍含该 `instanceId` 时显示；换号、删号、清理或切周立即撤下。登录弹窗绑定打开时的 `accountEpoch`，账号变化/阻断时立即关闭 |

## 图书馆认证、会话与持久化

| 项目 | 说明 |
| --- | --- |
| 认证 | 当前统一账号通过受控认证适配读取一次登录名/密码，只在核对后的学校 CAS HTTPS 表单提交；密码不进入图书馆插件、Repository、普通页面或日志 |
| 业务链 | 入口 → 官方 CAS → 一次性 service ticket → libspace app token → `/rest/ssoAuth` seat token → `/rest/v2/user` 本人校验 |
| 本人校验 | 自动认证和手动 WebView 登录返回的 `username` 都必须由账号模块与当前保存账号登录名比较；不一致立即失败，不发布、不持久化 |
| 会话 | seat token 只在内存与 `SchoolSessionStore` 的 Keystore AES-GCM 密文中；密文绑定内部 accountId 与凭据代次，旧格式/旧归属在读取时删除；旧操作不能按过期上下文清理新会话 |
| 失败语义 | 错误密码只提交一次、不循环；网络、TLS、验证码/二次验证、协议/上游、账号变化分别显示；验证码走学校正常网页登录，不绕过 |
| 回退 | 自动认证返回 `INTERACTION_REQUIRED` 时提示打开学校网页登录；未保存学校账号时手动登录只保留内存会话，不持久化无归属 token |
| 换号/删号/改密 | 先递增图书馆登录代次，再清加密副本/内存会话并等待学校 Cookie 清理；清理中或失败时登录、恢复与发布均被阻断 |

## 超星座位（Chaoxing）

| 项目 | 说明 |
| --- | --- |
| 认证 | 优先复用本机加密保存的学校账号，走 `cas.upc.edu.cn` 正常 CAS 表单；密码只提交给精确的 CAS 地址，不提交给 `passport2` 手机号/超星号表单。CAS 证书校验不关闭，逐跳校验 tyrzfw/passport2-api/office 固定 HTTPS 主机与路径。验证码/二次验证时回退受限官方 WebView，不绕过 |
| 会话 | 自动认证在内存 CookieJar 中完成 CAS → tyrzfw → passport2-api → office 链路，只把 `office.chaoxing.com` 可用的 Cookie 头交给 `ChaoxingService` 内存；不写 DataStore/Keystore/文件/日志。WebView 回退仍只读取应用内官方登录 Cookie。退出、换号、删号或会话失效时清理固定 office/passport2 host/path Cookie；清理单飞进行中拒绝新登录，清理失败/超时保持失败状态并阻止登录，必须重试成功后才可再登录 |
| 身份核验 | 服务端 `userLoginInfo.sno` 与当前统一账号比较；发布前复核 accountId/凭据代次/epoch/revision，迟到结果不发布；自动登录成功会使旧 WebView 入口失效 |
| 读取 | seat/seatengine 固定 `/data/apps/{seat,seatengine}/...` 路径：区域、房间信息、座位图、已用座位、已用时段；提交前 GET 固定 `/front/third/apps/{seat,seatengine}/select` 取得页面级 `submit_enc`。不访问 reservepc |
| 写入 | 只在用户最终确认后 POST 一次固定 `/data/apps/{seat,seatengine}/submit`：座位、日期、起止时间、空验证码/风控字段和 `enc`。不自动重试；超时/无法解析显示“结果未知，请核对官方记录”。取消、签到、团队预约未实现；验证码/风控分支只回官方页 |
| 浏览器隔离 | 不读取、不导入系统浏览器/Edge/微信/临时 profile 的 Cookie；受控 UI 验收的测试注入只用于测试，不是产品路径 |
| 已撤下 | 研讨间/空间预约（nspace、reservepc A/B）的产品页面、路由、协议、Service、表单和租户上下文桥接已按用户决定删除；研究记录归档，不在产品中读取或请求 |

## 本机待办与提醒（2.0.3 起）

- 待办保存在应用私有 Room 库 `upcpocket-todo.db`：标题、完成状态、创建/更新时间、提醒时刻、发送状态与 revision。未另行加密，依赖 Android 沙箱；不上传，不依赖学校账号，换号或删除学校账号不会删除待办。可在待办页编辑、删除，误删可撤销。
- 一次性提醒通过系统 AlarmManager 和通知发送。通知可能显示标题和时间，支持完成、稍后 10 分钟与点击进入；使用 `VISIBILITY_PRIVATE`，锁屏实际展示由系统设置决定。请按隐私需要设置锁屏通知。
- 仅在需要时申请通知与精确闹钟权限；拒绝不影响待办保存。未允许精确闹钟或厂商限制后台时提醒可能延后；系统强行停止后需重新打开应用恢复。接收开机、包更新和时间变化事件以重建本地调度，不为此请求校园接口。
- 诊断报告不包含待办标题或正文。清除全部应用数据会同时移除待办与本地提醒。

## 个人隐藏座位（2.0.3 起，先适配唐岛湾）

- `library_hidden_seats` DataStore 按系统、馆区、房间和座位 ID 保存隐藏偏好及座位名称快照；只存在本机，不发给学校，不代表官方拉黑或座位故障认定。
- 可撤销隐藏，在房间的隐藏管理中逐项或全部恢复。偏好不绑定学校账号，退出图书馆或更换学校账号不会删除。
- 按时段找仅在主动查找当前房间时向学校发送日期、起止时间、房间与分页参数；不会自动遍历全馆。古镇口东区与求是本轮未增加该功能。

## 查询会用到什么

| 功能 | 发往学校的数据 | 设备内保留的数据 |
| --- | --- | --- |
| 校园卡余额 | 当前统一账号中整串有效的本人学号（不含密码） | 带内部账号归属/代次的余额快照、绝对查询时间；旧学号草稿仅作迁移提示并在账号绑定后删除 |
| 唐岛湾电量 | 选择的楼号、寝室号 | 输入草稿、最后成功查询的房间、电量与时间 |
| 空闲教室 | 校区、教学楼、日期、节次 | 页面查询状态与 `classroom_prefs` 中的上次校区；不持久保存查询日期、节次与结果，每次进入默认今天上午 |
| 图书馆座位 | 学校正常认证所需登录名/密码（仅认证适配）；libseat 接口只接收 seat token 与查询/预约参数 | 运行会话；开启记住登录后保存绑定 accountId/代次的业务令牌 |
| 超星座位 | 学校 CAS 正常登录所需登录名/密码（仅认证适配，只发往 `cas.upc.edu.cn`）；随后只向固定的 tyrzfw/passport2-api/office HTTPS 路径发送认证 Cookie；座位读取只带 office Cookie 与固定区域/日期/时段参数。最终确认提交时再向固定 seat/seatengine `/submit` 发送所选座位、日期、起止时间与页面级校验字段。验证码/二次验证/风控回退 WebView，不把学校密码提交给 Chaoxing 表单 | 仅内存 Cookie；不保存区域/座位结果；退出/换号即清；提交结果不写入本地“成功”缓存，以官方记录为准 |
| 课表 | 学校 CAS 正常登录表单所需的登录名与密码（仅认证适配）；课表接口只接收课表业务 Cookie 与学年/学期/教学周 | 加密课表业务会话；按账号归属的成功教学周缓存、查询时间与完整性；课表组件只读取当前账号本周缓存中的今日课程名/地点/时间/颜色槽，不额外保存一份桌面快照 |
| 学校账号（M1/M2/M3/M4） | 余额只发送当前账号的受控学号；课表/图书馆认证只向核对后的 CAS HTTPS 端点发送账密 | 独立 alias 加密的账号与密码完整版本、代次和清理状态；余额快照/课表缓存/图书馆令牌另存且带账号归属 |
| 专注 | 不需要校园网络请求 | 标签、计时记录和统计 |

应用以私有 DataStore、文件和数据库保存配置与缓存；校园卡/电量快照、课表成功周缓存和输入未额外加密，依赖 Android 应用沙箱。图书馆 seat token（绑定 accountId/凭据代次）与课表业务会话分别使用 Android Keystore 加密，WebView Cookie 由系统 WebView 管理。系统备份已关闭。

“记住学校登录”只表示保存图书馆业务签发的 token，不是统一账号密码的保存偏好。关闭该开关或退出图书馆登录会清理图书馆持久副本与 UPC 业务 Cookie；它不会创建、覆盖或验证“学校账号”中的账密。

## 小组件与刷新

- 校园卡组件展示余额和更新时间、不常驻显示学号，电量组件展示最后成功查询的房间，课表组件只展示今日课程名、地点、时间和课程色条；桌面仍会显示余额、电量、寝室与课程信息，请按自己的隐私需要放置。课表组件不显示教师或学号。
- 小组件不周期请求。点击刷新才提交一次查询；失败保留同账号旧值与成功时间，旧值不能当作实时结果。课表组件的“未同步/无账号/清理中/非教学周/今天无课”分开显示，不会用空白冒充无课。
- 校园卡组件目标来自当前统一账号，不再依赖“先成功查询一次才能刷新”；已绑定但无历史快照也可点击查询。普通进程死亡后点击刷新会先有界等待本机账号恢复，再执行一次查询；不需要先打开 Activity，也不常驻服务。换号/删号/清缓存后立即撤下旧值，旧 Worker 的结果不能复活旧账号数据。
- 修改旧学号草稿不会改变组件目标；该草稿只作为账号设置提示，账号绑定后删除。页面“仅清除余额缓存”会同步移除对应本地快照，但不删除学校账号。
- 不读取桌面壁纸，不申请屏幕捕获权限。半透明背景由桌面合成。

| 导出 | 用户在关于页主动触发后，本机生成 `summary.txt` + `events.jsonl` 的 ZIP，再打开系统分享面板；不自动上传、不发邮件/短信；取消分享不会发送任何内容 |
| 文件共享 | ZIP 位于专用 `cache/diagnostic_exports/`，通过 `exported=false`、`grantUriPermissions=true` 的 FileProvider 生成 `content://` URI；仅对本次 `ACTION_SEND` 授予临时读取权限；分享后保留文件，按最多 3 个/24 小时清理 |
| 分享边界 | 用户选择外部应用后，接收方会按自己的规则读取 ZIP 内容；这不等于“数据始终留在设备”。本项目不提供后台网络上报或第三方遥测 |
| 异常 | 只记录固定异常类型与过滤后的应用帧（最多 8 帧），不含异常消息、文件名/行号或敏感路径；不捕获全局崩溃/ANR，也不声称进程被杀后事件不丢失 |
| 清理 | 关闭记录开关或点“清除诊断记录”会删除事件与导出 ZIP；换号/删号/个人数据清理先递增诊断代次并清空旧事件，旧异步记录不能写回；诊断失败不阻断登录/业务/退出 |
| 映射 | R8 映射仅按版本保存在开发机本地，不写入 ZIP、APK、仓库或发布附件 |

## 清除与退出

在校园卡页面“仅清除余额缓存”只删除余额快照、旧迁移文件和待清理门闩，不删除学校账号或密码；清理失败时旧值保持隐藏并可在重启后重试。唐岛湾页面使用清除功能删除电量输入与快照；图书馆可退出会话，也可在学校登录设置中清理保存的登录信息；课表目前随“首页 → 设置 → 学校账号”的更新/换号/删除清理会话与缓存，不另设独立清除按钮。“首页 → 设置 → 学校账号”的删除会清除加密账密、关联业务会话、能确认归属的个人缓存与组件内容；该动作不代表撤销校方服务器上的所有会话。Android 设置中的“清除应用数据”会移除全部本地配置和记录。

## 网络边界

校园卡余额和唐岛湾电量当前由学校 HTTP 接口提供，学号、寝室参数及返回值不受 HTTPS 传输加密保护。只查询本人账号与有权查询的房间；避免在不可信网络查询。古镇口通过学校外部页面访问，证书或网络异常时不绕过校验。

图书馆登录页面由学校提供。学校服务和外部浏览器有各自的数据处理规则，应用不能控制校方保存的数据或保证服务持续可用。M2 余额只向现有 HTTP 接口发送当前账号中整串有效的本人学号，不发送密码。M3 课表只向核对后的学校 CAS HTTPS 端点发送账密，业务请求只访问 `app.upc.edu.cn`；M4 图书馆同样只向核对后的 CAS 提交账密，业务请求只访问 `libspace.upc.edu.cn` 的固定路径；Chaoxing WebView 只加载受限的官方学校 CAS 与超星认证链路 HTTPS 主机/路径，不读取输入，业务请求只访问固定 `office.chaoxing.com/data/apps/{seat,seatengine}` 与 `/front/third/apps/{seat,seatengine}/select` 路径，最终确认后才 POST 固定 `/submit`；研讨间/空间预约已撤下，不访问 nspace 或 reservepc。不关闭证书校验，不向任意重定向发送密码或认证头，也不依赖开发电脑的现成 Cookie。真实课表/预约内容属于个人业务数据，不写入仓库、公开材料或聊天。

公开仓库和发布演示不得包含真实学生信息、密码、Cookie、Token、私钥或个人交易记录。README 组件截图使用虚构样本；教室示例来自公开查询。

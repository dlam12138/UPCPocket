# 隐私与数据说明

UPC Pocket Lightly 是非官方校园工具。应用直接访问对应校园服务，不使用本项目自建的数据中转或账号服务器。

已发布 v0.2.7 不保存学校密码。当前 **M1/M2 开发分支（尚未发布）** 新增“更多 → 学校账号”：仅在用户主动点击“加密保存到本机”时，保存当前一个学校账号与密码；默认不保存，也不会把“记住学校登录”开关自动解释为同意保存密码。M2 起校园卡余额只读取该账号中可确认的本人学号，不向余额接口发送密码。

## 学校账号（M1/M2 开发分支）

| 项目 | 说明 |
| --- | --- |
| 保存内容 | 当前一个学校账号与密码的完整版本 |
| 加密 | Android Keystore 中独立 alias `upcpocket.school-account.v1` 的 AES-256-GCM；每次加密使用随机 IV，密文带完整性校验 |
| 存放位置 | 应用私有 `noBackupFilesDir/school-account/`；不进入系统云备份或设备迁移 |
| 明文边界 | 页面输入只在当前操作内存中短暂存在；保存/离页后清空输入，不回显已存密码；不写日志、异常原文、通知或剪贴板 |
| 状态 | 保存成功固定显示“已保存，尚未验证”，不代表学校认证通过；保存动作不自动登录或遍历业务 |
| 修改 | 同账号更新密码会递增本机凭据代次，并使旧业务会话失效；同账号历史缓存是否保留由业务决定 |
| 更换/删除 | 先持久化切换/清理状态，再清理学校会话、Cookie 与能确认归属的个人缓存，完成后才启用新状态；进程中断可在下次启动继续 |
| 不删除 | 专注历史、主题、公开教室数据与用户明确设置的寝室配置 |
| 恢复 | 密钥失效、密文损坏或版本不支持时进入固定的“需要重新保存”状态，不崩溃、不降级明文 |

M1 尚未把密码接入校园卡、图书馆或课表。图书馆仍使用学校网页登录。M2 的校园卡余额只按账号登录名整串符合 8–16 位数字的本人学号查询；不截取、不猜测。账号登录名不是有效学号、未保存、恢复中、换号/删号清理中或密文不可用时，不发起余额请求。余额接口不接收密码，查询成功也不代表 CAS 登录或密码正确。

## 校园卡余额与缓存（M2 开发分支）

| 项目 | 说明 |
| --- | --- |
| 查询目标 | 只来自当前统一账号的受控本人学号；页面、组件、Worker 均不接受 Intent、路由、任务参数或旧草稿中的目标 |
| 接口数据 | 学号；不发送密码、Cookie、账号原文或通用解密结果 |
| 快照 | `noBackupFilesDir/card-balance-v2.json`，含内部 accountId、学号、凭据代次、余额/过渡余额（分）与绝对查询时间；未单独加密 |
| 旧版迁移 | `card-balance-v1.json` 未绑定前不展示；仅当前绑定学号与旧快照整串一致时迁为带归属的 v2 并保留原查询时间；异号、损坏、未知归属删除，不回退展示 |
| 迁移标记 | `card-balance-migration-v2.json` 记录已处理结果，保证幂等和中断恢复；其他账号的 marker 不会被当前账号继承 |
| 清除门闩 | `card-balance-clear-v2.json` 在用户清缓存时先落盘；删除全部成功后才移除。清理失败或进程中退出时旧值继续隐藏，重启后重试，不自动联网 |
| 页面/组件隔离 | 换号/删号后旧余额立即撤下，即使新账号尚未查询成功；同号更新密码保留历史余额并明确标注为历史值，但拒绝旧请求写回 |
| 删除区别 | “仅清除余额缓存”不删除学校账号、密码、图书馆会话或专注/电量/主题数据；“删除学校账号”才清理账密、关联会话与个人缓存 |

## 查询会用到什么

| 功能 | 发往学校的数据 | 设备内保留的数据 |
| --- | --- | --- |
| 校园卡余额 | 当前统一账号中整串有效的本人学号（不含密码） | 带内部账号归属/代次的余额快照、绝对查询时间；旧学号草稿仅作迁移提示并在账号绑定后删除 |
| 唐岛湾电量 | 选择的楼号、寝室号 | 输入草稿、最后成功查询的房间、电量与时间 |
| 空闲教室 | 校区、教学楼、日期、节次 | 页面查询状态 |
| 图书馆座位 | 学校正常认证及你主动查询、预约或取消所需参数 | 运行会话；开启记住登录后保存业务令牌 |
| 学校账号（M1/M2） | 余额只发送当前账号的受控学号；密码仍不发送 | 独立 alias 加密的账号与密码完整版本、代次和清理状态；余额快照另存且带账号归属 |
| 专注 | 不需要校园网络请求 | 标签、计时记录和统计 |

应用以私有 DataStore、文件和数据库保存配置与缓存；校园卡/电量快照和输入未额外加密，依赖 Android 应用沙箱。图书馆持久令牌使用 Android Keystore 加密，WebView Cookie 由系统 WebView 管理。系统备份已关闭。

“记住学校登录”只表示保存图书馆业务签发的 token，不是统一账号密码的保存偏好。关闭该开关或退出图书馆登录会清理图书馆持久副本与 UPC 业务 Cookie；它不会创建、覆盖或验证“学校账号”中的账密。

## 小组件与刷新

- 校园卡组件只展示脱敏学号，电量组件展示最后成功查询的房间；桌面仍会显示余额、电量和寝室信息，请按自己的隐私需要放置。
- 小组件不周期请求。点击刷新才提交一次查询；失败保留同账号旧值与成功时间，旧值不能当作实时结果。
- 校园卡组件目标来自当前统一账号，不再依赖“先成功查询一次才能刷新”；已绑定但无历史快照也可点击查询。换号/删号/清缓存后立即撤下旧值，旧 Worker 的结果不能复活旧账号数据。
- 修改旧学号草稿不会改变组件目标；该草稿只作为账号设置提示，账号绑定后删除。页面“仅清除余额缓存”会同步移除对应本地快照，但不删除学校账号。
- 不读取桌面壁纸，不申请屏幕捕获权限。半透明背景由桌面合成。

## 清除与退出

在校园卡页面“仅清除余额缓存”只删除余额快照、旧迁移文件和待清理门闩，不删除学校账号或密码；清理失败时旧值保持隐藏并可在重启后重试。唐岛湾页面使用清除功能删除电量输入与快照；图书馆可退出会话，也可在学校登录设置中清理保存的登录信息。“更多 → 学校账号”的删除会清除加密账密、关联业务会话、能确认归属的个人缓存与组件内容；该动作不代表撤销校方服务器上的所有会话。Android 设置中的“清除应用数据”会移除全部本地配置和记录。

## 网络边界

校园卡余额和唐岛湾电量当前由学校 HTTP 接口提供，学号、寝室参数及返回值不受 HTTPS 传输加密保护。只查询本人账号与有权查询的房间；避免在不可信网络查询。古镇口通过学校外部页面访问，证书或网络异常时不绕过校验。

图书馆登录页面由学校提供。学校服务和外部浏览器有各自的数据处理规则，应用不能控制校方保存的数据或保证服务持续可用。M1 保存的账号密码仍未用于任何在线认证；M2 余额只向现有 HTTP 接口发送当前账号中整串有效的本人学号，不发送密码。后续接入 CAS 时只允许把密码发送到核对后的学校 CAS HTTPS 端点。

公开仓库和发布演示不得包含真实学生信息、密码、Cookie、Token、私钥或个人交易记录。README 组件截图使用虚构样本；教室示例来自公开查询。

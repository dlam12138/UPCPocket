## 2. 唐岛湾楼号为什么选不了（实际复现）

在模拟器上先复现了用户看到的状态，而不是只改样式：

1. 打开飞行模式，冷启动进入「唐岛湾电费」。
2. 楼号列表请求失败，页面底部只出现“无法连接电费查询系统”，
   顶部按钮显示“选择楼号”但处于**禁用**状态；整页没有任何重新加载楼号的入口。
3. 查询按钮变成“重试查询”，点它只会提示“请先选择楼号”；用户被卡死，只能退出重进赌网络。

根因有三层：

- **加载状态与可用性绑死**：`enabled = !loading && buildings.isNotEmpty()`。
  一次失败后 `buildings` 为空，选择器永久禁用；重试只存在于查询路径，不在楼号加载路径。
- **一次性加载、无重试**：`LaunchedEffect(Unit)` 只请求一次楼号；错误提示在页面最底部，
  与选择器分离，用户很难把两者联系起来。
- **旧 DropdownMenu 的可操作性差**：菜单内容宽约 96dp、楼号有 30+ 项。模拟器实测：
  在菜单右半侧滑动会被当成“点击外部”直接关闭；必须正好在左侧窄条内滑动才能滚动。
  即使列表加载成功，选择体验也不稳定。

另外，旧实现会在列表返回时用 `list.first()` 覆盖“上次楼号不在列表”的情况，
存在覆盖用户选择的可能；本步不再自动改选。

### 修复

- 选择器改为 `AlertDialog` + `LazyColumn` 滚动列表：整屏可点、可滚，不再受 96dp 菜单宽度限制。
- 选择器按钮**不再因列表为空而禁用**；点开后可看到“正在加载/加载失败/列表”，
  失败时明确给出“重新加载楼号”。
- 页面选择器下方也常驻加载状态；失败显示原因和“重新加载楼号”，空列表显示“尚未获取…”。
- 楼号列表只来自学校页面；不编造静态楼号。
- 列表加载完成后不再自动选中或覆盖：只有持久保存的楼号会被回填，
  用户没选过就保持“选择楼号”。
- 已保存楼号不在当前列表时，只提示“请重新选择”，不静默改值。

## 3. 结构调整

### 3.1 一个「电费」入口，二级选校区

- 首页删除“宿舍电费 · 唐岛湾”“宿舍电费 · 古镇口”两张卡片，改为一个「电费」卡片。
- 新路由 `ELECTRICITY` → `ElectricityScreen`：
  - 唐岛湾：进入 App 内原生查询（`POWER_TANGDAOWAN`）。
  - 古镇口：保留学校外部页面，说明域名证书已过期、不绕过 TLS。
  - 页面明确写“唐岛湾为 App 内查询；古镇口为学校外部页面，未做原生接入”。
- 唐岛湾页删除浏览器、微信、分享、外跳图标与冗长的数据来源说明；
  只保留楼号、房间号、查询、结果、错误与清除。

### 3.2 校园卡余额直接嵌在首页

- 删除首页“校园卡余额”目录卡片和 `CAMPUS_CARD` 二级路由。
- 原整屏 `CampusCardScreen` 拆成 `DirectCardBalanceSection`：
  无 Scaffold / TopAppBar，只保留表单、状态和结果，直接放在首页「校园卡余额」区。
- 保留 `Accept: */*`、`getCardInfo`、按“分”解析、私有缓存、真实失败状态；
  不恢复平台登录、流水、充值。

## 4. 输入持久化

### 4.1 数据层

新增 `data/repo/PowerInputRepository` 与 `data/repo/CardInputRepository`，
底层仍是现有 `ui_prefs` DataStore：

| 配置 | 键 | 说明 |
| --- | --- | --- |
| 唐岛湾楼号 | `power_building` | 沿用第二步已有的键，升级不丢 |
| 唐岛湾房间号 | `power_room` | 新增；与楼号同一次编辑写入 |
| 校园卡学号 | `card_student_id` | 新增；与余额快照完全分离 |

- 两个 Repository 都暴露 `Flow` 读取 API 和 `save` / `clear`，
  为将来的 RemoteViews 组件复用；本轮**不新增组件注册**。
- 不依赖“记住学校登录”开关，也不与图书馆 token 捆绑。
- 查询动作不写输入；输入保存不依赖查询成功。
- 只保存到应用私有 DataStore，不写日志、测试样本或文档。

### 4.2 界面行为

- 唐岛湾：进入页面/进程重启自动回填楼号与房间号；选择楼号或修改房间号时立即异步保存；
  “清除楼号与房间号”同时清 UI、持久配置和旧结果。
- 校园卡：学号单独持久保存，未查询成功也能在重启后回填；“清除学号与余额记录”
  同时删学号、余额快照和 UI。
- 输入变化时旧电量结果立即隐藏；结果卡片自身还带楼号/房间号，
  并通过 `ElectricityReading.matches()` 再做一次归属校验。
- 查询请求带序号；返回时若输入已变或序号过期，不写入结果。

- 没有用真实房间号发起唐岛湾查询，因此“成功结果展示、候选房间、旧结果标旧”只做了
  单元测试与代码路径验证，未做真实数据点测。
- 校园卡没有用真实或虚构学号发起查询；只验证了输入持久化、清除和失败状态代码路径。
- 古镇口只验证了页面与说明，没有实际打开外部浏览器（会离开 App）。
- 图书馆真实登录/预约/取消未重跑。
- 本轮不实现桌面小组件；Repository/Flow 已就绪，但 RemoteViews、注册和刷新均未做。

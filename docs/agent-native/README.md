# Agent 开发手册

项目指令的唯一主入口是[根 AGENTS.md](../../AGENTS.md)。本页解释发现、加载、协作与维护；不会自动替 Agent 加载其他文档。当前架构/API/贡献流程分别见 [ARCHITECTURE](../../ARCHITECTURE.md)、[API](../../API.md)、[CONTRIBUTING](../../CONTRIBUTING.md)。完整索引在 [docs/README](../README.md)，本次建设的依据与边界见[审计报告](2026-11-16-audit-and-delivery.md)。

本机工具接入见 [TokenEconomizer 安装、验收边界与回滚记录](2026-11-17-tokeneconomizer.md)。

## 每个任务的读取顺序

1. 确认仓库根目录与工作区已有修改，识别目标文件及其生产者/消费者。
2. 显式读取根 AGENTS，以及目标路径从根向下遇到的局部 AGENTS；跨模块任务对每条受影响路径执行。例如改 card：根 → feature → feature/card；改 AppGraph：根 → app；改账号：根 → core。
3. 按根的任务矩阵读取普通文档相关章节，随后核对源码、测试和构建配置。不要将“列出文件名”记作“已理解内容”。
4. 执行期间发现事实冲突，先区分历史记录、未完成迁移与当前错误，调查并交接；不自行猜测。修改后检查文档同步，交付写实际阅读与验证。

这些步骤同时适用于不支持 AGENTS 自动发现的工具。某 Agent 声称支持嵌套规则，不能证明本项目会话已加载新文件。当前实测/未测状态见[兼容记录](agent-compatibility.md)；自动发现不可靠时，显式读取是共同兜底。

## 分层理由

| 层级 | 当前文件 | 为何需要 |
| --- | --- | --- |
| 根 | `AGENTS.md` | 工作方式、全局硬约束、任务读取矩阵、交付和维护 |
| 目录组/宿主 | `app/AGENTS.md`、`core/AGENTS.md`、`feature/AGENTS.md` | 宿主系统入口、基础与认证、业务共有规则，覆盖所有模块 |
| 独有业务 | card/library/timetable/todo 的 `AGENTS.md` | 写操作防重、多平台协议、真实日期与独立提醒 revision，风险/流程各异 |

本轮共一个根与七个局部入口；不为每个 Gradle 模块建文件，不新增模块内部的更深指令。focus 旧 schema 规则在 feature 指令和 ADR 003，account/upc-auth 边界在 core 指令与 ADR 002；当前体量无需再拆。新增目录不自动要求新增 AGENTS，只有独立、长期且不能清晰放在父级的约束才考虑增加。子级不重复父级，复杂事实进架构/API/证据文档。

## 多 Agent 与跨会话交接

调度遵守根规则：简单直做，复杂先 planner，外部事实 researcher，代码修改 coder；重要工作 tester 与 reviewer 分别验证。分工是职责划分，不是增加调用数量的目标。独立任务可并行，同一文件只有一个写入者；检查角色证据后再进入下一阶段，发现问题交 coder 定向修复。

推荐交接格式：

```text
目标与验收：本次要改变的行为/知识，完成标准。
范围与限制：可改文件、不可碰内容、外部操作授权、文件写入归属。
已读依据：文档章节、源码/测试入口及实际冲突。
已完成：具体文件/决策，当前输入或产物版本。
实际验证：命令、退出码、任务执行/缓存、结果与证据位置。
未验证与下一步：真实校园/设备/分支限制、待修问题及负责人。
```

交接不附账密、Cookie、token、私钥、完整请求/响应或未脱敏业务记录。当前会话结论归入适当文档，不复制全段聊天；临时定位记录不变成长期指令。

## 技能与工具

已有 `.agents/skills/` 收录固定版本 Android 专业技能，来源/许可证与触发描述见[索引](../android-skills.md)。按任务读对应 `SKILL.md` 与必要资源，先核对项目版本；不能因技能描述包含新 API 而自动迁移。当前 Codex 上下文提供技能目录；其他 Agent 的自动发现未实测，按路径显式读取即可。

发布准备和校园系统研究已有 [BUILD](../BUILD.md)、[更新机制](../updates/README.md)、[研究方法](../research/校园系统探索方法.md)及实际工具。本轮未创建新 skill：没有已验证、跨任务可复用且不重复这些文档的新增独立操作流程。今后创建需明确触发、输入输出、步骤与验证，并实查目标 Agent 的技能加载机制，不改上游技能存放项目规则。

Lody 命令先调用并读成功的命令专属 `lody_help({command: TOOL_NAME})`，再顺序执行；索引/摘要不能代替完整帮助。帮助丢失或上下文压缩后重读，不为验证兼容而创建新计费会话或改配置。

## 持续维护与自动化

根矩阵决定“何时读”，普通文档决定“读什么事实”。发现重复误解才评估长期规则，写最合适层级并避免重复；重要规则变更必须说明并审查。架构/API/用户用法/版本分别维护 ARCHITECTURE、API、README、现有 CHANGELOG，重大选择新增关联 ADR。

现有 `checkModuleBoundaries`、类型/凭据 opt-in、模块测试和 Lint 能验证部分边界；当前没有仓库 CI、通用文档链接检查或自动 API 兼容基线。本轮只复用现有机制与临时文档检查，不修改构建或加检查代码。未来自动化建议须单独评估范围，不能写成已经存在。验证只覆盖改动实际影响，排除非必要测试；真实 CAS 验收遵守根的本人真实账密要求。

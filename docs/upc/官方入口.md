## 课表来源与验证边界

课表协议、认证流程和严格解析参考本地 [UPC-MCP](https://github.com/dlam12138/UPC-MCP) 固定提交
`948f5f21ad7a12fd94b53403a07ac867209f7700`（MIT，Copyright (c) 2026 3beuml）。只移植正常
CAS 表单登录、票据回调、`get-index`/`get-datatmp` 与校验语义；不嵌入 Python、MCP 服务、
DPAPI 桌面设施或其他学校的接口。系统备份仍关闭，来源项目只读、未重绑、未删除。

以下是三类不同事实，不能互相替代：

1. **参考源码事实**：固定提交中的 `timetable_protocol.py`、`timetable_service.py`、
   `timetable_tools.py`、`timetable_auth.py`、`auto_auth/cas.py` 与
   `auto_auth/providers/timetable.py` 给出上述协议形状、周日起算、ISO weekday 和严格错误语义；
   合成 fixture 只用于验证解析器。
2. **实际认证/数据验证**：2026-11-03 在 Android 36 模拟器上以用户明确授权的本人账号完成
   一次正常 CAS 登录和单周只读查询，页面显示周网格/今日课程，并在断网后重开显示已成功缓存。
   验证只读取本人课表，没有预约、报名、签到、充值或其他写操作；未在文档保留账号、密码、
   Cookie、票据或课程原文。Android 成功不等于 Python 或桌面浏览器成功，也不等于所有设备/网络
   条件可用。
3. **正式授权**：用户表示已与学校取得联系；这不构成官方客户端身份、统一认证接入资格或
   全量接口许可。应用仍按非官方工具描述，正式 API/授权到位前不扩大接口范围。

## 图书馆/空间六入口研究边界（2026-11-03）

用户标定的六个入口（唐岛湾座位、唐岛湾东馆研讨间、古镇口东区座位/研讨间、求是图书馆
座位/研讨间）已做公开前端与入口研究，见
[六入口接口研究](../research/图书馆与空间预约六入口接口研究-20261103.md)。边界按以下事实分开：

1. **公开前端事实**：`libseat`/`nspace` 的公开 JS 与公开配置给出了 CAS 入口、业务 token
   兑换和主要 API 路径；`office.chaoxing.com` 的 seat/seatengine 入口当前跳到
   passport2 登录，`reserve.chaoxing.com` 的裸 URL 在无租户/会话上下文时返回 303。
2. **现有页面事实**：求是 `reservepc` 已在用户现有 Edge 正常加载“研讨室列表”和
   A301、A402–A404、A501–A505；地址栏带 `reserveId/resvAppId/enc/fidEnc/uid/wfwEnc/code/state`
   等上下文（值不记录）。因此无 Cookie 的 302/303 不能说明现有会话不可用。
3. **实际 HAR**：2026-11-03 取得用户授权的六份只读 HAR（libseat、nspace、seat、
   seatengine、reservepc 两租户）。libseat 已确认 filters/floors/stats2/settings/
   announce 与空当前预约；nspace 已确认 venue/roomType/dates/roomList（6/11，2 页）；
   reservepc 两租户分别确认 8/23 个预约项、空 user list、loginStatus=true；seat/seatengine
   仅到入口配置、index、identity 和空 current/near，没有馆区/座位列表。
4. **认证边界**：六份 HAR 都没有 CAS/passport 登录跳转、token 获取或写请求；它们只
   证明已授权页面的只读请求，不能证明端到端统一认证。本机 Edge 没有 CDP 调试端点，
   为避免破坏现有会话，未重启 Edge 或修改调试配置。UPC-MCP 2026-10-31 的 `libseat`
   只读查询属于既有历史证据，不等于本轮重新验证。
5. **历史（2026-11-04）研讨间观察**：reservepc 的一次性微信/目录上下文曾在浏览器中加载
   古镇口 8 个/求是 23 个研讨间；该入口上下文不可由稳定 URL 重新签发。此条仅保留研究证据，
   相关产品功能已于同日按用户决定撤下。
6. **当前 Android 实现**：M4 已覆盖 `libseat` 统一认证、本人校验与既有会话迁移。M5 现行
   图书馆只保留三个座位入口：唐岛湾 libseat、古镇口 Chaoxing `seat`、求是 Chaoxing
   `seatengine`；后两者是类型化只读仓库/Service/Compose + 受限官方 WebView 内存会话，
   东区 6 区域/求是 21 区域、座位图与 30 分钟时段已在真实 Android 进程内读取。nspace 与
   reservepc 的页面/认证/表单/取消/租户上下文桥接已删除；旧研讨间路由只落到图书馆首页。
   真实预约/取消/签到仍不在原生范围。历史六入口矩阵见
   [M5 图书馆六入口（归档）](../m5/图书馆六入口.md)。

入口目录见 [official-entrypoints.json](official-entrypoints.json)，用途为开发资料，不是应用运行时 API 配置。各功能实际能力以源码与 [验证记录](../CHANGELOG.md) 为准；入口返回 HTTP 200 不等于登录或业务完成。

## e站通开发候选来源与验证边界（2026-11-14）

学校信息化建设处列有 e站通入口；[学校办事说明](https://youth.upc.edu.cn/2020/0917/c15324a316537/page.psp)是历史操作资料。业务入口为 `https://service.upc.edu.cn/`。协议和认证流程参考固定 UPC-MCP 提交 `948f5f21ad7a12fd94b53403a07ac867209f7700`，许可与移植范围见[来源记录](../third-party/UPC-MCP.md)。Android 代码按只读边界接入事项目录/指南与本人待处理/在办；认证成功必须绑定当前账号和凭据代次。入口 URL 仅作为数据展示，不自动打开；个人结果仅保存在内存。

当前正常 CAS 成功来源为密码认证或绑定到同账号/凭据代次的 SSO；验证码/二次验证返回需要学校验证并停止自动登录。已确认公共 CAS 挑战只有状态和 URL，没有可继续且能证明账号归属的挑战上下文；e站通上游没有可核对账号字段，公开 CAS 页登录也不能证明本人身份。因此当前不采纳网页登录 Cookie，也不提供虚假的完成操作；待真实挑战发生且有可验证的挑战上下文与身份依据后再评估。

截至本轮，账号/凭据代次与业务 epoch 清理、加载中切页、目录缩页、指南 URL/票据/附件引用脱敏及独立 MIT 资源已完成复核。最终定向测试 499 项，497 通过、2 项真实联网测试跳过、零失败；Debug、AndroidTest APK 编译/打包、模块边界和长期签名 R8 + resource shrink Release 构建通过。Android 公开目录曾因 `(?U)` 正则抛异常误报格式变化，已用统一 Unicode White_Space 码点分词修复，并有 25 码点及完整合成 HTTP→协议→服务链路回归。最终签名包已保留数据覆盖安装，公开目录、指南、无结果搜索与清空、断网本地第 2 页、刷新失败保留结果及普通进程重建均完成走查；指南/搜索首次网络失败保留，手动各复核一次后成功。正式系统添加的今日课表组件完成进程死亡后的刷新与整卡导航。

本轮未读取学校账号或访问受保护 CAS/个人接口，真实正常登录、验证码、绑定 SSO、自然失效恢复及个人队列仍待授权账号实测；不将上游或合成结果当作 Android 真实业务验收。最终候选与安装结果见 [开发记录](../releases/2.0.5-development.md)。

## 体育馆与游泳馆预约来源与验证边界（2026-11-20）

在正常登录的 Windows 微信中，从服务号搜索结果可进入公众号「中国石油大学体育场馆」；打开底栏「场地预定」后，对话窗口标题明确显示该名称，展开的子菜单包含「场地预定」和「游泳馆预定」。体育馆路径为「场地预定 → 场地预定」，游泳馆路径为「场地预定 → 游泳馆预定」；点击游泳馆子菜单会打开微信内网页并显示「游泳馆」。体育馆选择一个项目与日期后能进入真实场次网格。关注该公众号是否为预约前置条件尚未确认，因此交接文案只提示搜索、打开菜单并按页面选择，不要求关注；只核对了单个项目与日期样本，未逐项验证，也不把该样本写成固定项目。游泳馆只核对到微信内网页显示「游泳馆」，未点购票、选位、下单或提交，菜单后的项目、时段、余位与业务可用性未在应用内验证。当前绑定的业务域名 `26501.koksoft.com` 以 HTTP 提供场次，同域正常 HTTPS 校验报证书过期。未找到可验证的官方公众号深链、小程序参数或公开安全的余位 API，这些地址和参数均不写入应用。

学校 2024-11-11 的[校工会比赛通知](https://gh.upc.edu.cn/2024/1111/c5517a445354/page.htm)也使用「中国石油大学体育场馆」，与本次实测名称一致，可作名称旁证；该页面的泳馆菜单信息只作历史资料，不作为现行规则。更早的[2023 预约规则页面](https://sports.upc.edu.cn/2023/0606/c7678a405213/page.htm)使用旧称「中国石油大学体育馆」，仅作为规则文献与公开链接保留，应用搜索名以实测的「中国石油大学体育场馆」为准。[游泳馆开馆报道](https://news.upc.edu.cn/info/1432/114958.htm)是学校公开 HTTPS 页面，已核对作为游泳馆介绍入口。泳馆按既有校区约定归唐岛湾；服务页在常用校区为古镇口时隐藏该入口，完整「校园官方网页 → 生活」目录始终可见，并由副标题标明唐岛湾。

2.1.0 开发代码在服务目录增加「体育馆预约」和「游泳馆预约」：可从 服务 → 全部 / 校园生活 和 校园官方网页 → 生活 找到，均可按标题搜索且不提供首页图钉。点击后显示同一份交接对话框，标题、公众号、菜单路径与公开页面按钮均由各自条目传入；只有用户主动点击「复制公众号名并打开微信」时，才把学校公开的公众号名称写入剪贴板，并通过系统 `PackageManager` 启动已安装的 `com.tencent.mm`（复用 manifest 既有包查询）。微信缺失或启动失败时留在可操作对话框并明确提示，仍可打开预约规则或游泳馆介绍页。

实时余位、场次核对、提交与预约结果都在微信内完成，应用不读取、不代理，也不把「微信已打开」当作预约成功；未新增插件、网络实现、未证实深链、微信 SDK、权限、TLS 或持久化。两个入口未随 2.0.9 发布；Android 真机交接与微信内业务提交尚未测试，现有证据仅限 2026-11-20 Windows 微信中的公众号名称、底栏菜单与泳馆网页显示核对；未点购票、选位、下单或提交，不声称业务完整可用。

# 0.1.5 登录页面修复与手机测试

本轮针对手机反馈的图书馆/校园卡白屏及课表同步 404。不是校园业务全链路完成报告。

## 根因与修复

1. 课表同步原入口 `/site/weekschedule/` 返回学校 404，改为已核验的 `/site/weekschedule/index`。
2. 官方 CAS 页面中的 `#loginIframe` 在 Android 36 WebView 高度为 0，但内部已加载两个输入框。仅修正这个 iframe 的像素高度后官方表单立即可见。现已将修复限制在 exact HTTPS CAS 登录页、实际塌陷的指定 iframe，并处理旋转/resize。不读取账号密码，不自行提交表单。
3. 相同模拟器的 WebView 访问图书馆/校园卡业务认证入口发生连接重置，而 Android 原生 HTTP GET 正常返回 CAS 跳转，相同 UA 也能成功。仅对已确认的业务认证 GET 路径使用原生重定向解析，再加载官方 CAS。App 自己的 Cookie 在两种请求方式之间传递；CAS 表单仍由官方页面处理。限制路径、域名、跳转次数、超时和响应体大小，不输出 ticket/token/响应正文。
4. 三个登录页共用加载、错误、重试与资源清理；证书错误取消加载，不再静默白屏。

## 实际验证

- assembleDebug、testDebugUnitTest、lintDebug 均成功。单元测试 390 项，0 失败/错误/跳过；lint 0 errors、70 warnings、7 information。
- 新增覆盖业务跳转、Cookie 转发/接收、不自动随跳、错误脱敏、域名/路径限制、有界 HTML、CAS 子框架错误、超时/销毁及官方课表入口。
- 从已安装的 0.1.4 覆盖安装成功；既有“测试晚课”等本地日程仍可见。
- Android 36 模拟器实际点击图书馆、校园卡、课表同步三个入口，均显示官方 CAS 用户名/密码/登录按钮。没有用 CDP 手动导航或注入来替代新 APK 验证。图书馆 iframe 实测高度 720，viewport 720，输入框 2 个。
- 图书馆 CAS 服务名为“新图书馆空间预约系统”；课表为“UPC移动校园”。校园卡服务名显示“未注册的信息系统”：已如实记录，不能据此宣称校园卡登录能成功，也不能直接判定必然失败，需要核对学校接受回调的实际结果。
- 当前 App 进程 crash buffer 无记录。未进行完整断网重试真机验证；失败/超时行为已有回归测试。
- REA 仅辅助分析学校公开前端；未获取个人凭据，未使用真实账号，未执行预约或取消。

## 请在手机验证

1. 覆盖安装 APK，保留数据。先检查旧日程仍在，不要为排错先卸载。
2. 课表 → 导入 → 登录并同步学校课表：应显示官方登录表单，无 404。本人正常登录后检查学期列表、完整预览，再确认写入；重复同步应无重复。
3. 校园卡余额 → 登录学校统一认证：应显示表单。注意“未注册的信息系统”提示；若学校拒绝认证或回调，只反馈脱敏错误文字，不发送密码、完整回调 URL 或 token。只有回到原生页并读到本人实际余额才算完成。
4. 图书馆 → 使用学校统一认证登录：应显示表单。本人正常登录后验证原生查询；预约/取消仅由本人明确操作，并核对学校最终记录。
5. 可测试网络失败后的错误与重试，以及开启记住登录后的重启复用。以上真实账号链路本轮未验证。

尊重手机已能查看两校区电费的反馈，本轮未改电费。此前核验古镇口站点证书到期日为 2026-07-11；本轮没有开启任何证书绕过。可另行研究仅对古镇口只读连接、固定服务身份的限域兼容方案，但不能全局 trustAll 或在统一认证中 SSL proceed；该兼容尚未实现。

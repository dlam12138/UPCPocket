# 2.0.8 · 待办清单桌面组件调研与计划

日期：2026-11-17。状态：**已进入 2.0.8 本地开发，尚未完成候选验收**。当前正式版仍为 2.0.7 / 28，正式版有三个桌面组件。本文件保留前期调研与目标，文中“现有/拟实施/仅文档”按调研时点理解；后续开发依据、实际落地及未验证部分见 [开发记录](../releases/2.0.8-development.md)。功能为 P1，数据升级与页面稳定性为发布前提。详见 [总计划](2.0.8-update-plan.md)和 [CHANGELOG](../CHANGELOG.md)。

## 需求与可行性

来源为用户转交的同学反馈截图，仅记录功能诉求，不入库评论者身份、头像或截图原件。

| 反馈要求 | 计划行为 |
| --- | --- |
| 待办内容与截止时间 | 展示未完成事项标题及其可选截止时间；未设截止的任务仍可显示 |
| 勾选框 | 在桌面直接完成事项，保存成功后同步清单和数量 |
| 新建待办事项 | 「＋」直接打开应用内新建面板，用户输入并保存 |
| 剩余待办数量 | 显示全部未完成事项总数，不能只统计组件当前可见行 |
| 其他操作进入应用 | 点事项正文打开对应任务；标题/数量进入待办页，编辑、删除等在应用内完成 |

**可行，主要工作包括独立截止字段、兼容迁移、桌面交互及刷新导航。** 现有 RemoteViews 与本机待办服务可以复用，minSdk 31 已覆盖 Android 12 的交互式 CheckBox，不需要迁移 Glance、Navigation 3、Hilt 或升级构建依赖。[Android 状态交互说明](https://developer.android.com/develop/ui/views/appwidgets#stateful-behavior)

## 拟实施方案

### 截止时间与数据兼容

- 拟新增可空 `dueAt`，在领域模型、Entity、读写接口及应用编辑界面中独立表达截止时间。原 `reminderAt` 和提醒权限语义保留，设置截止不自动开启通知或精确闹钟。
- 先确定#9提出的Room/KSP候选基线，再统一设计Todo v1→v2；Room运行库升级不会自动新增`dueAt`，不能替代schema迁移，也不由两条开发线各写一套v2。保留focus独立数据库及其兼容结构，两个库分别核对。
- 旧任务迁移后截止为空，原标题、完成状态、时间、revision 与提醒记录保持；保留数据库文件名和任务 ID，不清库、不用破坏性迁移、不从提醒时间倒推截止。
- 建议首版截止支持可选日期与时分，按设备本地时区选择和展示，保存绝对时间点；仅日期/全天的交互在实施前明确，不能把当天零点擅自当全天截止。
- 截止编辑也经过服务并维护 revision 与必要提醒重建。新增接口时核对首页摘要、待办页、通知动作、DAO、schema 和相关测试消费者，同步内部 API 与数据兼容记录。

### 组件布局与操作

- 建议默认 4×2、允许缩至 2×2，按实际 dp 空间和字体大小决定可见条数。延续 24dp 圆角、近实底与深浅色基线；尺寸、条数属于设计建议，尚未经过视觉验收。依用户后续要求，待办与校园卡、电量、课表共用可选外观设置；默认基线保留，用户认可01/03/05方向，桌面通透度/静态高光的具体参数待局部验证，详见 [全部组件外观方案](2.0.8-library-layout-and-widget-appearance.md)，不另存一套待办材质偏好。
- 建议首版用有限行摘要显示未完成事项，超出部分点进应用查看；滚动清单可作为备选，用户未要求桌面承载完整编辑流程。
- 建议按已逾期、临近截止优先，无截止按创建时间排序，用稳定 ID 打破同值。实施时明确应用、首页和组件各自排序及共用规则；提醒时间继续明确标为提醒。
- 勾选、正文和新建区域分开，避免一次点击同时完成任务和打开应用。完成成功后从未完成列表移除，取消完成可在应用内处理。
- RemoteViews 的支持控件不包含 EditText，「＋」应打开应用新建面板；新建、打开任务、打开待办页使用固定动作，在活动页只消费一次，同时同步 Pager 与底栏选中状态。[RemoteViews 控件范围](https://developer.android.com/reference/android/widget/RemoteViews)
- 导航以#8待合入的五Tab和稳定route接线，不依赖旧Tab下标；应用编辑页接#9公共控件时保留输入、截止/提醒选择及保存中状态，主题切换与返回不重复新建或保存。桌面仍是RemoteViews静态材质，不调用应用内Backdrop渲染。

### 完成动作与系统入口

- 完成动作经 `TodoStore.setCompletedIfRevision` 写入，不直接改 DAO，不按未知当前状态执行 toggle。携带并校验当前包组件、widgetId 归属、合法 taskId、revision 和允许的目标状态。
- API 31 的 `setOnCheckedChangeResponse` 会填入 `RemoteViews.EXTRA_CHECKED`。接收该动态值的 PendingIntent 需要允许填入，不能一概设为 immutable；普通不需动态参数的新建/打开入口优先 immutable。集合内勾选须用 `RemoteResponse.fromFillInIntent` 配合可变模板。独立行读取动态勾选值同样需要可变性，这是由 API 填入语义作出的设计判断，尚待设备验证。[勾选响应 API](https://developer.android.com/reference/android/widget/RemoteViews#setOnCheckedChangeResponse(int,%20android.widget.RemoteViews.RemoteResponse))、[集合模板示例](https://developer.android.com/develop/ui/views/appwidgets/collections)
- 必须可变的入口固定 action、component 和 package，仅接受约定字段；私有写入 Receiver 非导出，不接收任意路由、URL 或嵌套 Intent。`onCreate` 与 `onNewIntent` 使用同一校验规则。[PendingIntent 安全要求](https://developer.android.com/privacy-and-security/risks/pending-intent)
- 如后续采用 `RemoteViewsService` 滚动列表，另核对 `BIND_REMOTEVIEWS`、模板与 fill-in 的约束；不直接给集合行套普通 `setOnClickPendingIntent`。
- 成功落库后重绘所有实例，取消对应旧提醒/通知；旧 revision、目标已删除或保存失败时重绘真实状态。系统临时勾选效果不能作为保存成功证据，每次渲染显式设置实际勾选状态。

### 本地刷新与边界

- 渲染与待办模型归 `feature:todo`，Provider、Intent 和系统调度归 `app`。通过宿主注入的窄回调或宿主订阅连接刷新，不让 feature 依赖 app，不新增独立任务表或计数。
- 新增、编辑、完成、删除、撤销以及通知完成/稍后等持久化变更后，刷新所有待办组件实例。刷新需覆盖组件冷启动路径，不能只依赖 Activity 正在收集 Flow。
- 首次添加、调整尺寸和普通进程重建后的入口异步读取本机数据；不得将 Room IO 放进 Receiver 主线程，也不能因未打开应用就显示成功空列表。
- 数据变更可直接更新组件，不必等待 30 分钟周期。时间文案和逾期排序在截止、跨日及系统时间/时区变化时安排本地重绘，必要兜底复用现有调度方式；仅有组件时保留调度，删除最后一个时取消。系统后台限制仍可能延迟刷新，不承诺截止时刻准点提醒。[组件更新机制](https://developer.android.com/develop/ui/views/appwidgets/advanced)
- 全流程不需要学校认证、联网或新常驻服务；待办仍独立于学校账号。有效空列表、读取失败、尚未恢复和插件不可用分别表达；缺插件不能旁路创建服务或伪装“暂无待办”。待办正文只用于本机业务与桌面展示，不进入诊断或公开样本。

## 实施顺序与最小验收

先按 [总计划](2.0.8-update-plan.md) 确定依赖基线，再完成截止模型、编辑界面和无损迁移，随后接组件渲染、动作与五Tab导航，最后核对本地刷新、多实例同步和页面状态恢复。两阶段同属本计划，不以暂时删除截止需求缩小范围；实现时同步 ARCHITECTURE、API、相关 ADR、README、隐私说明及 M5 入口映射，记录实际验证结果。

后续仅做与本改动相关的定向验证：

1. v1 升级保留原任务、完成状态和提醒；旧任务无截止，新截止与提醒可分别设置。
2. 组件勾选成功完成，列表、总数、应用与多个实例一致；编辑后的旧 revision 不改写新任务，失效动作重绘当前状态。
3. 「＋」直达新建，正文打开正确任务，标题/数量进入待办页；冷启动与已有 Activity 均只消费一次，已删除目标与缺插件状态真实。
4. 新增/编辑/删除/撤销及通知动作后更新；普通进程重建、组件缩放后能读取本机数据并保持勾选正确，时间状态能重绘。
5. 核对常用紧凑/宽尺寸、深浅色与大字体，区分完成区和导航区。按系统入口影响做必要 Release 安装冒烟，保留数据，不扩展为无关压力或设备矩阵测试。

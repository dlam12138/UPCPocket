# 2.1.1 更新计划

2026-11-23 整理。基线为已发布的 Android 2.1.0（versionCode 41）。本页收录用户反馈、调研依据和候选验收条件，各项目前处于待开发或待评估状态。 [2.1.0 发布记录](../releases/2.1.0.md) · [2.1.0 开发计划与完成情况](2.1.0-update-plan.md)

## 用户反馈与处理顺序

| 反馈 | 2.1.1 计划 | 状态 |
| --- | --- | --- |
| 勾完待办就消失，连勾几项只能从提示里撤回最后一项 | 日程待办完成后在原位置打勾和划线，连续勾选的各项都能在原行取消完成 | 优先 |
| 待办希望按日期、重要程度排序，也能自己调整 | 「全部待办」提供日期、重要程度和手动排序，日程待办沿用相应顺序 | 拟开发 |
| 想在桌面同时看到今天和明天的课 | 新增独立「今明课表」组件，沿用 UPC Pocket 的视觉和课表缓存 | 拟开发 |
| 讲座、考试可以设某日几点到几点，并在课表及今日安排看到 | 新增本机个人日程，在课表和日程待办可添加，在相应日期与首页今日安排显示 | 拟开发 |
| 希望首页顶部显示自定义正计时或倒计时 | 可选固定一项纪念日，按日显示上学、考试、毕业等日期的距离 | 拟开发 |
| 想查看本人的教务成绩、学分和绩点 | 新增只读「成绩与学分」，先做教务同步和按学期查看明细，核实口径后提供总览 | 拟开发，先核对成绩来源 |
| 希望有个备忘录 | 优先评估可独立保存的本机短文本，比较「全部待办」内入口与事项备注，确认用法后排期 | 预研 |
| 希望只看课表 | 先核对现有课表直达路径，评估同一安装包内的课表单页入口 | 预研 |

## 调研依据

- WakeUp 的 Android 文档列出今日、近日、一周和日视图四类组件，其中部分可自定义样式。今明并排是一张用户示意图表达的需求，具体版式使用本项目的组件风格。 [WakeUp 桌面小部件](https://www.wakeup.fun/doc/widget.html)
- Android 12（API 31）起支持按网格指定组件初始尺寸和按实际空间提供响应式 RemoteViews。桌面和网格会影响可用 dp。系统的 `updatePeriodMillis` 周期下限为 30 分钟，事件和本地任务也可以触发更新。今明版适合复用现有本地重绘链路，午夜更新时间以桌面和系统调度为准。 [Android 组件布局](https://developer.android.com/develop/ui/views/appwidgets/layouts) · [组件更新方式](https://developer.android.com/develop/ui/views/appwidgets/advanced)
- Google Tasks 的 Android 版提供按截止日期、最近加星及手动顺序等排序方式。Google 日历将计划开始与结束时间和任务截止日期分别设置。UPC Pocket 的待办排序和日程时段可各自处理，按同一天汇合展示。 [Google Tasks 排序](https://support.google.com/tasks/answer/7675629?co=GENIE.Platform%3DAndroid&hl=en) · [Google 日历任务时间](https://support.google.com/tasks/answer/9901136?hl=en)
- Room 支持增量迁移和迁移测试。现有 `upcpocket-todo.db` 的实际版本为 v2，已有 v1 → v2 的可空截止字段迁移。ADR 003 记载的是当时的 v1，后续迁移按正式版代码和现行数据归属制定。 [Room 迁移](https://developer.android.com/training/data-storage/room/migrating-db-versions) · [TodoDatabase](../../feature/todo/src/main/kotlin/com/upcpocket/app/todo/data/TodoDatabase.kt) · [数据归属与兼容](../../ARCHITECTURE.md#数据所有权与兼容) · [ADR 003](../adr/003-data-ownership-and-schema-compatibility.md)
- 用户提供的成绩页和现有课表页同属 `app.upc.edu.cn`。2026-11-23 匿名请求成绩入口收到 HTTP 200，成绩业务的认证方式、本人核验、字段、学期覆盖及分页仍待确认。 [学校成绩页](https://app.upc.edu.cn/site/score/index) · [现有课表来源](../upc/官方入口.md#课表来源与验证边界)
- 教务处成绩证明指南给出必修课五分制平均学分绩点的学分加权口径，适用范围是该证明模板。教务处当期学业警示通知另按培养计划相关学分核对，并提示学分冲抵可影响结果。移动成绩页的总 GPA 和学分字段含义需以实际教务来源核实。 [教务处成绩证明指南](https://jwc.upc.edu.cn/_t34/2013/0929/c22241a372563/page.psp) · [2026–2027 学年第一学期学业警示通知](https://jwc.upc.edu.cn/2026/0910/c18519a499499/page.htm)

## 实施范围

### 日程待办与排序

- 两个宿主共用的日程待办目前只列未完成项，完成后由单个撤销提示恢复最后一次操作。「全部待办」已按完成状态分组。新增在原行打勾、划线和再次点击取消完成，按任务 ID 分别保存。完成状态不参与当天排序，写入失败恢复行状态并明确提示。折叠卡片继续能展开，未完成计数独立。 [日程筛选](../../feature/todo/src/main/kotlin/com/upcpocket/app/ui/todo/TodoSchedule.kt) · [日程卡片](../../feature/todo/src/main/kotlin/com/upcpocket/app/ui/todo/TodoScheduleSection.kt) · [宿主导航](../../app/src/main/java/com/upcpocket/app/ui/nav/AppNav.kt)
- 有截止或提醒的任务保留在对应日期。因逾期或无日期出现在「今天」的任务，完成后依据实际完成日期在当天保留，次日的「今天」继续只接纳未完成的逾期和无日期任务。切换到专注页宿主或重开应用时从同一 Room 数据恢复。完整列表继续保有已完成分组。
- 日期顺序默认延续已有口径。完整列表先按截止时间升序列出有截止的任务，再按创建时间倒序列出无截止的任务。日程卡按选中日已有的截止、提醒时间排序。重要程度拟设高、普通、低，旧任务默认普通，同级采用日期顺序。手动模式支持拖动或上移、下移，按任务 ID 在一次事务内更新独立的排序记录，保留任务记录、提醒 `revision`、提醒时间和发送状态。切换排序模式后仍可回到自定义次序。 [待办排序](../../feature/todo/src/main/kotlin/com/upcpocket/app/todo/data/TodoOrdering.kt)
- 完成和恢复继续用任务 ID 加当前 `revision` 执行条件写入，并沿用提醒协调。桌面待办继续读取未完成摘要，原有通知与新增入口继续指向现有路由。 [TodoStore 与系统消费者](../../API.md#业务能力与系统消费者)

### 今明课表组件

- 计划在系统小组件列表和「设置 → 桌面组件」提供独立「今明课表」，优先做到约 4×2 宽卡。两日各列日期、节次和课程名，超出行数给出数量。根据 Launcher 实际宽高和字号精简文字，保留两日及各自的状态。整卡打开「课表」，课表插件缺失时沿用现有组件的首页回退。已有「今日课表」和「本周课表」继续独立可选。 [现有组件入口](../m5/README.md) · [课表组件视觉](../m5/2026-11-05-组件视觉修订.md)
- 以 `Asia/Shanghai` 的实际今天和次日读取当前账号已成功缓存的两天。周六的明天可能属于另一个教学周，按两日真实日期查找覆盖。两栏分别显示有课、已同步无课、该日未同步或学期外等结果，读取失败保留对应说明。复用本地缓存读取和发布前的账号、代次、日期复核。
- 同步成功、组件尺寸变化、时间变化和上海跨日触发本地重绘。今明版和今日版共用宿主调度入口，按组件实际需要选择跨日或课时边界。自动更新仅走本地路径，系统限制可能使显示晚于午夜。 [周快照](../../feature/timetable/src/main/kotlin/com/upcpocket/app/timetable/TimetableWeekWidgetSnapshot.kt) · [课表服务](../../feature/timetable/src/main/kotlin/com/upcpocket/app/timetable/TimetableService.kt) · [宿主组件调度](../../app/src/main/java/com/upcpocket/app/widget/TimetableWidgetTicker.kt)

### 个人日程与今日安排

- 课表日期入口与日程待办的新增入口共用本机编辑流程，可选择创建「待办」或「日程」。日程填写标题、开始日期和时刻、结束日期和时刻，以及可选地点或备注。结束必须晚于开始。例子为某日 14:00–16:00 的讲座或考试。使用个人日程承载时间段，待办继续独立设置截止和一次性提醒。
- 课表对应日期显示个人日程标记和按时刻查看的列表，任意时段和重叠日程都可查看。日程待办按所选日期显示本机日程。首页「今日课程」区拟扩为「今日安排」，汇合课程和个人日程并清楚标记来源。课表加载、未同步或插件缺失时，仍可在首页查看本机日程。仅课表能力可用时，沿用课程展示与同步入口。日程待办移至专注页后，可继续从课表和首页查看个人日程。 [现有首页](../../app/src/main/java/com/upcpocket/app/ui/home/HomeScreen.kt) · [课表插件入口](../../feature/timetable/src/main/kotlin/com/upcpocket/app/timetable/TimetablePlugin.kt)
- 所有个人日程入口统一按 `Asia/Shanghai` 录入和编辑，表单标注「上海时间」，起止保存为确定时点。设备更改时区后重开表单，仍显示和保存原上海时间。选择的时刻无法唯一对应实际时间时，例如时区规则造成当地时间跳过或重复，提示改选。课表及首页「今日安排」沿用上海日期，日程待办沿用设备本地日期。跨日取时间段与日期的交集，零点结束的日程计至前一日。设备时区与上海不同时，显示时段的视图注明时间口径。
- 拟由 `feature:todo` 持有个人日程独立表与读写入口，沿现有 Room 迁移链无损新增表。宿主从最终激活能力接入，按窄契约注入课表和首页所需展示数据、编辑入口，feature 之间保持独立。学校课表继续按账号保有只读缓存，换号或删号时撤下旧课程并拒绝迟到快照，保留个人日程、待办和本机偏好。 [模块边界](../../ARCHITECTURE.md#模块与依赖) · [隐私与数据](../PRIVACY.md)

### 首页纪念日正计时与倒计时

- 从「设置 → 应用」管理一个可选的首页纪念日，填写标题、日期，选择正计时或倒计时，可关闭顶部显示。开启时在首页日期附近显示一行，默认关闭。
- 正计时在起始日前显示「还有 N 天开始」，起始日为第 1 天。倒计时在未来显示「还有 N 天」，目标日显示「就是今天」，过期显示「已过 N 天」。与首页共用上海日期，进入和跨日时按当前日期重算。设置仅保存在本机。参考图中的重复规则先作为后续选项评估。 [首页日期与页头](../../app/src/main/java/com/upcpocket/app/ui/home/HomeScreen.kt)

### 成绩与学分

- 拟在「服务 → 学习与空间」增加二级页，采用项目现有界面样式。用户点击「教务同步」后，只读获取本人课程成绩。明细按学期和学校提供的课程性质筛选，显示课程名、教务原始成绩、课程学分和可确认的通过状态。页面标明已同步的学期和上次成功同步时间。成绩入口可交由系统浏览器打开。 [服务目录](../m5/README.md#12-旧--新入口映射) · [学校成绩页](https://app.upc.edu.cn/site/score/index)
- 沿用课表使用的统一账号引用与凭据代次校验，参考其宿主装配和状态处理。独立成绩模块负责协议、解析和数据。确认学校成绩使用 CAS 后，可复用 `core:upc-auth` 的登录能力，按实测的成绩回调建立独立业务会话。结果须与当前本人会话绑定，学校返回可用身份字段时一并比对。需要交互验证或无法确认归属时交由学校网页处理。 [课表认证器](../../core/upc-auth/src/main/kotlin/com/upcpocket/app/upcauth/UpcTimetableAuthenticator.kt) · [课表服务](../../feature/timetable/src/main/kotlin/com/upcpocket/app/timetable/TimetableService.kt) · [账号与会话边界](../adr/002-account-generation-and-business-sessions.md)
- 首版成绩会话保留在内存。只将已核对归属、完整成功的学期结果加密保存在成绩专用的 `noBackupFilesDir` 子目录。刷新失败时可查看本账号上次成功快照，完整空结果、未同步和失败分别显示。写入及展示前复核账号、凭据、业务和请求代次。同号改密使旧会话失效，换号或删号立即撤下并清理对应缓存，缺插件时由宿主清理。 [宿主清理](../../app/src/main/java/com/upcpocket/app/core/AppGraph.kt) · [数据所有权与兼容](../../ARCHITECTURE.md#数据所有权与兼容)
- 总览拟包括总 GPA、必修 GPA、均分、修读及已获学分、通过率，以及按学期、课程性质和成绩分段的统计。点击学期或课程性质可打开对应明细。优先使用学校给出的明确口径和汇总范围。本地计算须核对适用规则及所需数据的完整性，明确重修、补考、等级成绩、免修、未出分、分母和舍入口径。未能核实的指标显示「暂不可统计」，部分学期仅展示对应学期的统计。修读及已获学分只反映已核对的查询范围。

## 开发次序与验收

先完成日程待办原位勾选，再接入排序。今明课表可单独开发；个人日程在敲定 Room 迁移、日期投影和宿主装配后接入。纪念日沿用首页日期和现有设置入口。备忘录预研先验证独立无日期条目能保存、重开和编辑。只看课表先试用「日程待办位置 → 专注」和桌面组件直达，再评估「仅看课程」视图对同步、返回、现有组件和入口回退的影响。独立安装包或全局切换留待专项评估。

成绩与学分可并行准备页面。确认学校授权范围、本人会话和学期查询协议后，再接入原生只读同步。先验收明细，逐项核对后启用总览指标。若原生来源尚未核实、学校网页已验证可查询，候选版可先提供固定网页入口。

| 后续验收 | 最小检查 |
| --- | --- |
| 待办 | 在课表和专注两种位置连续勾选两项，分别取消，重开后同日位置与状态一致。切换三种排序，核对手动顺序可恢复、截止和提醒时间保留。在允许提醒的设备上重排一项待触发任务，验证其提醒仍触发一次。 |
| 今明组件 | 同时看到有课和已同步空日，周六／周日邻接一日未同步时明确提示。检查宽卡和缩小后的文字、整卡导航、午夜及账号切换后的快照归属。 |
| 个人日程与升级 | 添加、修改和删除讲座或考试，在周课表、日程待办和首页核对同一条。一条跨午夜日程按日期正常呈现。将设备设为东京时区，用上海时间 23:30–23:50 的日程核对课表与首页归当日、日程待办归次日，重开表单核对原上海时段。从 2.1.0 保留数据覆盖安装，核对旧任务 ID、完成状态、截止、提醒及 `revision`，验证原 v1 迁移链可继续升级。 |
| 纪念日 | 核对起始日、目标日前与目标日/过期的文案，关闭后首页回到原布局，换号后仍可看到已保存设置。 |
| 成绩与学分 | 用已授权的本人真实账号走正常学校认证，读取并对照一个学期的课程成绩、学分和已启用的统计。用合成数据核对筛选、缺项、完整空结果和已启用的本地计算规则。检查断网后仍能查看本账号快照，换号或删号后旧成绩即时撤下、迟到结果无法写回。 |

实施时按影响选待办、课表和成绩定向测试、模块依赖边界检查及必要设备冒烟，并同步 M5 导航映射、数据归属与隐私文档。当前核对范围为用户截图、第一方资料、2.1.0 发布记录和仓库代码。功能、迁移和 Launcher 行为留待候选包验收。 [贡献流程](../../CONTRIBUTING.md) · [组件和课表设计](../m5/2026-11-05-课表与组件设计.md)

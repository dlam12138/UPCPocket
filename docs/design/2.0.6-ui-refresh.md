# 2.0.6 · 界面与交互更新工程方案

日期：2026-11-15。状态：**功能已实现，本地签名 Release 候选已构建并保留数据安装，待用户视觉评审，未发布**。本文为本轮需求和实施约束入口；实际实现、交付文件与验收证据见 [开发与验收记录](../releases/2.0.6-development.md)。

基线为正式版 **2.0.5 / versionCode 26**，应用标识 `com.upcpocket.next`，namespace 为 `com.upcpocket.app`。工程候选版本为 **2.0.6 / versionCode 27**；公开版本、更新清单和 Release 资产仍保持 2.0.5。

## 1. 目标与已确认范围

采用讨论中的 **A「清爽工具」+ B「随身日程」**：以清楚的文字层级、紧凑的服务入口和柔和的容器组织页面，把当天有用的信息放在前面，用短动画连接操作与结果。

| 区域 | 用户已确认的要求 |
| --- | --- |
| 首页 | 删除问候语，缩小日期；将课表页的「今日课程」移到首页顶部；适当收紧待办摘要和服务入口 |
| 课表 | 优化周网格的阅读层级、课程配色和详情呈现；今日课程移出后，周网格获得更多空间 |
| 待办 | 优化信息密度、完成反馈和列表过渡，保留已有新增、编辑、删除及提醒能力 |
| 查询页面 | 统一筛选、结果、刷新与异常状态的呈现，减少整页闪空和重复说明 |
| 空闲教室 | **本轮重点页面**，需要重排筛选与结果，解决当前页面显得杂乱的问题，不能只换配色 |
| 设置 | 统一账号卡片与分组列表；**图书馆登录默认收成一行，点击展开操作** |
| 账号保存 | 优化表单与状态层级；**删除固定的「尚未验证」，显示「已保存」**，保存成功提示同步简化 |
| 动效 | 为按下、切页、详情展开、完成待办和刷新提供适度反馈 |
| 专注 | **不改动专注页、计时交互、记录和统计**；共享组件调整也不能间接改变其视觉与行为 |

本文后续的字号、间距、动画时长、筛选面板形态属于工程建议，实施时以实际页面评审为准，不把这些数值视为用户逐项定稿。

不加入本轮的发散想法：自动重排服务入口、个性化首页编辑、待办与专注联动、全局搜索、新校园接口或写操作。保留当前四 tab「首页 / 课表 / 待办 / 专注」与整页 Pager，不新增「更多」目录。

## 2. 首页：今日课程先出现

目标顺序：

```text
较小的日期                                      设置
今日课程：完整的当日课程、上课中 / 下一堂、查询时间
紧凑待办摘要：未完成数量、近期任务、新增
常用服务：电费 / 空闲教室 / 图书馆 / 石光 / e站通 / 校园网页
校园卡：余额、流水及已有操作
四项浮动导航
```

- 删除问候与对应占位，日期降为普通标题或辅助信息，不再占据首屏主视觉；今日课程内的日期避免和页头重复铺陈。
- 「移到首页」指迁移现有今日课程能力，**不是只显示下一节而丢掉当天其余课程**。保留课程顺序、时间、地点、上课中、下一堂、已结束与点击详情；长列表随首页正常滚动。已结束课程默认折叠等额外行为需后续评审，不能直接替换全量课程。
- 未同步、账号尚在恢复、账号不可用、有缓存、读取失败、当日确实无课分别呈现。未加载或跨日旧数据不能显示成「今天没有排课」。首页提供去课表同步或去账号设置的短入口，行为由状态决定。
- 待办继续使用同一 Store 与排序，摘要维持最多两条；压缩容器内边距、标题与空态占位，保留新增、完成和进入待办页的路径。空态可以合并为紧凑一行，不用大块空白占位。
- 服务入口从当前较高的两列大卡改成紧凑图标加标题布局，主要减少容器高度与常驻副标题；动态插件数、长标题、大字体下仍自然排列。先以两列紧凑行评审，三列只在实际宽度足够时采用。
- 校园卡原有余额、流水、绑定、缓存与错误信息完整保留。二级功能入口不能在美化过程中遗失。

### 今日数据与插件边界

- 今日课程仍由 `:feature:timetable` 提供。建议为插件增加首页今日课程区块归属（如 `UiSurface.HOME_TIMETABLE`），由 `TimetableUi` 注册，宿主按区块顺序挂载；宿主不复制课表模型、读取密码或自行查学校接口。
- 课表插件未启用或被隔离时，首页区块与相应入口一起缺省，不留下打不开的占位。相关说明与映射同步到 [M5 文档](../m5/README.md)。
- 首页只恢复当前账号归属的本机课表缓存，按 `Asia/Shanghai` 的实际日期派生今日课程。**不能直接调用会联网的 `TimetableService.open()` 来填充首页。**
- 当前 `refreshToday()` 依赖内存 `lastIndex`；首页冷启动时不能假定它已由课表页初始化。实施时补齐只读本机索引与周缓存的恢复路径，磁盘读取放到后台，复用现有账号、代次和失效守卫。
- 缓存恢复不得更改用户正在查看的学期/周；切周不得清空今日课程。页面恢复、上海时区跨日后重算，未缓存新一天时回到真实未同步状态。
- 账号切换、改密、删除、清理未完成以及恢复期间的迟到读取不能复活旧账号课程。详情也随账号/数据失效关闭，不持有过期业务内容。

## 3. 课表与待办

### 3.1 课表

- 页面以「紧凑学期/周选择 → 周网格」为主，不再重复摆放首页今日课程；保留刷新、学校登录与说明入口。
- 弱化网格线与外框，拉开课程标题、地点和辅助信息层级。同一课程跨周使用稳定配色；文字与背景保持可读，深色模式单独检查。
- 日期继续按真实周日到周六连续排列；左轴沿用学校官方 1–12 节作息，13–14 节缺少官方时刻时显示「时间待确认」。美化不更改节次与日期规则。
- 突出今天；当前时段指示可作为视觉细化，但必须仅在日期、时刻确实对应时显示，不能改变课程时刻。
- 课程详情建议从现有弹窗改为底部展开面板，首页与周网格共用同一详情实现。保留教师、地点、源节次、周次及缺失字段的真实状态，返回后保留原滚动位置和查看周。
- 大字体或窄屏时优先保证可点与详情可读，不通过缩小字体强行塞满网格。内部横向滚动与一级 Pager 的手势职责需要实测。

### 3.2 待办

- 减少重复分隔与大块空态，统一首页摘要和完整列表的文字层级。
- 完成时先给明确勾选/文字反馈，再平滑移入已完成；提供撤销路径。数据写入由现有 Store 完成，动画不能延迟关键保存或让同一任务重复提交。
- 保留已完成折叠、连续新增、提醒设置、编辑、删除与已有删除撤销；完成过渡不得取消或恢复错误的提醒。
- 默认不增加横滑完成/删除，以免与整页 Pager 竞争。任何新增手势都需有可见按钮等价路径。

## 4. 空闲教室：把条件和结果分清楚

### 4.1 当前问题与重排目标

当前 `ClassroomFilterPanel` 同时铺开校区、日期与前后日按钮、教学楼、自选节次、古镇口卓越分类、多个时段组、节次汇总和查询按钮。下方 `ResultSummaryCard` 又重复一遍完整条件，结果网格采用较明显的状态底色和边框，多层控件与说明挤在一起。

本轮先减少默认页面同时出现的控件数量，避免筛选区占去过多首屏；结果区以楼栋和房间号为主，状态退为辅助标记。

建议默认页面结构（仅示意，不是真实查询结果）：

```text
返回  空闲教室
唐岛湾 / 古镇口                  日期选择
上午 / 下午 / 晚上等现有快捷时段
当前条件摘要                    筛选
查询状态 / 更新时间              查询或刷新
空闲数 / 总数                  仅看空闲
教学楼分组
房间号网格：空闲 / 占用文字及轻量状态色
```

### 4.2 筛选与结果呈现

- 校区、日期、常用时段直接可见；教学楼、自选节次等详细条件通过「筛选」按需展开，优先评审底部面板。日期前后切换可合并进日期选择区，保持能力可达。
- 古镇口保留「全部 / 卓越 A / 卓越 B」，可放在紧凑筛选区，当前非默认条件必须出现在摘要中；唐岛湾不显示该分类。
- 当前条件只在一处完整表达，结果侧保留必要的归属、计数、更新时间与更新失败提示。条件变化但尚未查询时，不能用新摘要包装旧查询结果。
- 教学楼仍为主要分组；房间号清晰，空闲用柔和状态色，已占用使用较弱的中性色，同时始终提供文字状态。减少每个房间的强边框与大面积高饱和填色，不改成热力图。
- 保留「仅看空闲」默认值及开关；统计、分组和空态基于相同筛选结果，不能因收紧页面漏算被过滤房间。
- 空目录、无空闲、等待查询、更新中、网络失败、协议数据不可确认分别处理。同条件刷新失败可保留带时间的上次结果；不同查询键的结果不冒充当前结果。

### 4.3 既有查询语义必须保留

| 操作 | 本轮保持的行为 |
| --- | --- |
| 真正进入页面 | 上海日期的今天、上午、全部教学楼；只恢复上次校区，恢复完成后一次初始查询 |
| 预设模式切校区/有效日期/快捷时段 | 沿用自动查询、相同查询键去重；快捷组的叠加/取消和部分选中语义保留，不直接改成互斥选项 |
| 自选节次 | 只改变条件，显式点击查询；切回快捷组后恢复预设模式 |
| 教学楼选择 | 保持手动查询；保留现有「查询全部」的显式查询能力 |
| 卓越 A/B、仅看空闲 | 当前结果的本机过滤，不新增学校请求 |
| 修改筛选/请求迟到 | 沿用取消与请求代次，旧响应不得覆盖新条件 |

详细筛选面板如使用草稿，打开、取消不能改变已应用条件或发请求；确认应原子应用，避免逐个调用会自动查询的 setter 引发多次请求。自动/手动规则仍按上表执行，不把展开动画或关闭面板当成查询事件。

自选节次沿用教室接口当前有效范围（现有实现为 1–13），不能直接套用课表网格的 1–14 节。未识别的卓越房间仍留在「全部」，原有跨校区重置与配置恢复规则不变。

## 5. 其他查询页面

- 电量、校园卡流水、图书馆、石光与 e站通采用一致的「当前条件 → 状态/操作 → 结果」层级；按现有能力整理，不给没有缓存的页面新增虚假离线能力。
- 常用条件可直接调整，较长筛选按需展开；保留原有选择、搜索、分页、加载全部、明细与网页登录回退入口。
- 同一有效查询与账号上下文内刷新时，尽量保留仍可用的已有结果和时间，用局部进度表示更新。切账号或筛选已不匹配时，先失效旧内容，再呈现等待或加载状态。
- 首次加载、已加载空结果、无搜索匹配、未登录、会话失效、验证码、离线、缓存和查询失败不能合并成通用空态。
- 图书馆现有座位确认、隐藏、未知结果防重与验证码回退不因动效改变；本轮界面方案不包含新的真实预约、取消或签到验收。

## 6. 设置与账号保存

### 6.1 设置

- 顶部为紧凑学校账号卡：标题、脱敏账号/状态、进入箭头。校园与应用项目采用统一分组列表，常规行不堆叠重复副标题；异常状态在所属条目直接可见。
- 图书馆登录**初始收起为一行**，点击展开现有「记住学校登录」、当前会话、退出与数据说明；再次点击可收起，展开/收起有短过渡。
- 收起不等于退出，不更改记住登录开关，不清理 Cookie，不触发重新登录。已有会话提示和错误状态仍来自真实服务；缺少图书馆插件时不显示空行。
- 桌面组件、校园官方网页、外观、关于继续指向原有页面。账号、图书馆登录不另建第二套目录。

### 6.2 账号保存文案（本次用户明确覆盖旧文案要求）

用户指出「尚未验证」不会随实际使用变化，因此本轮去除账号保存状态中的这条固定提示：

| 位置 | 目标文案 |
| --- | --- |
| 账号页的已保存状态 | `已保存 · <脱敏账号>`，没有可显示账号时仅 `已保存` |
| 设置页共用账号摘要 | 与账号页一致，不再展示固定「尚未验证」 |
| 保存成功反馈 | `已保存`；需要下一步引导时用独立短入口或短句，不再附加「尚未验证」 |

这是展示文案调整，**「已保存」只陈述本机保存成功，不改写为「已登录」「学校认证通过」**。内部 `SchoolAccountStatus.SAVED_UNVERIFIED`、账号代次、凭据恢复和各业务独立认证逻辑继续沿用；不做数据迁移，也不为匹配文案虚造已认证状态。课表、图书馆等页面仍反馈各自实际登录、验证码和查询结果。

M1 与历史发布文档中的「已保存，尚未验证」保留为当时记录；后续实现以本节新要求为准。实际尚未验证的测试分支、失败、离线、清理未完成等事实仍须如实表达，不能全仓替换删除「未验证」。

### 6.3 账号表单与安全边界

- 把状态、输入和操作分区，输入顺序清楚，优化键盘「下一项 / 完成」、保存进度、字段错误与成功反馈；长屏说明收进已有数据说明，不新增入口。
- 已保存后先展示账号、点击修改再展开表单可作为候选；是否折叠以及具体布局待实际视觉评审，不能视为已确认交互。确认密码字段本轮不擅自删除。
- 保存与删除操作明确分离，删除后果确认保留。读取失败、保存失败、清理未完成、重新保存要求继续显示，不能被「已保存」覆盖。
- 沿用 `FLAG_SECURE`、禁止自动填充、密码不进入 `rememberSaveable`/持久状态、保存尝试与离页清空密码的约束。普通配置变化可恢复非敏感 UI 状态，不能恢复密码。
- 检查键盘、系统栏与返回手势下的表单和按钮可达性；按当前 Compose 版本采用可用的 Insets 方案，避免重复加入键盘留白。

## 7. 视觉、动效与技术实现

### 7.1 视觉基准

- 延续 Material 3 与已有主题色、浅/深模式；以表面层级、留白和文字区分信息。课程颜色服务于识别，状态色服务于真实状态。
- 建议以 16–20dp 页面水平边距、12–16dp 容器内边距、8–12dp 同组间距开始评审，减少同一页多重外框与容器嵌套；这些数值不是验收的唯一标准。
- 图标与圆角统一；服务卡和设置行视觉紧凑，但触控目标至少 48dp，交互区域不能重叠。大字体允许换行、加高和减少列数，不强制压缩字号。[Android 触控规范](https://developer.android.com/develop/ui/compose/accessibility/api-defaults)
- 新样式优先由本轮页面显式使用。修改共享 `GlassCard`、主题 Typography 或通用行组件前核对调用方，确保专注页及桌面组件不会被间接改样。

### 7.2 动效清单

| 场景 | 建议动效 | 行为约束 |
| --- | --- | --- |
| 服务入口与设置行按下 | 很轻的压下或底色变化 | 点击立即处理，反馈不延迟导航 |
| 四 tab 切换 | 打磨现有页面与胶囊的跟手联动 | 不叠加重复入场动画，不改变专注页内容 |
| 课程详情 | 底部连续展开与收回 | 共用详情，返回恢复原位置 |
| 待办完成 | 勾选、文字变化、列表平滑补位 | 同一任务一次写入，可撤销，保持提醒一致性 |
| 图书馆登录/筛选展开 | 短高度过渡与内容淡入 | 展开不触发业务请求，收起不清数据 |
| 查询刷新 | 局部进度、更新区域短过渡 | 不滚动整页、不清空同条件可用结果、不伪造完成 |

微反馈建议先试 100–180ms，内容/页面过渡试 220–300ms，实际按触控与设备体验调整。动效应支持连续点击和中途打断，跟随系统动画缩放；关闭动画时结果和状态仍完整可用。首次进页不安排逐卡排队入场，列表/背景不添加持续装饰动画。

### 7.3 技术基线与改动落点

基线以源码配置为准：AGP 8.7.3、Kotlin 2.0.21、Compose BOM 2024.12.01、Gradle 8.9、minSdk 31、compile/targetSdk 36。本轮不为美化引入 Navigation 3、AGP 9、Glance、实验 Grid 或数据层迁移。可用技能为 `adaptive`、`jetpack-compose-performance` 与 `edge-to-edge`，按当前版本选取指导，不机械采用技能里的新 API。

| 工程落点 | 任务 |
| --- | --- |
| `app/.../ui/home/HomeScreen.kt`、`ui/nav/AppNav.kt` | 紧凑页头、首页顺序、区块挂载与四 tab 导航 |
| `core/plugin-ui/.../PluginUi.kt`、`feature/timetable/.../TimetablePlugin.kt` | 首页课表区块契约、贡献注册、缺插件一致性 |

## 8. 实施顺序与验收

### 8.1 实施顺序

1. 首页、今日课程数据复用、课表详情：先完成核心信息迁移和冷启动状态，再评审布局。
2. 空闲教室：重排默认筛选/详细筛选/结果，单独评审正常、无结果、失败与大字体页面。
3. 设置与账号：图书馆默认折叠、保存文案简化、表单键盘与清理状态。
4. 待办及其他查询页：统一密度和状态反馈，最后添加短动画。
5. 定向回归、Release 安装、截图评审与交付记录；未实现的分支继续明确标注。

### 8.2 必须覆盖的验收场景

| 区域 | 验收重点 |
| --- | --- |
| 首页今日课程 | 冷启动只读本机缓存且不联网；有课/无课/未同步/失败/跨日；当前与下一堂；切查看周不影响今天；首页与网格详情一致 |
| 账号生命周期 | 冷启动有界恢复、改密/换号/删除/清理中；迟到缓存不能恢复旧内容，旧详情失效 |
| 缺插件 | 课表区块、对应 tab、路由与快捷入口一致缺省；图书馆设置不留空行；其余服务正常排版 |
| 空闲教室 | 两校区、恢复后一次查询、预设自动/自选手动、快捷组叠加/部分选中、日期与楼栋、卓越 A/B、仅看空闲、统计/空态/详情一致 |
| 空闲教室并发 | 筛选取消无请求、确认无重复请求、同键刷新失败保留、不同键不误显、快速切换拒绝迟到响应 |
| 设置/账号 | 图书馆默认一行，展开收起不改变会话；状态仅显示已保存且无已登录暗示；密码清空、错误、删除后果、清理失败与键盘可达 |
| 待办 | 摘要/列表同数据、完成与撤销、连续新增、编辑/删除、提醒状态、过程打断与进程重建 |
| 查询页 | 同条件刷新、筛选变化、搜索无匹配、分页、离线、验证码、失败和缓存真实性 |
| 专注及组件 | 专注页面和行为不受共享样式影响；三个 RemoteViews 的尺寸、刷新、冷启动与整卡导航保持可用 |
| 尺寸/无障碍 | 浅/深、约 320dp 窄屏与常规宽度、1.0×/1.5× 字体，2.0× 作为边界检查；长课程/地点/楼栋名、TalkBack、动画关闭、系统栏与键盘 |

交付收尾遵从用户最新要求，停止追加极限组合矩阵。常规窗口、正常高度窄屏与 1.0×／1.5× 字体作为本轮检查范围；极短窗口叠加 2.0× 字体、深色和动画全关的 Debug 夹具异常单独记录，不作为额外交付门槛。已发现问题、未完成检查和原因未定位的事实仍写入验收记录。

实施时优先扩展现有 `TimetableServiceTest` / `TimetableScreenStateTest`、`FreeClassroomViewModelTest` / `FreeClassroomScreenTest`、`SchoolAccountScreenTest`、`TodoScreenTest` 及宿主插件 UI 测试，验证数据、状态与交互边界，不为圆角或固定间距另建机械断言。

与改动匹配的检查包括 `:app:assembleDebug :app:testDebugUnitTest`、相关 feature/core 定向单测、模块边界与受影响模块 Lint。最终用户候选为长期签名的 **R8 + resource shrink universal Release APK**；检查 merged manifest/APK 无 debug 夹具，并实际安装冒烟。已知 release unit test 的 debug-only manifest 限制按 [开发规范](../../AGENTS.md) 如实记录。

最终交付记录应包含实际改动、截图/动效走查、测试计数、设备范围、APK 字节数、SHA-256、证书指纹、ABI 和未验证项。覆盖安装前核对包名、版本与证书，保留用户数据。实际签名候选、构建测试及设备检查范围见 [开发与验收记录](../releases/2.0.6-development.md)；用户视觉验收后再单独处理正式发布。

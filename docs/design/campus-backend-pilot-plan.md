# UPC Pocket 校内后端建设计划书

Android 首期试点

UPC Pocket 项目组　｜　供信息化建设处及相关业务部门讨论　｜　2026 年 11 月 27 日

## 建设目标与试点范围

项目由校方主导推进。建议把后端部署在学校提供的服务器上，由手机发起请求，后端按当前学生的权限向对应校园系统查询，再把结果返回手机。首期先交付账号服务。取得教务部门的本人课表只读授权后，再用“查看本周课表”验证整条链路。校方可以分别启用和停用这两项服务。

### 首期交付

| 项目 | 交付内容 | 启用条件 |
| --- | --- | --- |
| 账号服务 | Android 在学校页面登录，Pocket 建立账号关联，支持退出和撤销设备会话。 | 校方确认账号字段、登录协议、停用方式及撤权生效时限。 |
| 本人课表 | 手机按学期和周次查询本人课程，返回课程、节次、地点及可取得的数据更新时间。 | 教务确认使用范围和字段，校方提供能限制到本人的只读接口。 |
| 后续服务 | 校园卡余额、图书馆查询可沿用同一接入方式。预约、充值分别设计确认、防重和结果核对。 | 各业务主管部门逐项授权、验收，再确定上线批次。 |

### 现状与范围

现行 Android 版由设备直连相应校园服务，用户可主动将学校账密加密保存在本机。首期只安排 Android，未来原生 iOS 应用可复用后端接口。国产模型仅供开发团队辅助编码与编写文档。[现行账号与会话架构](../../ARCHITECTURE.md#本机账号与业务会话) · [项目隐私说明](../PRIVACY.md#学校账号)

### 请校方在启动时确认

请指定牵头单位、身份认证和教务接口负责人，确认“仅账号储存在校方服务器”所含字段，提供现行集成规范和试点办理流程。校方公开的试行办法对数据使用申请、使用协议和保密承诺作了规定。接入学校数据平台还涉及技术备案和第三方安全评估，具体材料按校方现行要求办理。[校方数据管理办法第 17、18、23、24 条](https://nic.upc.edu.cn/_upload/article/files/6c/9e/2a94c6d147b6b1db688e86dac858/7bf8e886-e435-4ea6-b403-5bf10cdf08bd.pdf#page=5) · [信息系统建设集成规范入口](https://nic.upc.edu.cn/2026/0312/c7408a484506/page.htm)

## 一次课表查询如何完成

**Android 应用 → 校方 HTTPS 网关 → Pocket 后端 → 校方数据平台或教务接口**

1. **校方验证身份。** 学生在系统浏览器的校方页面登录。若采用 CAS，Pocket 后端向校方校验专发给 Pocket 的单次票据。若采用 OpenID Connect，Android 使用授权码和 PKCE（S256），回调限已登记地址，后端核验签名、签发方、受众、有效期及本次登录绑定。通过校验后才为手机建立可撤销的 Pocket 会话。[CAS 服务票据规范](https://apereo.github.io/cas/development/protocol/CAS-Protocol-Specification.html#311-service-ticket-properties) · [原生应用登录规范](https://datatracker.ietf.org/doc/html/rfc8252) · [OAuth 安全规范](https://www.rfc-editor.org/rfc/rfc9700.html#section-2.1.1)
2. **按本人身份查询。** 手机请求拟定接口 `GET /v1/me/timetable`，仅提交学期和周次。Pocket 从有效会话确定本人身份，使用教务认可的用户授权，或由校方数据平台在服务端限定本人的查询范围。若共享方式是整表同步，请校方先提供按本人取数的接口。
3. **把必要结果返回手机。** 后端检查返回字段和授权范围，在内存中处理课表并返回。只有上游明确返回完整空周，手机才显示“本周无课”。上游超时或无法确认结果时，提示查询失败。有本机缓存时可显示上次成功内容及时间。

### 账号和业务数据分别放在哪里

| 信息 | 处理位置和保存方式 |
| --- | --- |
| 账号资料 | 校方服务器的 Pocket 账号库仅保存应用用户标识、校方稳定标识及启停状态。业务确需学号时，由校方接口提供受控映射。账号停用、解绑、删除及备份到期规则由校方确认。 |
| 密码与校方会话 | 推荐由学校统一认证系统处理数字石大密码。若校方要求托管密码供旧系统代登录，单列责任主体和审批，由校方管理的专用凭据服务承担，再决定接入范围。 |
| Pocket 会话 | 校方一次性票据用完即弃。Pocket 签发可撤销的随机会话令牌，服务端将令牌摘要和有效期短时保存在内存，关闭持久化及备份。会话丢失或到期，用户重新认证。 |
| 课表及本机内容 | 课表正文只在后端请求期间处理，离线副本由手机按账号隔离保存。待办、专注和个人日程继续由设备保存，均不进入校方账号库。 |

校方 2024 版共享目录列出的本科生和研究生课表为每日同步。若试点沿用该来源，手机应区分学校数据更新时间与本次查询时间。上游未提供更新时间时，仅标示本次取得时间。[校方共享目录，本科见第 30 页、研究生见第 50 至 51 页](https://nic.upc.edu.cn/_upload/article/files/26/68/103edc744faa995d4b1ae5175dad/99a919b1-1c70-4d57-8398-174b5ad0c714.pdf#page=30)

## 安全运维与用户迁移

### 生产环境由谁管理

| 责任方 | 建议职责 |
| --- | --- |
| 信息化建设处及校方运维 | 管理域名、证书、网关、主机、密钥和生产权限。确定安全评估、审计留存、应急联系人及撤权时限，执行发布、停用和恢复。 |
| 教务等业务主管部门 | 确认服务对象、批准字段、数据更新频率和调用额度，提供只读接口与对账依据。授权变更时通知运维并复核访问范围。 |
| UPC Pocket 项目组 | 开发 Android 与后端，交付接口说明、部署和回滚步骤。在隔离环境开发联调，生产操作经校方授权。开发模型仅使用可提供给开发工具的代码、公开资料或合成样例。 |

### 服务器上的防护措施

首期建议部署一个 Pocket 后端程序，内部划分认证、会话和课表模块，账号数据使用独立关系库。技术选型沿用校方能长期运维的栈。若校方没有指定，可采用 Spring Boot 和 PostgreSQL。

- **限制访问范围。** 对外开放校方 HTTPS 网关，后端和账号库部署在受限网络。校内链路同样校验证书。每个业务只连接登记的上游地址和方法，分别配置服务身份、限流和超时。
- **控制密钥和人员权限。** 服务密钥由校方托管、按业务轮换。开发、测试、生产环境分开。生产运维使用实名账号和多因素认证，临时权限到期收回。账号库及备份加密，由校方验证恢复。
- **防止查询正文被留存。** 对个人响应关闭共享缓存，网关、应用、监控和报错链路过滤票据、查询参数、请求和响应正文，并关闭相关临时落盘。排障记录只留随机请求号、固定结果和耗时。运维人员操作由校方独立审计。

### 从旧版本切换及退出试点

学生主动选择学校登录，在官方页面重新认证。原设备保存的密码、密文和 Cookie 不上传。换号时撤下前一账号的课表和组件内容，丢弃迟到的查询结果。清理学校账号资料时保留个人待办、专注和日程。启用试点前，向参与者说明账号保存位置、查询经手的数据及解绑入口。

Pocket 通过校方停用通知或在约定时限内复核身份状态，撤销该用户的会话。离线手机重新联网获知撤权后，清理该账号的课表缓存和组件内容。出现跨账号显示或个人正文泄露时，校方运维停用受影响接口、通知参与者，业务复核后再开放。期间学生可打开官方网页或使用本机功能。试点结束时，按约定清理账号和备份，收回临时权限，移交部署配置、恢复步骤和联系人清单。

## 实施排期与验收

以下为资源到位后的五周排期建议。请校方确认可提供的网关、测试主机和密钥托管设施，并为 Pocket 分配独立的账号数据空间。测试与生产分别配置。主机规格、容量及经费由校方按试点人数和可用资源核定。

| 时间建议 | 主责与工作 | 交付及放行条件 |
| --- | --- | --- |
| 第 1 周 | 信息化建设处牵头，与身份平台、教务及项目组确认范围。 | 账号字段表、责任人、登录接入配置、课表授权申请和试点数据处理说明。 |
| 第 2 周 | 项目组和身份平台接通 Android 登录与校方账号服务。 | 在校方测试环境演示本人登录、退出、设备撤销及账号停用，可独立验收。 |
| 第 3 至 4 周 | 教务授权到位后，项目组对接本人课表，完成客户端切换和运维交接。 | 只读接口说明、字段清单、账号隔离记录、停用与恢复操作步骤。授权待办时先交付账号部分。 |
| 第 5 周 | 校方组织小范围试点，业务部门和项目组共同核对结果。 | 脱敏验收记录、遗留问题、责任人和处置意见，由校方决定是否扩大范围。 |

### 试点现场怎样判定通过

1. **本人登录与撤权。** 两名获准参与者各自用本人真实账号，通过校方页面登录。退出或撤销一台设备后，其旧会话按约定时限失效。校方停用账号后，所有关联设备按同一约定停止访问。
2. **课表一致与隔离。** 在已授权的课表阶段，两位参与者各自与教务页面核对同一教学周。切换账号后，页面和组件仅展示当前账号内容。只记录比对结果。
3. **存储边界和异常提示。** 运维用合成业务标记核对账号库、日志、缓存和备份范围。在隔离测试环境模拟上游暂不可用，手机显示失败或标明时间的历史缓存。真实业务内容仅由参与者本人核对。
4. **校方能独立接管。** 运维按交接文档停用试点接口、撤销试点会话，在隔离环境完成一次加密账号备份恢复。业务部门确认复开条件，项目组交回试点临时权限。

账号服务与课表分别记录验收结论。若当期仅获账号侧授权，验收范围止于账号服务，课表待教务完成授权后另行排期。后续每新增一项业务，沿用相同的授权、上线和撤回流程。

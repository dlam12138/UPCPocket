## 选座：源码事实与拟议交互

### 问题来源

[LibrarySeatScreen.kt](../../feature/library/src/main/kotlin/com/upcpocket/app/ui/library/LibrarySeatScreen.kt) 的 `SeatMap` 按完整 `rows × cols` 逐格绘制，格子固定 38dp，空坐标也占同样空间，容器最高 430dp 并支持双向滚动。大范围稀疏坐标会放大空白，座号文字仅 8sp；直接把整图进一步缩小会继续损害阅读和点选。

学校截图底部提供“座位布局图选座”，据此推测截图中紧凑的多列座号可能是列表视图，而非同一坐标图的缩略版。这是**截图推断**，本轮未登录学校验证切换行为，不当作官方页面协议结论。

### 两种展示共用同一选择状态

建议在既有“按座位选”内增加“座位列表 / 布局图”：

| 展示 | 实施建议与约束 |
| --- | --- |
| 座位列表 | 只从当前房间已取得的 `layout.seats.filter { it.isSeat }` 派生，省去坐标空白；保留原座号、状态、选中、隐藏和更多操作。数字座号按数值排序，保留前导零；非数字名称明确稳定排序规则，同值以稳定 ID 打破。列数根据实际宽度和字体决定，不固定照搬学校截图的六列 |
| 布局图 | 保留相对位置、内部通道和非座位布局元素。只裁去真正的外围空白，计算边界时不能排除隐藏、不可用座位或有意义布局元素；缩小概览用于定位，放大后准确点选，提供复位。不能把内部空行空列删除后冒充实际布局 |
| 切换 | 只改变展示方式，共用选中座位 ID、已选时段、底部摘要和原确认流程；不触发业务模式切换或重复请求，不清除用户时段 |
| 恢复 | 展示偏好与滚动/缩放状态按系统及房间隔离，普通旋转/重建可恢复；换房间不能沿用旧房间视口。不锁定方向 |

`RoomSeatMode.SEAT/TIME` 仍表示“按座位选 / 按时段找”。列表/地图切换不能调用现有 `setSeatMode`，它会清除另一业务模式的确认和时段状态；也不能为了切视图重新调用 `chooseSeat`。列表建议复用外层 `LazyColumn` 组织网格行，避免嵌套无界高度的懒网格，不为此引入新实验布局依赖。

首轮重点覆盖反馈中的唐岛湾页面；同层 UI 按图书馆局部指令同步古镇口东区、求是。可参考 [ChaoxingSeatScreen.kt](../../feature/library/src/main/kotlin/com/upcpocket/app/ui/library/ChaoxingSeatScreen.kt) 已有的外围范围和按宽缩放思路，但 libseat、seat、seatengine 的坐标、占用、时间 ID、会话与确认规则保持独立，不共用未经核实的学校协议。

### 实施前必须处理的兼容点

静态审计发现：当前 `openRoom` 清空 `hiddenSeatIds`，进入房间后没有立即重新加载隐藏偏好；自动读取主要位于切到按时段模式的路径。新列表依赖隐藏状态，因此应在房间就绪时通过现有房间上下文与 `hiddenGeneration` 守卫恢复隐藏偏好，分别表达读取中和失败，不能以空集合冒充读取完成。同时核对普通 `chooseSeat` 与确认入口，确保已隐藏项不能经新视图重新选中/提交。

这是**待实施的源码兼容点，未运行复现或修复**。沿用 `LibraryHiddenSeatsStore` 的持久化格式、原子写入、撤销与恢复；隐藏只影响本机展示，不上传、不改变学校状态、换号不误删。地图仍保留隐藏项位置，不因隐藏重排。

预约仍经过原预检和单次提交守卫。只读布局或展示验证不能替代真实预约、取消、签到验收；本轮不执行这些操作。

## 2026-11-18 外观决定

按用户验收反馈与同一模拟器上的短帧采样，2.0.8 应用内继续采用 Material 3。完整实时折射、模糊和动态高光尚无满足原主题流畅度的同场景证据。前期降低渲染成本的做法缩减了实时视觉，结果见 [开发记录](../releases/2.0.8-development.md)。

校园卡、电量、今日课表、待办分别在系统桌面小组件列表增加「玻璃版」。原组件保留 Provider、布局、动作与已保存外观。用户手机试用时指出玻璃版底色过实，顶边高光超出圆角。独立玻璃版及预览改用半透明圆角渐变与细描边，让壁纸底纹透出并呈现静态磨砂质感。新版为磨砂背景单独调整次要文字与状态色。实际通透程度随 Launcher 和壁纸变化。玻璃版与原组件共用数据和刷新。选座布局及相关验收范围照原计划执行。外观参考见 [Issue #6](https://github.com/dlam12138/UPCPocket/issues/6)。

后续试装确认，加入弧形反光的固定磨砂候选与 Issue #6 的参考效果仍有差距。桌面小组件玻璃质感的改进转入长期计划。 [长期计划](long-term-plan.md#桌面小组件玻璃质感)

## 全部桌面组件：前期实施路径

### 外观范围与候选

建议首发在现有“设置 → 桌面组件”提供**全局外观**，同步影响所有已添加的校园卡、电量、课表及未来待办实例。默认保持近实底；可选通透度与静态玻璃质感。用户已认可01/03/05的视觉方向，具体档位、配色和高光强度在局部样式验证中确定，不能把应用内折射直接承诺给桌面。每实例单独配置作为后续选项，尚未承诺本轮加入。

| 方向 | 现有 RemoteViews 的可落地部分 | 取舍 |
| --- | --- | --- |
| 通透 | 半透明或无底色、明确字色、必要文字衬底/阴影、统一圆角和留白 | 最接近真实 AppWidget 参考；复杂壁纸上须增加衬底或切回默认 |
| 静态玻璃质感 | 渐变、轻量静态高光和层次，文字保持清晰 | 可以借鉴应用内玻璃外观，但不能称为壁纸实时模糊或折射；描边需防止与 Launcher 裁切叠出双层边框 |
| 动态折射/壁纸模糊 | 当前架构下没有可直接移植并保证跨 Launcher 的公开方案 | 社区演示主要用于 App 内；本轮作为效果参考，不承诺把 Shader 库直接嵌入桌面 |

用户本轮要求授权调研可选玻璃风格；app 局部指令及 M5 的近实底、无玻璃/描边仍是当前默认与已发布事实。本轮不改这些历史/默认规则，不把候选风格写成已经实现。完整项目比较与平台一手来源见 [Android 玻璃效果调研](../research/2026-11-17-android-glass-projects.md)。

### 模块、偏好与渲染

| 位置 | 拟改动及边界 |
| --- | --- |
| [widget_surface.xml](../../core/designsystem/src/main/res/drawable/widget_surface.xml)、[WidgetRenderSupport.kt](../../core/designsystem/src/main/kotlin/com/upcpocket/app/designsystem/WidgetRenderSupport.kt) | 承担共用背景和配色描述；有限预设可用 shape/layer-list，不生成大尺寸位图。core 只认识通用外观，不认识 `WidgetKind`、具体 feature 或账号 |

| 业务 renderer | 校园卡、电量、课表及待办复用外观描述，覆盖正常、未设置、尚未恢复、未同步、加载、失败和清理中等全部分支；保留各自业务状态含义与点击 |
| [WidgetUpdates.kt](../../app/src/main/java/com/upcpocket/app/widget/WidgetUpdates.kt) | 保存外观只本地重绘所有存在实例，保留校园卡发布门闩和账号代次，不触发校园网络、不重建周期、不绕过既有发布入口 |
| [BaseWidgetProvider.kt](../../app/src/main/java/com/upcpocket/app/widget/BaseWidgetProvider.kt) | 当前未提供配置 Activity 或实例恢复映射；若以后做每实例外观，需另外处理 widget ID 删除/恢复及偏好迁移。全局方案无须先引入这些状态 |

外观长期偏好不能放在 `WidgetStateStore`：后者用于刷新反馈，会在最后一个实例删除后被清除。偏好也不混入余额、房间、课表等业务快照。

透明度只调整背景，不对整个组件 `setAlpha`，防止文字、错误状态和点击反馈一起变淡。文字配色需盘点 XML 与运行时全部字段：标题、单位、过渡余额、日期、次课、状态和图标不能各自遗留旧颜色。元数据目前可用资源色由 Launcher 根据深浅模式解析；不要全部替换为 App 进程预先计算的固定颜色，从而丢失宿主主题适配。实际语义色与需要运行时指定的文字色应分别核对。

保持当前刷新与导航规则：课表/校园卡无刷新图标、整卡导航保留，电量仍保留手动刷新；待办完成、新建和正文点击按 [待办组件方案](2.0.8-todo-widget.md) 分开。样式变化不能恢复已删除热区、弱化错误或增加课程通知。

### 平台与依赖边界

当前桌面使用 XML RemoteViews，不能直接装入任意 Compose、自定义 Shader View、GLSurfaceView 或 BlurView；在本机先画成位图也只会得到已取得背景的静态结果，无法自动取得 Launcher 背后实时内容。[RemoteViews 官方文档](https://developer.android.com/reference/android/widget/RemoteViews)

壁纸普通读取在 Android 13 起受限，Android 14 起 `getDrawable()` 对普通应用会抛 `SecurityException`。窗口模糊作用于自己的 Window，且受 GPU/省电状态影响；第三方组件提供者不能据此控制任意 Launcher 的窗口。此次外观不新增壁纸读取、广泛存储权限、截图授权或常驻服务。[WallpaperManager](https://developer.android.com/reference/android/app/WallpaperManager#getDrawable())、[AOSP 窗口模糊](https://source.android.com/docs/core/display/window-blurs)

当前 main 为 Kotlin 2.0.21、AGP 8.7.3、Compose BOM 2024.12.01、min31/compile36 与 RemoteViews。#9 提出 Kotlin/Compose/KSP/Room 升级、AGP仍8.7.3，作为本次明确待评估的合入候选；兼容决策、Lint检测器问题和数据升级条件见 [总计划](2.0.8-update-plan.md)。不能因上游演示自动升级，也不能一边承诺原样合入一边要求依赖绝对不变。桌面继续 RemoteViews，不因应用内玻璃迁移 Glance。

## 应用内玻璃风格：前期比较 01 / 03 / 05

App 内可以控制自身背景与前景层，具备实现动态折射的条件。以**01的统一材质为主，结合03的轻边缘透镜、05的高光层次**；用户现已将 #9 的合入工作列入2.0.8计划，优先复用其 Backdrop 1.0.6 / Shapes 1.2.0 及公共控件候选，按下列来源要求审查。03/05保留为必要备选或差异参考，不再平行开发同一引擎。此前“有限自绘、仅作风格参考”的方向已更新；候选尚未在本项目主分支完成编译、设备和页面稳定性验收，不能因此默认重写管线。

### 复用与移植顺序

1. **优先01 Backdrop**：先核对适配现有Compose的发布版本/旧分支。能直接使用时固定依赖版本；需要兼容调整时，优先固定上游提交移植所需Android源码及其必要辅助实现，保留背景记录、坐标变换、shader、缓存与降级的完整依赖关系。避免只摘取shader片段后重新补写原项目已有的管线。
2. **05作为Compose备选，03按差异补充**：若01适配代价不合理，再评估05的可用代码；其许可证元数据冲突先核清。03是View/原生库路线，只有主引擎确有未覆盖效果且接入收益明确时才考虑相关代码或模块，不为三个参考项目各装一套引擎。
3. **项目侧只补连接部分**：通过`core:designsystem`封装上游能力，接入现有主题、背景层、导航胶囊、点击语义、偏好和生命周期；优先沿用上游的模糊/折射/回退策略。只有上游未覆盖且本项目确实需要的适配才新增代码。若仍需大规模改写核心算法，应先记录缺口与取舍，不把新写算法包装成移植。
4. **固定来源并保留归属**：记录仓库、tag/commit、原文件路径、移入文件及本地改动；保留原版权、LICENSE及上游存在的NOTICE，修改部分标明变更。依赖或源码移植都要核对传递依赖和原生ABI，不把上游demo、无关平台/服务和整套主题一起搬入。

复用与许可要求继续适用。main 尚未引入第三方玻璃代码；当前首选审查 #9 已提供的 1.0.6 候选与所提依赖组合，是否采用该升级须通过明确兼容条件。前期找到的01纯Android版1.0.0保留为需要兼容移植时的调查备选，其Kotlin2.2.21/Compose1.9.4仍新于main，且需核对后续绘制修复；不能写成已验证基线。具体提交、文件范围与修复来源见 [移植候选记录](../research/2026-11-17-android-glass-projects.md)。

### 渲染、降级与偏好

- 上游引擎的薄封装与统一材质描述归 `core:designsystem`；宿主连接自己的页面背景和现有主题偏好，业务 feature 不依赖 app 或其他 feature，不把账号/业务实体传进材质系统。保留动态取色、浅深模式、字号及可访问语义。#9已在 [外观页](../../app/src/main/java/com/upcpocket/app/ui/settings/AppearanceScreen.kt) 候选中提供玻璃/Material 3切换，缺键时默认玻璃，须核对老用户升级和偏好恢复；桌面组件仍独立保存、默认近实底。强度等参数为后续精修，不凭概念图认定已验收。
- 真折射要有可采样的应用内背景，素材演示中的丰富底图不等于本项目纯色页面也会呈现同等强度。只对明确背景层做效果，文字、图标与触摸层正常绘制，避免把当前玻璃层再次捕入背景导致递归/重影。不为增强演示新增无意义背景图，也不读取用户壁纸或截取外部应用。
- 建议一个可见页面复用受控背景来源与绘制资源，限制效果面积/层数，避免每张卡片截图、创建 Bitmap 或重新编译 shader。未激活 Pager 页面、离屏内容和后台停止效果更新；动画仅按交互需要运行，不增加永久逐帧循环。优先复用上游已有的资源缓存与绘制逻辑；必要的本地适配按当前Compose能力使用`remember`、按尺寸缓存路径/画刷，并将动态uniform和图形动画尽量留在绘制阶段。[固定性能技能](../../.agents/skills/jetpack-compose-performance/SKILL.md)、[图形绘制](../../.agents/skills/jetpack-compose-performance/references/graphics-performance.md)、[动画](../../.agents/skills/jetpack-compose-performance/references/animation.md)
- Android 13 / API33+可评估应用内 RuntimeShader/AGSL 折射；Android 12 / API31–32先采用透明色层、静态高光及可用的受控模糊，无法可靠渲染时退回清晰近实底。对前景整体调用 blur 不能替代背景采样。完整路径、渲染开销和降级均未在本项目验证。[AGSL官方说明](https://developer.android.com/develop/ui/views/graphics/agsl)
- 01当前源码工具链较新，05要求Kotlin2.2+且许可元数据有冲突；03虽使用Kotlin2.0.21，仍是View/原生库路线，不能据此视为Compose即插即用。优先审查#9的明确版本候选及升级条件，必要时再按上述顺序核对兼容版本与源码移植；背景捕获、shader及已有降级优先复用原实现，兼容性未验证不能当作自行重写的理由。

后续最小验证聚焦导航胶囊、首页卡片/按钮的真实绘制与点击、深浅/大字、正常滚动/Pager切换、API31–32降级和API33+效果；分别记录真机视觉与性能证据，不凭模拟截图、构建或API可用性宣称已稳定。本轮未开始实现或构建。

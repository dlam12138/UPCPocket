## 优先级

P0 表示先解决的功能阻断或发布前提；P1 表示本版本主要交付项；P2 表示在功能和稳定性满足后完成的外观调整。所有项目仍在 2.0.8 目标内，优先级不等于删除需求或承诺上线日期。

| 优先级 | 更新项 | 评估与完成条件 |
| --- | --- | --- |
| **P0** | 页面稳定性、PR 合入与升级兼容 | 涉及五项导航、全局控件、工具链及 Room，影响面最大；须满足下文页面与数据验收条件，不能以作者测试说明、生图或构建成功替代 |
| **P0** | 研究生校园卡适配 | 已知本机格式限制会阻断余额、本人流水及充值入口；先统一完整学号规则和本人核验，保留账号隔离与订单防重，学校真实业务另验 |
| **P0** | #8 的 4×2 课表组件多课程展示修复 | 纠正既有组件显示不足；以实际 dp、字体与可用空间判断展示数量，核对主课、后续课及超出提示，不把所有标称 4×2 都当成同样尺寸 |
| **P1** | **#8 → #9 本地整合** | 保留服务五 Tab、首页固定和 Material 3 图表。应用内玻璃实验及性能结果记入开发记录 |
| **P1** | 待办截止字段与桌面组件 | 先确定 Room/KSP 基线，完成无损 schema 迁移，再接桌面完成、新建、数量、截止与多实例刷新；不将提醒时间当截止 |
| **P1** | 图书馆选座布局 | 解决后段座号滚动问题；列表、地图和概览共用选择，进入房间恢复隐藏偏好，保留原预检和单次提交守卫 |
| **P1** | 官方校历查看 | 公开外链、实现成本较小，可在入口契约明确后先完成；加入 #8 服务目录并支持首页固定，同官方网页目录共用固定校历栏目 |

### #8：服务目录集中，首页保留快捷

按用户本次将 PR 合并纳入计划的要求，以候选中的 **首页 / 课表 / 服务 / 待办 / 专注** 五项导航为实施方向。已发布 main 仍是四项导航；当前架构、根指令及历史 M5 文档不预先写成已经完成五项迁移，实际合入时同步现状与入口映射。

- 服务页提供分类、搜索及官方网页目录；首页保留今日课程、待办、校园卡和可置顶快捷，常用服务旁增加“全部服务”。
- 候选默认固定电费、空闲教室、图书馆、石光。e站通在服务目录，可手动固定；校园卡充值和流水也可固定，首页余额区原入口保留。新增校历应接入同一目录与固定机制，不另建一份首页清单，也不擅自增加第五个默认快捷。
- 合入前处理空图钉集合语义：当前候选在用户取消全部图钉后会显示全部服务。应明确区分“偏好未设置”与“用户主动清空”，并确定清空后的呈现；不能把这段行为当成已修复。
- 核对组件、通知、详情返回及 Pager 的路由，不依赖旧 Tab 下标。插件缺失时入口与页面仍按已有装配规则缺省。
- 图表依据已成功加载的数据表达，保留分页不完整、缓存和失败含义，不将局部流水统计冒充完整账单。

### #9：复用 Kyant，同时评估工具链与默认行为

候选实际依赖 `io.github.kyant0:backdrop:1.0.6`、`shapes:1.2.0`，已有背景记录、模糊、折射及控件连接，优先审查和复用其实现。此前 01 为主、05 备选、03 按差异补充的复用要求保留；不再重复开发另一套相同管线。保留上游版权、许可证、来源提交与本地改动记录。

候选同时把 Kotlin `2.0.21 → 2.3.10`、Compose BOM `2024.12.01 → 2026.02.01`、KSP `2.0.21-1.0.28 → 2.3.6`、Room `2.6.1 → 2.8.5`，AGP 仍为 `8.7.3`。这是 2.0.8 待评估的明确升级候选，不能同时承诺原样合入又绝对要求上述依赖全部不变；当前 main 工具链继续以 [BUILD](../BUILD.md) 为准，不因文档先行修改构建配置。

合入前重点处理：

1. 核对这一版本组合与当前构建、R8、Room/KSP 的兼容性。候选为检测器崩溃全局关闭了 `AutoboxingStateCreation`、`FrequentlyChangingValue`、`NullSafeMutableLiveData`、`RememberInComposition` 四项 Lint；优先解决兼容组合，必要抑制须说明原因、最小范围与恢复条件，不能把关闭检查当稳定性保证。
2. Room 运行库升级与 Todo schema 迁移分开记录。新增 `dueAt` 仍需显式无损迁移；不清库，保留任务、提醒、revision、数据库文件名和 focus 停用表兼容结构，避免多条开发线各写一套 v2。
3. 候选对缺少界面风格偏好的旧用户默认启用玻璃，需核对升级、已有偏好恢复和 Material 3 切换。应用内风格与桌面组件偏好分开，桌面默认近实底不随之改变。
4. 原候选 Dock 采样导航内容，普通卡片/按钮主要采样环境背景。后续用户反馈卡顿后，按 [ADR 005](../adr/005-2.0.8-toolchain-and-widget-state.md) 收敛为环境背景 Dock、静态通透普通卡片及重点控件交互折射；以新候选实测判定改善。API 31–32 简化效果、33+ 折射及无背景时的清晰回退分别核对。
5. 全局控件替换后核对点击语义、禁用/加载状态、输入与滚动、返回及底部安全区；不以“全页面零遗漏”或“零滞后”的作者描述替代实际证据。

## 页面稳定性：发布前的必要条件

以本轮实际改动页面和共享控件的代表页面作定向验证；发现公共问题再扩大到其消费者，不穷举设备矩阵、不做无关压力或破坏性测试。

| 范围 | 验收条件 |
| --- | --- |
| 导航与返回 | 五 Tab 点按/滑动后 Pager、底栏和内容一致；详情返回合理；组件/通知打开正确目标，不重复入栈、不误触其他 Tab |
| 状态保留 | 正常页面切换、返回、旋转或进程重建时，按现有归属恢复查询条件、教学周、选座/时段、滚动与可恢复编辑状态；不因重组或主题切换清空已保存内容，不把密码放进可恢复状态 |
| 异步与错误 | 加载、取消、失败、缓存、未查询和有效空结果分别表达；旧请求不覆盖新选择或新账号；单次动作和未知订单/预约结果守卫保留，不因重绘重复请求或提交 |
| 滚动、点击与输入 | 正常滚动/Pager/玻璃拖动手势不互相抢占；底栏、键盘和安全区不挡操作；正文、复选框、按钮及禁用/加载态的点击语义保持，文字和状态色清晰 |
| 视觉回退 | 深浅色、常用大字与常见窗口尺寸可读；Material 3 与玻璃切换不丢页面状态；简化平台/缺背景时清晰回退，不发生持续闪烁、重影或不可操作页面 |
| 数据与资源 | 旧数据升级保留任务与提醒等本机内容；前后台、页面离屏和普通重建时资源按生命周期释放，不新增永久逐帧循环、壁纸权限或常驻服务 |

后续代码阶段选择受影响模块的定向测试、模块边界/Lint、必要构建及保留数据的 Release 安装冒烟；页面至少覆盖首页/服务、一个密集列表、一个输入/确认流程和各自新增功能。玻璃两种平台路径按实际可用设备验证，缺少设备或真实研究生凭据时明确记为未验证。任何真实 CAS 验收仍使用已授权本人账密；页面只读走查不授权下单、付款或预约提交。

## 建议实施顺序与依赖

1. 先处理研究生校园卡格式与本人核验；同时对 #8/#9 候选做静态审查和最小兼容准备，记录上述页面稳定性条件。
2. 以 #8 确定五 Tab、服务目录和首页固定契约，核对 4×2 课表修复与导航；完成对应定向验收后再合入。
3. 确认 #9 的依赖基线、Lint 兼容处理和旧数据策略，再合入其玻璃增量；先验证共享控件与代表页面。技术可行性应尽早确认，精修参数放后。
4. 在确定的 Room/KSP 基线上完成待办截止迁移与组件；选座布局和校历可按互不写同一文件的模块并行准备，最终 UI 接到合入后的公共控件和入口。
5. 四类桌面组件统一外观，完成应用内材质精修和最终页面稳定性复核。若 #9 的兼容问题未解决，先保留可审查记录，不以取消检查或绕开旧数据兼容强行推进。

同一模块只维护一份状态、迁移与业务实现。App 内实时玻璃和 RemoteViews 静态材质分别实现、分别验收，共用色调与圆角方向，不复用不适用的渲染容器。

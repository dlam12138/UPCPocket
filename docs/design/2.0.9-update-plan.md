## 首页快速下拉异常回弹

**首页已关闭边界拉伸。** 首页沿用同一个纵向滚动状态，只关闭这个滚动容器的边界效果，快速下拉后的反向手势可以继续推动内容。 [首页滚动容器](../../app/src/main/java/com/upcpocket/app/ui/home/HomeScreen.kt#L148)

在离线 API 36 模拟器上以约 363dp 宽、1.15× 字体复测。正式版 2.0.8 在一次快速下拉、立即反向上滑的组合里停在顶部，另一次顺利离顶。包含首页修复的 Debug 构建能离顶继续浏览，也可横滑进入课表，再从底栏回到首页原位置。反馈手机的手势起点和复现条件仍待确认。

**RC2 续修。** RC1 在 320dp 的 API 36 模拟器上仍会拦住从底栏旁留白起手的滑动。在首页顶部，先向右再向下的手势也会触发一级页的横向拉伸。RC2 将底栏命中区域收至胶囊矩形内，并关闭外层 Pager 的边界拉伸。长签名 Release 覆盖安装后，留白起手可滚动，录屏中未再出现该横向拉伸。触顶后立即反向上滑、横滑进入课表及点底栏回到首页原位置均通过。 [宿主导航](../../app/src/main/java/com/upcpocket/app/ui/nav/AppNav.kt#L330)

首页的「今日课程」在后台重读同日、同账号的缓存时继续显示已有课程，读完后更新。玻璃底栏的静态底板使用半透明主题色和高光，水滴交互时采样主题渐变和导航图标，同时保留速度拉伸与弹簧回弹。

### 底栏样例与采用条件

**2026-11-19 状态。** 实时玻璃已作为可选外观合入开发代码，偏好由 `app_ui_style` 保存，默认 Material 3；光学底栏仅用于 API 33 及以上，API 31–32 回退 Material 3。以下条目与帧数据是合入前的提案和旧样本，不代表合入后的真机测试结果，真机性能、视觉与交互仍待验证。

1. 以回滚前的 Kyant 观感和 Apple 材质为参考，先在现有主题里试一个底栏，正文滚过时有实时折射，胶囊按压和拖动有高光及跟手形变。检查深浅色文字和图标、滑页与点击、返回及键盘避让。首选把采样限制在底栏所需区域，再测背景复用及等效滤镜合并。缓存绘图对象只减少对象开销，变化的背景仍需处理。Haze 和 Kyant #126 的样例用于选择实验方向。后者测试的是 Backdrop 2.0.1 catalog，项目旧候选用 1.0.6，收益需由本项目验证。 [旧候选依赖](../research/2026-11-17-2.0.8-dependency-provenance.md) · [Apple 材质设计](https://developer.apple.com/videos/play/wwdc2025/219/) · [Haze 基准](https://chrisbanes.github.io/haze/2.1.0/benchmark-results/) · [Kyant 滤镜对照](https://github.com/Kyant0/AndroidLiquidGlass/issues/126)
2. 保持当前 `compileSdk 36` / `minSdk 31` 的范围。已核对社区 `liquidglass-material3-android:1.0.0` 的 AAR 元数据为 `minCompileSdk=37`。若样例使用 `RuntimeShader` 折射，API 31–32 使用 Material 3 底栏。四类桌面小组件继续由原有 Provider 和静态 RemoteViews 渲染。 [构建基线](../BUILD.md#环境) · [社区 Material 3 适配](https://github.com/shayann07/liquidglass/blob/v1.0.0/docs/material3.md) · [Maven Android 制品](https://repo.maven.apache.org/maven2/dev/shayxo/liquidglass/liquidglass-material3-android/1.0.0/liquidglass-material3-android-1.0.0.aar) · [RuntimeShader](https://developer.android.com/reference/android/graphics/RuntimeShader) · [桌面组件决定](../adr/006-2.0.8-material-theme-and-glass-widgets.md#决策)
3. 优先用反馈卡顿的 Android 真机，固定刷新率、内容与手势脚本，交替测三组配对的 Release 优化构建。A 为现有 Material 3，B 只更换底栏材质。场景取服务目录滚动和 Tab 点击/滑动，另目检胶囊按压和拖动。用离线内置内容，记录设备、系统、刷新率、构建与每组帧数。分别记录 `frameOverrunMs` P95 和逐帧 `frameOverrunMs > 0` 的比例。比较两种玻璃实现时保持相同视觉要求。 [AndroidX 帧指标](https://developer.android.com/reference/androidx/benchmark/macro/FrameTimingMetric)
4. 本轮提出的初始试验门槛为各场景 B 相对 A 的 P95 升幅至多 1 ms，超时帧占比升幅至多 1 个百分点，取三组配对差值的中位数。轮次和数值作为建议，随基线重复测量的波动复核。两项同时满足，且实时效果、可读性与交互目检通过，再考虑仅采用底栏样例。某个场景未达标，或样本波动大到无法判断时，以 Material 3 交付，先分析这一场景的帧追踪。

底栏样例在开发阶段可独立撤回。若采用后已向用户分发，后续通过更高 `versionCode` 的同签名修正版恢复 Material 3。 [升级身份与签名](../adr/004-release-identity-and-update-trust.md#决策)

本轮核对了正式版源码、历史帧统计原件、上游制品与指标文档。新底栏已合入可选外观，其真机帧数据、API 31–32 回退表现与视觉验收仍待验证。

## 课表周网格半宽与课名截断

**已按实际重叠时段分栏。** 2.0.8 用当天的最大并排数计算所有课卡的宽度，所以一处节次重叠会压窄当天其他时段。现在独立课程占所在日列的可用宽度，共用节次的课程按相连的一组分栏。 [周网格分栏](../../feature/timetable/src/main/kotlin/com/upcpocket/app/timetable/TimetableScreen.kt#L1514) · [课卡宽度与文字](../../feature/timetable/src/main/kotlin/com/upcpocket/app/timetable/TimetableScreen.kt#L1031)

反馈设备的诊断摘要显示窗口宽 363dp、字体缩放 1.15。按 2.0.8 的网格尺寸估算，半宽卡片只剩约 18dp 可排文字。旧版按整列宽度计算课名行数，在这里限一行并省略溢出内容，所以卡片可能只剩省略号。报告记录六次非空周数据解析并写缓存成功。课程名在协议解析时必填，完整名称可在卡片详情中查看。重叠条目是否来自重复记录仍待确认，诊断里只有查询阶段和条目数量等汇总信息。 [周网格尺寸](../../feature/timetable/src/main/kotlin/com/upcpocket/app/timetable/TimetableScreen.kt#L821) · [课名解析](../../feature/timetable/src/main/kotlin/com/upcpocket/app/timetable/TimetableProtocol.kt#L283) · [诊断字段](../PRIVACY.md#本机诊断报告202-起)

课卡高度沿用课程跨越的节数。空间足够时，课程名、时间和地点从上到下分三个等高区域，各自在区域内水平和垂直居中。课程名用 9sp，时间和地点用 8sp。课程名和地点各最多两行，已知的开始和结束时间各占一行。 [课卡尺寸与字号](../../feature/timetable/src/main/kotlin/com/upcpocket/app/timetable/TimetableScreen.kt#L1031)

常规字号下，两节课卡高 86dp，单节课卡高 42dp。单节课和过窄课卡优先展示最多两行课名，卡宽不足 24dp 时课名用 7sp。点按各自的卡片可查看完整课程名、时间和地点。紧凑字号仍待在反馈手机上确认可读性。 [课表布局回归](../../feature/timetable/src/test/kotlin/com/upcpocket/app/timetable/TimetableWeekLayoutTest.kt#L279)

## 图书馆选择「现在」后无法确认预约

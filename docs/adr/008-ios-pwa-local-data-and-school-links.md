# ADR 008 · iOS PWA 静态部署与数据归属

- 状态为 Accepted
- 记录于 2026-11-19；2026-11-23 按独立静态版整合，移除站内登录、站内预约与服务端接口。
- 依据为桌面《UPC Pocket · iOS 网页版开发计划与设计指南》、[官方入口](../upc/官方入口.md)、[ADR 002](002-account-generation-and-business-sessions.md)与 [ADR 003](003-data-ownership-and-schema-compatibility.md)

## 背景

首版要能从 iPhone 主屏幕打开，离线处理待办并恢复专注计时。现有学校课表可在官方网页使用，站内展示需要校方支持第三方 Web 接入及本人只读数据。

## 决策

- 将 [`web/`](../../web/) 作为独立静态应用，使用相对资源路径和哈希导航。Service Worker 按部署范围和版本缓存允许列表中的静态资源；部署不需要本项目自建的账号服务、数据库或 `/api/*` 接口。
- 待办、活动专注和专注历史保存在 IndexedDB。到点或提前结束时，在同一读写事务内按会话 ID 生成历史并清除活动状态。静态缓存升级与本机数据升级分别处理。
- 用户主动点击后，通过顶层导航进入官方学校页面。校方负责认证、会话和个人页面；图书馆、空闲教室、学校校历和 e站通只提供固定官方入口，站内不收集学校账号密码，也不保存 Cookie、Ticket 或预约记录。
- 学期课表的导入、存储与 `.ics` 预览另见 [ADR 009](009-web-semester-timetable-import.md)。

## 备选

- 站内登录与站内图书预约：需要学校书面授权和可访问学校上游的部署网络，且会引入站内会话、加密与运维边界。本版不采用，相关代码与记录不进入静态站点。
- 站内代理公开查询：需要同源后端进程。本版不采用，公开信息直接交给学校官方页面。

## 取舍与影响

静态部署让首版的本机功能无需维护账号服务或网络数据库。当前站点来源、安装环境和部署路径会影响记录及应用身份，故使用稳定的 HTTPS 地址；跨设备同步需要另行设计。学校页面承担登录与业务操作，本站无法控制校方保存的数据或保证服务持续可用。服务端集成适用于校方明确提供并授权这类接入的情形，届时另行决议维护与隐私边界。

[开发与验证记录](../web.md)区分静态预览、浏览器、模拟器、真机及学校业务证据。

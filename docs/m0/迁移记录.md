### 复核修正：故障隔离与 focus 可移除

1. `PluginRuntime.start()` 不再返回全局 Invalid。每个插件按确定顺序单独校验、创建、
   核对能力并原子提交；工厂异常、缺必需依赖、宿主 API 不兼容、依赖环、重复能力只
   停用该插件及所有传递必需依赖它的插件，独立插件继续启动。
2. 新增固定诊断码 `DEPENDENCY_DISABLED`；现有码保持稳定。诊断只含插件/能力 ID 和
   固定说明，工厂异常原文不会进入结果或日志。
3. dev/release 策略：`PluginStartupPolicy` 在 `BuildConfig.DEBUG` 且存在失败时直接
   fail-fast；release 记录 `plugin:CODE:ID` / `ui:CODE:ID` 的脱敏摘要后使用健康插件。
4. UI 贡献按插件 fork 暂存，整份通过才原子合并；贡献抛异常、入口/页面 ID 越界或与
   已接受贡献冲突时只丢弃该插件整份 UI，不残留半套入口，也不阻塞后续插件。
5. 专注顶部 tab 改为 `PluginBottomNav("focus.tab", order=10, route=focus)`；
   `AppNav` 只固定首页(order=0)/更多(order=100)，中间 tab 全来自已激活插件。
   宿主不再 import `FocusScreen`、`FocusService` 或 `FOCUS_STATS_ROUTE`。
6. 新增 `PluginAppLifecycle`：只有成功激活的插件会收到 `onAppCreated`/`onAppStart`。
   专注的通知通道与计时恢复由 `FocusPlugin` 自己实现；无 focus 时宿主不调用它们。
7. `PomodoroService`、通知权限、前台服务权限已移入 `feature:focus` 的 manifest；
   移除模块时系统入口一起消失。运行期未激活时，legacy Service 入口仍返回
   `START_NOT_STICKY` 并停止，不借缺能力初始化数据库。
8. `AppGraph` 的 card/power 组件能力改为可空读取；Provider 缺插件时渲染空态，
   Worker 显式记录“功能未启用”，不再从能力 getter 抛错。电量组件旧入口在页面
   未注册时安全回首页。

新增边界测试：创建失败 + 独立健康插件、传递必需依赖、缺失/失败的可选依赖、依赖环
与独立插件、宿主 API 不兼容、重复能力、声明/提供不一致、UI 贡献异常/ID 越界/冲突、
固定诊断码、开发 fail-fast/发行降级、无 focus 装配、legacy Service 不可用。

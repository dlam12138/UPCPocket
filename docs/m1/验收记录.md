测试覆盖的失败路径（使用 fake crypto 与可注入 `AccountFileStore`，不是真实设备注入）：

- 首次保存、加密后重启恢复、同账号更新代次、换号清理范围与旧 token 失效；
- 加密失败、pending 写失败、journal 写失败、过渡状态写失败均保留旧正式密文；
- journal 写入后模拟进程中断，重启继续提升新版本；
- 删除清理失败持久化 `REMOVING`，重启后继续；
- 密钥不可读/密文损坏/版本不支持进入 `NEEDS_RECONFIGURATION`，旧个人数据清理后可重新保存；
- 密码输入不进入状态、密文文件不含明文；同账号更新与换号的不同失效范围；
- Compose 页面保存成功显示“已保存，尚未验证”、失败显示固定错误、密码字段清空、
  `StateRestorationTester` 恢复后密码为空、`FLAG_SECURE` 已设置。

## 3. 真实本机凭据的 Keystore 集成测试

本机来源项目已有 Windows DPAPI 统一凭据。按用户本轮授权：

- 只读定位来源项目 `auto-auth` 凭据与元数据，校验账户哈希；没有写入、清空、重绑来源项目；
- 使用来源项目自己的 Python/`win32crypt` 在宿主机进程内解密，仅取当前学校账号一组；
- 通过 `adb shell run-as ... sh -c 'cat > files/...'` 的标准输入写入应用私有临时文件，
  不把密码放进命令行参数、Gradle `-P`、Intent、通知、日志或共享仓库文件；
- 在模拟器运行 `RealKeystoreAccountTest`，只输出测试通过/失败，不输出账号或密码；
- 测试结束删除临时文件、隔离账号目录并卸载测试 APK；来源凭据文件长度与修改时间未变化。

结果：**通过 1 test，0 failure**。实际覆盖：

1. 真实 Android Keystore 生成独立 alias 密钥并以 AES-GCM 保存；
2. 新建仓库实例仅从磁盘密文与真实 Keystore 恢复，状态为 `SAVED_UNVERIFIED`；
3. 同一真实账号再次保存，代次从 1 增至 2，密文变化；
4. 密文文件中不出现真实账号或密码的 UTF-8 明文；
5. 删除后正式密文不存在，状态为 `NOT_CONFIGURED`。

未联网、未调用 CAS、未读取课表/余额/图书馆业务数据，也未进行预约、报名、签到或其他写操作。
真实凭据没有进入本次对话、文档、截图、日志或仓库；本记录不保留任何账号片段。

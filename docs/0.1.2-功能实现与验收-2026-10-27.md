# 0.1.2-preview 功能实现与验收（2026-10-27）

本文件记录本轮在 `upcm1-local-prototype` 上的实际改动、验证结果、未完成项和缺失材料。总体计划书原文未改；`E:\UPCpocket` 的 main 未合并。

## 本轮完成

### 1. 课表 1–13 节与 CSV 批量导入

- 默认作息由 10 节扩到 13 节（第 11–13 节 21:00–23:50，可编辑）。
- 已有安装启动时只补缺失的 11–13 节，不覆盖用户改过的时间；Room 真实测试覆盖该补种。
- 课表网格、节次列、跨节次块、手工添加/编辑、课程详情、今天页、桌面组件均按实际最大节次工作；背景裁剪参考线同步 13 节。
- CSV 解析新增：
  - 表头别名：课程/教学班、星期/周几、周次/教学周/起止周、节次/上课节次、上课时间/排课时间等；
  - `1-16(单)`、`1-8单,10-16双`、`1,3,5` 等周次与逐片段单双周；
  - `1-2,3-4；5-6` 多时段单元格拆成多条；
  - `星期一第1-2节` 单列“上课时间”；
  - 1–13 节；超出当前作息明确报错，不静默丢弃；
  - 空白周次报错，不推断整学期。
- 导入继续使用 SAF 文件选择、预览、整批校验、Room 事务写入、稳定标识去重；新增“从剪贴板导入”。
- 新增登录后主动导出工具：`tools/upc-schedule-export.user.js`。脚本在已登录课表页逐周读取选定学期，任何一周失败即停止，生成 CSV 并尝试复制到剪贴板；App 复用导入预览。

**适配范围**：脚本端点与字段来自学校课表页公开前端代码（`/timetable/wap/default/get-index`、`get-datatmp`，`d.classes` 的 `course_name/teacher/location/lessArr`），但尚未在真实登录账号上端到端验证，也未取得真实导出表头/DOM。不能把模板和单元测试说成 UPC 实际格式已通过。

### 2. 空闲教室

保留并实测上一轮的原生公开查询：校区、日期、教学楼、1–13 节多选；结果只列所选节次均未占用的教室；有查询时间、失败/空目录区分，不提供预约。2026-10-27 模拟器实测唐岛湾 2026-10-27 第 1、2 节返回“可用 110 间 / 共 216 间”。

### 3. 图书馆座位（原生数据层 + 官方 CAS 登录）

- 新增 `data/library/`：馆区/日期/楼层/房间/座位布局/开始结束时间/预约/我的预约/取消的独立数据层。
- 请求签名按学校页面公开前端实现：`X-request-id`、`X-request-date`、HMAC-SHA256(`seat::uuid::timestamp::METHOD`)，并带 `Authorization`/`loginType`。公开配置密钥用 AES 解出，单元测试固定了 Node 计算的 HMAC 向量。
- 登录只使用学校官方 CAS 网页（应用内 WebView，仅登录步骤）；登录成功后读取页面自己的 seat token，立即关闭并清理 WebView Cookie。token 只保存在内存，退出/进程结束即清除，不写数据库/文件/日志。
- 功能界面为原生：选馆区/日期 → 查房间 → 看座位图 → 选可用座位 → 选起止时间 → 二次确认提交 → 刷新“我的预约” → 取消。无自动抢座、后台轮询。
- 学校启用图形验证码时，原生提交会明确提示并停止（`isCaptchaOpen`），不伪造预约成功。
- 未登录只显示登录引导，不显示可点击的空壳预约按钮。
- 实际接口核验：`/rest/v2/settings` 匿名返回 `isCaptchaOpen:false`；带无效 token 的签名请求返回 `{"status":"fail","code":"12"}`，已按登录失效处理。

**未完成验证**：没有用户本人的图书馆账号，未实际完成 CAS 登录后的馆区/座位/预约/取消全链路。模拟器只验证到 CAS 登录页正常加载（WebView target 标题 `CAS Login`），未提交账号。真实预约必须由用户本人在有账号、校园网/可访问网络的真机上验收。

### 4. 微信 SDK 适配

- 新增腾讯开放平台 SDK 6.8.40 依赖和 `data/wechat/WeChatDirect.kt`，封装 `OpenWebview.Req` 与 `WXLaunchMiniProgram.Req`。
- AppID 从被 gitignore 的 `keystore.properties` 或本机 `~/.gradle/gradle.properties` 读取，构建时写入 `BuildConfig.WECHAT_APP_ID`；没有正式 AppID 时只显示复制/分享兜底，**不发送 SDK 请求**，也不显示“直达”按钮。
- 当前仓库没有正式 AppID，因此微信直达未启用；模拟器弹窗明确显示“尚未配置正式移动应用 AppID”。
- 没有把现有 H5 地址当作小程序标识，没有写死个人认证链接，没有调用私有 Activity/Provider。

**缺失材料**：正式移动应用 AppID、微信开放平台登记的正确包名 `com.upcpocket.app` 与签名、目标 H5 在开放平台的白名单/业务域名确认；若走小程序，还需要学校提供的已发布小程序原始 ID 与页面路径（或官方 URL Link）。

### 5. 电费 / 校园卡

本轮没有开放原生余额入口，原因不是界面未做，而是没有可用的只读数据链：

- 唐岛湾电费 `http://dfcz.upc.edu.cn/ShiYou/Default.aspx` 匿名访问 302 到 `open.weixin.qq.com/connect/oauth2/authorize`，依赖微信 OAuth；普通浏览器/改 UA 不能补齐。
- 校园卡 `http://jhzf.upc.edu.cn:20081/wechat/query/balance.html` 匿名 200 但正文为“无效token”；它需要学校公众号/微信上下文生成的 token。
- 数字石大 `https://i.upc.edu.cn/` 匿名跳学校 CAS；没有本人账号不能取得同业务的普通网页只读接口。
- 因此保留“复制/分享到微信”与学校入口，不显示零余额、不伪造查询结果，也不增加充值/转账。

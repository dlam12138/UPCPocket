# e站通完整只读接入计划

记录日期：2026-11-13。计划实施：2026-11-14。状态：原生只读代码、独立定向测试与审查、签名 R8 候选及包审计已完成；最终 Release 安装与公开页面/无账号/进程/课表组件冒烟已完成，真实本人 CAS/受保护数据待授权实测，尚未发布。

用户已决定将 UPC-MCP 的 e站通现有功能完整接入 UPC Pocket，本晚保存计划，明日实施。本期覆盖事项搜索、办事指南、本人待处理、本人在办申请及可用进度，并接入统一账号 CAS 认证、会话恢复和清理。页面以首页服务入口进入，保留现有四个底部 tab。

## 功能范围

“完整接入”按上游 e站通四项工具及其配套会话行为对齐，包含登录后当前账号可见的目录和个人队列。

| 上游工具 | Android 接入内容 | 必须保留的语义 |
| --- | --- | --- |
| `upc_service_search` | 事项列表、关键词搜索、分页、名称、部门和访问类型 | 优先读取当前账号可见目录，再本地匹配名称和部门；没有可用登录会话时可退回公开目录并明确提示范围。文件夹不作为事项，文件夹与事项可能共用 ID，重复事项行不能简单按 ID 去重。 |
| `upc_service_guide` | 原生指南详情，展示已有的说明、材料、地点、时间、费用、入口及类型信息 | 复用当前账号会话；仅认证类失败可回退公开指南，网络或解析错误不能伪装为公开空结果。缺失材料、截断内容和未知字段如实表示；指南不证明已申请或可申请。 |
| `upc_service_my_todos` | 当前账号待本人处理的任务列表、标题、状态、当前节点、创建时间及第三方标记，支持分页 | 固定 `status=1`；保留总数、本页完整性、是否还有下一页和范围完整性。合法空列表不等于认证失败。与现有本机待办保持独立。 |
| `upc_service_my_applications` | 当前账号在办申请列表、事项名称、状态、创建时间、第三方标记及可用进度，支持分页 | 固定 `status=1`；在办可能等待他人处理。只有非空节点和有效整数百分比同时存在时展示已知进度，零保留零，缺值显示未知。 |

关键词沿用上游最多 40 字；页码和每页条数为 1–50，默认每页 20。当前个人列表只覆盖上述状态，不扩展为完整申请历史或消息中心。入口 URL 作为数据处理，不自动打开；第三方事项不因此获得原生办理、详情或进度能力。原始内部实例 ID、票据和私有附件地址不进入页面、日志或诊断。

当前实现的搜索按钮每次重新读取完整目录后再本地匹配；翻页复用同账号的内存目录。更换关键词失败不展示旧查询结果，同查询刷新失败可保留结果并明确提示；进程重建不恢复该目录。

配套行为包括登录、检查业务会话、明确失效后的有限恢复、退出/清理，以及换号、改密、删除账号时同步失效。上游没有申请提交、审批、撤回、表单或附件操作，本期也不引入这些能力；不移植 Python MCP 服务、Windows DPAPI、桌面设置页或 CLI。

## CAS 认证与账号绑定

e站通已经使用学校 CAS，复用现有统一账号和 `core/upc-auth` 公共登录逻辑，新增 e站通专属适配。上游认证链为：学校统一账号或已绑定的 CAS SSO → e站通专属单次票据 → 业务 Cookie → 会话检查 → 目录及个人查询。

固定业务主机为 `https://service.upc.edu.cn`。CAS service 的解码值为：

```text
https://service.upc.edu.cn/site/login/cas-login?redirect_url=https%3A%2F%2Fservice.upc.edu.cn%2Fv2%2Fsite%2Findex
```

回调路径、`redirect_url` 和单次 ticket 逐项核对，不能只按域名放行，也不套用石光的 HTTP service 规则。账号密码只经受控凭据接口交给认证层，业务模块不直接读取密码。

**受控 CAS 认证成功、业务会话有效且明确绑定当前账号和凭据代次，可作为本期个人查询的身份依据。** 上游 `identity_verified=False` 仅表示未额外读取业务学号等字段做交叉核对，不能据此把已成功的 CAS 认证视为失败；另找独立身份接口不是开工前置条件。若接口自然提供可靠身份字段，可补充交叉核对并在明确不符时拒绝采用会话。

SSO 只能复用来源明确、属于当前账号和凭据代次的会话；来源不明的浏览器 Cookie 不可直接绑定到当前账号。账号保存状态仍遵守“已保存，尚未验证”的现有文案，保存动作不代表已登录。验证码或二次验证停止自动密码提交并返回 `INTERACTION_REQUIRED`。目前公共 CAS 挑战只提供状态和 URL，没有可继续且能证明账号归属的挑战上下文；e站通上游也没有可交叉核对的账号字段，公开 CAS 页面本身不能证明登录身份。因此本期不采纳网页登录 Cookie，只有未来挑战流程能提供可验证的来源和本人归属时再评估恢复原生会话。

## 固定只读接口

以下为固定参考提交中的实现契约，业务读取均为 GET；CAS 密码登录的认证 POST 与业务写操作分别处理。

| 路径 | 用途与参数 |
| --- | --- |
| `/api/apps/list` | 读取当前来源、当前身份可见的完整目录，再本地筛选分页；作为主要搜索来源。 |
| `/api/apps/service-list` | 上游保留的分页搜索方法，参数 `p`、`page_size`、可选 `keyword`；不替代完整目录主路径。 |
| `/api/apps/detail` | 指南，参数 `id`、`userview=1`。 |
| `/site/my-task/todo` | 本人待处理，参数 `p`、`page_size`、`status=1`。 |
| `/site/process/inst-list` | 本人在办，参数 `p`、`page_size`、`status=1`。 |
| `/site/message/count` | 业务会话检查；消息计数不充当待办总数，也不单独证明本人身份。 |

模型保留 `total`、`has_more`、`complete_for_page`、`complete_for_scope` 及公开/登录目录范围；页面使用简短文案表达。登录目录完整只指当前账号可见范围。上游 196/386 项为历史样本，不硬编码当前总数。响应大小、文本长度、超时和重定向继续有界，响应结构变化显示错误，不转换为空列表；指南按原生文本展示并过滤脚本。

首期会话和查询结果只保存在内存，避免个人数据落盘与迁移。账号/凭据代次、业务 epoch 和查询选择版本共同阻止迟到结果；公开回退不能把上一账号的目录、指南或个人列表带回来。保留同一账号、同一查询归属的已有结果时，明确显示刷新失败；切换归属立即清除旧结果。

构造插件和应用启动不触发认证或业务查询；进页和用户动作触发有界请求。认证互斥，忙碌操作不重复排队提交密码；一次操作遇明确会话失效最多恢复一次并重试一次，网络超时不当成密码错误或空结果。不增加后台轮询、Worker 或组件。

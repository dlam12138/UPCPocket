# 校园系统机制探索方法

适用对象：UPC Pocket 的中国石油大学（华东）接入研究。方法提炼自郑大参考项目，学校事实必须重新验证。

## 探索顺序

1. **建立官方入口台账。** 从用户提供的官方链接和学校公开导航出发，记录服务、校区、域名、页面路径和来源。第三方仓库单列，不能当作校方依据。
2. **拆解跳转链。** 区分导航首页、移动页、业务页、统一认证、微信 OAuth、iframe 与接口。先匿名访问无临时参数的入口，观察状态码、标题与跳转；原始链接里的 code、token、ticket 不作为固定配置。
3. **识别独立会话。** 沿正常登录流程确认各系统的 Cookie、票据或 Token。分别验证系统浏览器、WebView 和微信的会话承接；统一认证成功不等于所有业务已经登录。
4. **从真实页面确认数据契约。** 优先观察业务页实际请求，结合公开前端代码和第三方实现寻找线索。区分字段名称、请求方法、参数、错误响应、刷新方式和会话失效。代码中存在的接口只是候选。
5. **核对业务语义。** 课表检查学期、教学周、单双周、节次与整学期范围；余额检查金额单位、账户类型、更新时间；电费分别确认校区与房间标识；座位检查馆区、时段、预约 ID 和最终状态。
6. **按证据推进原生接入。** 网页负责必要的认证，业务通过独立数据源连接原生页面和本地缓存。保留错误、过期和待确认状态；页面返回 200、构建通过或请求发出均不能替代业务验收。

## 每个结论应记录什么

| 字段 | 要求 |
| --- | --- |
| 学校 / 校区 / 系统 | 明确归属，不能只写“学校接口” |
| 来源 | 官方页面、用户给定链接、当前源码、匿名实测或第三方参考 |
| 入口与跳转 | 保存无个人凭据的地址；动态回调参数留在运行时 |
| 认证与数据 | 分别记录登录、会话、数据请求和业务动作 |
| 验证环境 | 日期、校内外、客户端、是否登录；不能把一次失败推断为永久不可用 |
| 证据状态 | 用户提供 / 匿名入口可达 / 登录已验证 / 数据已验证 / 业务已验收 |
| 待办 | 下一项能消除不确定性的具体检查 |

## 郑大案例能迁移什么

| 郑大探索经验 | UPC 应执行的验证 |
| --- | --- |
| CAS、教务、一卡通、图书馆各有会话 | 逐个确认 UPC 系统自己的认证链，不能复制郑大请求头与令牌交换 |
| 本科与研究生系统独立 | 先确认 UPC 是否有同样拆分，不能假定存在相同系统 |
| 页面可以负责登录、原生层负责数据 | 验证 UPC 的会话承接和真实数据协议 |
| 电费房间号、双表计和金额字段有专用规则 | 按 UPC 校区重新建立规则；郑大的前导 8 等算法不能迁移 |
| 前期访问失败后来发现是协议或页面条件问题 | 记录网络、证书、HTTP/HTTPS、UA 和跳转，保留不确定结论 |
| 文档早期结论被后续实测修正 | 标记日期与勘误，当前证据覆盖历史假设 |

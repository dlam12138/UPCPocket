## 3. 改造后的身份与边界

### 3.1 应用标识

```
applicationId  com.upcpocket.app
namespace      com.upcpocket.app
versionCode    1
versionName    0.1.0-m1
```

> **为什么版本号回到 1**：这是**另一个应用**。上游的 `com.zzupocket.app` 不会被覆盖安装，
> 上游的数据库、令牌、DataStore 也不会被本应用读到。两者数据语义不同，迁移没有意义。
> 数据库也因此从 `version = 1` 重新开始，不保留上游 v1–v10 的迁移链。

### 3.2 网络边界（最强的保证不是开关，是"代码不存在"）

- `AndroidManifest.xml` 里**没有 `INTERNET` 权限**。即使将来有人误加一个网络调用，它也发不出去。
- 构建脚本里**没有 OkHttp、WorkManager、security-crypto**。
- `AppGraph` 只暴露：数据库、两个偏好存储、课表仓库、专注仓库、番茄钟引擎与通知。
  容器里**拿不到任何能发校园请求的对象**。
- 唯一与外部世界接触的地方是「校园服务」页发出的隐式 `ACTION_VIEW` Intent ——
  由系统浏览器联网，App 全程不参与。

### 3.3 保留的上游资产

| 保留项 | 说明 |
| --- | --- |
| MIT 许可证 | 根目录 `LICENSE` 原样保留 |
| 上游致谢 | `AboutScreen` 与 README 均保留 `3beuml/ZZUPocket`（MIT）与拾光课程表（Apache-2.0，仅版式参考） |
| 课表网格 / 周翻页 / 课程详情 | 保留（渲染逻辑与视觉一致） |
| 自定义日程编辑器 | 保留（撞课提醒、单双周、颜色） |
| 番茄钟 | 保留（引擎、前台服务、通知、标签、热力图、统计） |
| RemoteViews 小组件 | 保留两个课表组件（下一节课 2×2、今明课表 4×2） |
| 主题系统 | 保留（Material You 动态取色 + 8 套预设） |

## 4. 本地能力的实现要点

### 4.1 数据模型

```
semesters        本地学期（开学日 / 总周数 / 名称）—— 用户可改
periods          节次作息（默认 10 节，可在设置里改时间）
course_sessions  课表格子记录，source 只有 "custom"
courses          手动补录的课程聚合（课程总览用）
display_overrides 课程名 / 教室的本地显示覆盖
focus_tags / focus_sessions  番茄钟
```

**没有任何"同步状态"表**：本应用不存在需要同步的远端。

### 4.2 学期与周次的来源

上游用教务校历；M1 只有两个来源，都在本机：

1. 用户在「课程表设置 → 教学周」里填的开学日 / 当前周次 / 总周数；
2. 首次启动时按"今天所在那一周的周一"生成的默认学期（`LocalDefaults.defaultStartDate`）。

界面上明确标注"本地设置"，不出现"校历已同步"这类暗示。周次换算全部走纯函数
`WeekMath` / `WeekAlignment`（均有单测）。

### 4.3 演示数据（见 §5）

### 4.4 桌面小组件

- 两个组件都只读本地数据：Room 里的自定义日程 +（演示模式下）内存里的演示课。
- 表头/周次行会在演示模式下追加「演示」，避免桌面长期挂着一张不知真假的课表。
- 保存/删除日程、切换演示开关、修改节次时间、修改配色之后都会主动重推组件
  （系统的定时刷新下限是 30 分钟，不能等它）。

## 5. 演示数据模式的设计约束

演示数据是 M1 验收"无需账号即可浏览课表"的前提，也是最容易越界的地方。实现上钉了四条：

1. **隔离** —— 演示课在 `DemoTimetable.sessions()` 里即时生成，**永不写数据库**。
   数据库里只可能存在 `source = "custom"` 的记录。所以关掉演示、或卸载重装，
   用户数据一条都不会被污染；演示课的 id 带 `demo:` 前缀，也不会撞上用户数据的主键。
2. **标识** —— 课名全部以「（演示）」结尾、地点以"演示"开头、教师为"示例教师"；
   课表格子有「演示」角标、今天页表头有「含演示」、课程详情写明"虚构、不可编辑"、
   桌面组件表头有「· 演示」、课程总览单独分组。
3. **不参与真实统计** —— 演示课不给"开始专注"入口（避免虚构课名写进真实专注统计）；
   撞课提醒只比较用户自己的日程，不拿演示课制造"撞课"。
4. **确定** —— 内容固定、无随机数、无时钟依赖；同一教学周每次生成完全一致（有单测）。

默认**开启**演示模式（否则首次安装是空白页），并在今天页首屏、课表页上方都挂了可点击的横幅，
一键直达设置。

## 6. 校园服务导航

数据源：`data/local/CampusServices.kt`（唯一来源，纯常量表，有单测）。
展示：`ui/campus/CampusServicesScreen.kt`。

### 6.1 交互

- 一律 `Intent.ACTION_VIEW` + `CATEGORY_BROWSABLE` 交给系统浏览器；
- **不用 WebView 内嵌**，不代填账号，不做单点登录代理，不读页面内容；
- 未安装浏览器时给 Toast，不崩溃。

### 6.2 两个校区的适用范围（页面置顶展示）

| 入口 | 校区 | 适用条件 | 适用范围说明 |
| --- | --- | --- | --- |
| 宿舍电费 · 唐岛湾 | 唐岛湾 | 需登录 · 建议校园网 | **只适用于唐岛湾校区宿舍**。照明与空调是两套独立表计，余额不能互抵，两套各有一个号。 |
| 宿舍电费 · 古镇口 | 古镇口 | 需登录 · 建议校园网 | **只适用于古镇口校区**。与唐岛湾是**完全不同的另一套系统**，房间号、账户、余额互不相通；不要拿唐岛湾的房间号在这里试。校外匿名访问曾返回 503，通常需先连校园网。 |

其余入口（课表、空闲教室、图书馆座位 / 主页、校园卡 / 数字石大、信息化建设处、古镇口综合办）
按"学习 / 生活与办事"分组，每张卡点开可看完整适用范围、注意事项、地址与核对依据。

单测钉住的边界：地址必须是 http(s)、**不带 token / code / ticket 等凭据参数**、
两校区电费必须是**不同域名**、每个入口都必须写清适用范围与核对依据、
不得出现"官方合作 / 校方授权"这类越权表述。

- 未做**跨天/跨周**的时间行为验证（需要改系统时间）。
- 组件在"用户日程"与"演示课"混排、且同一格冲突时的显示优先级未专门验证。

---

## 8. 已知限制与剩余问题

1. **只验证过模拟器**（Android 36 / Pixel 6 AVD），未上真机。厂商 ROM 的后台与通知策略、
   真实启动器对 RemoteViews 的裁剪，仍可能和模拟器不同。
2. **默认作息是常见排法，不是 UPC 官方作息**。首次安装后用户需要在
   「课程表设置 → 节次时间」里改成实际时间，否则课表时间与桌面组件会有偏差。
   界面上已如实说明，但这仍是一个需要用户手动做的一步。
3. **还没有"新建/切换学期"的 UI**。首次启动会按今天自动生成一个学期；
   改开学日 / 总周数在设置页可以做到，但多学期并存（例如提前排下学期的课）暂未提供入口。
4. **手工补录课程没有批量导入**（ics / Excel 都不支持）。课表内容全靠手工添加。
5. **节次数量不可增删**，只能改每节的时间。改节数会破坏已保存日程的语义，
   所以暂时固定为 10 节（这也是课表网格的行数）。
6. **校园服务入口的地址会变**。表中记录了核对日期与依据，但没有自动校验机制；
   入口失效时只能人工更新 `CampusServices.kt`。
7. **两校区的划分只体现在入口表里**，App 本身不识别用户属于哪个校区，
   也没有按校区过滤课表的能力。
8. **未接入任何受保护接口**（符合范围约束）：教务课表、空教室、电费、校园卡、图书馆座位
   都只能跳官方网页，App 内看不到真实业务数据。
9. **深色模式下的桌面小组件配色未单独验证**：组件颜色由主题算出（与 App 同一套算法），
   但只实测了浅色桌面。

## 9. 下一步建议（不影响本轮交付）

1. 上真机复测，重点看四处：演示横幅在小屏上是否显眼、课表网格里「演示」角标是否被挤掉、
   深色桌面上的组件配色、以及厂商 ROM 杀掉进程后番茄钟能否恢复。
2. 补"新建学期 / 切换学期"的入口，让多学期并存可用。
3. 评估本地 `.ics` 导入，降低手工录课成本（纯本地解析，不涉及校园接口）。
4. 按学校回复情况再决定是否争取只读接口授权；在此之前保持"无 INTERNET 权限"这条硬边界。

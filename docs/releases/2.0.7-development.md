## 详细诊断与复测方式

沿用“首页 → 设置 → 关于 UPC Pocket → 导出诊断报告”，导出仍为本机生成的 `summary.txt` 与 `events.jsonl` ZIP，由用户主动分享。复现一次流水查询或充值准备失败后直接导出即可；不需要为了取证再次提交订单或付款。

认证网络汇总包括 DNS、连接、TLS、请求头、响应头及正文阶段，记录总耗时、各阶段耗时、DNS 返回的 IPv4/IPv6 数量、连接/TLS/请求头尝试次数，以及是否复用连接、固定协议与代理类别。未观测到的字段保持未知，不填为 0。响应字节数为读取器实际取得的解压后字节；正文读取失败时保留已收到的 HTTP 状态和已读数量，不保存正文。

固定业务事件覆盖本人核验、流水页/全量/汇总、充值准备各步骤、订单创建、支付准备、查单及微信可用性/分发。各根动作使用独立的短 operationId；认证请求沿用自己的认证 operationId，不能把相邻但独立的操作强行视作同一链路。写请求发出后不能确定结果时保留 UNKNOWN；微信接受分发只表示已交给微信，不能当作付款或到账。

新摘要严格按固定枚举及有界数字汇总；原有 schema 4 行保留，不补造缺失的网络细节。网络错误、超时、TLS、协议错误和响应过大分别记录，但这些分类仍需结合反馈设备复测，不能仅凭耗时或地址族数量断言现场根因。

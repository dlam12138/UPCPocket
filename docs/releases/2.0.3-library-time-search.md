## 1. 接口核实结论（先协议，后接生产）

Issue #1 给的 `GET /rest/v2/searchSeats/{date}/{begin}/{end}?roomId=...&page=...` 只是线索。
本轮分别用**学校当前公开前端**和**本人账号最小只读请求**核实，结论：该接口是 UPC 当前真实协议，
参数与语义如下（只记录脱敏结构、枚举、数量与布尔值，不记录 URL 正文、账号、token、Cookie、座位业务内容）：

- 公开前端 `libseat/static/js/app.*.js` 定义 `fetchGet("/rest/v2/searchSeats/"+e.date+"/"+e.begin+"/"+e.end,{params:e})`；
  `chunk` 页面组件对「按时段找」构造 `{date, begin:$timeToMinute(startTimeStr), end:$timeToMinute(endTimeStr), batch, page, roomId, buildingId, token}`，
  响应读 `e.data.data.seats`（key = row*1000+col），并对 `status`/`message` 做业务判断。
- `$timeToMinute("HH:mm")` = `60*HH+mm`（分钟），`minuteToTime` 反向；**不是** HH:mm 字符串、不是半小时档位。
- 实测（正常 CAS → app token → seat token → 本人核验 → filters → rooms → searchSeats，全部只读）：
  - 路径 `/rest/v2/searchSeats/{date}/840/960`（=14:00–16:00）、query `roomId/buildingId/batch/page/token`，
    使用与其它 `/rest/v2` 相同的 HMAC 签名头与 `Authorization`，返回 HTTP 200、业务 `status=true`。
  - `data` = `{seats:{row*1000+col:seat}, page:n, hasMore:bool}`；seat 字段与 `layoutByDate` 一致
    （`id/name/type/enabled/status/local`，无 row/col，由 key 还原）。
  - `batch=1,page=1` → 1 个座位 `hasMore=true`；`batch=1,page=2` → 0 个 `hasMore=false`；
    `batch=100,page=1` → `hasMore=false`。**服务端分页字段真实存在且随 batch/page 变化**。
  - 不同时段区间返回不同数量（14:00–16:00 与 14:00–14:30 等），证明是**完整目标区间**语义，
    不是 layout FREE 的此刻状态；`begin/end` 用 HH:mm 字符串会得到不同/错误结果。
  - 无效区间（结束早于开始）实测 `status=false, data=null`（业务失败），客户端仍自行校验 begin<end，
    不把空数组当成功。
  - 对区间候选调用官方 `startTimesForSeat`/`endTimesForSeat` 成功：返回 `[{id,value}]`，含目标
    HH:mm 的真实 id（如 14:00 / 16:00 各有对应 id），可据此用原始 id 提交。
- **证据边界**：真实只读验证只做一页/少数区间与一条座位时间链；没有真实预约/取消/签到，
  没有连续多页真实全量翻页，没有在全校各房间/各时间段穷举。分页循环/上限/部分失败/代次隔离
  由合成单测覆盖，不代表学校在极端条件下的真实行为。HTTP 200 未当作业务成功，`status=false`、
  `code=12`、结构异常分别处理。

## 2. 实现摘要

- 唐岛湾房间页新增两段切换「按座位选 / 按时段找」，默认按座位选；原有座位图、时间选择、
  底部摘要、二次确认、取消/预约记录流程保持通过。超星 seat/seatengine 独立协议未改动。
- 按时段找：系统风格 TimePicker 明确 HH:mm，不自动填一小时/不猜半小时规则；「查找座位」才联网，
  只查当前房间首次一页；手动「加载更多」按服务端 `page/hasMore`，按稳定 id 去重，识别重复页/
  页号倒退/不推进，单次条件最多 20 页；部分失败保留同条件结果并提示，首屏失败不写 0 个可约；
  完整读完且无失败才写「共 N 个」。候选全隐藏但 `hasMore=true` 时仍保留加载更多，不宣称全房间没座。
- 查询键 = 会话/账号代次 + 馆区 + 房间 + 日期 + 起止分钟 + 模式；切条件清空旧候选/选择/分页，
  迟到响应按代次 + token + 完整键隔离，不能覆盖新条件或重新启用确认。
- 候选单选后调用该座位官方 `startTimes`/`endTimes`，按真实 HH:mm 匹配并使用**服务端原始 id**；
  不匹配清除选择并提示「该座位时段已变化，请重新查找」。两种模式确认守卫完全分开：
  按座位模式仍依赖 layout `selectable`；按时段模式依赖已验证区间结果 + 静态字段 + 官方时间映射，
  当前占用不单独否决未来区间可约。最终提交只发一次，结果未知/超时不重提、不自动换座/扩大时段。
- 本机个人隐藏：独立 DataStore，命名空间 = `system=libseat + buildingId + roomId + seatId`，
  另存座号展示快照；候选更多菜单、座位图长按、已选座位均可隐藏；选中即清空确认状态，
  Snackbar「已隐藏座位 N」带撤销；地图保持真实坐标、不重排，弱化并用独立斜线/图例标记，
  区别于官方占用；房间更多菜单「隐藏的座位（N）」底部面板支持逐个/全部恢复。
  这是设备本地偏好，不上传、退出/换号不误删、恢复不改变学校可用状态。
- 前端文案精简（Apple 式短句），不新增顶级入口/大段说明/新框架；诊断不记录 URL/正文/账号/座位内容。

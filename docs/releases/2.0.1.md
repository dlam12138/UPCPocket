# UPC Pocket 2.0.1 课表网页登录修复（本地构建，未发布）

2026-11-05 真实用户反馈：课表自动登录触发验证码后打开网页登录，WebView 像此前的图书馆登录一样没有正常加载。本文只记录本轮定位、修复和实际验证；不更新 `v2.0` tag、不改写 2.0 发布记录，也不自动 push / merge / publish。

## 1. 根因

课表 `TimetableLoginDialog` 在 Compose `AndroidView` 中创建 WebView 时没有显式 `layoutParams`。API 36 模拟器实测：

- 修复前 WebView 实际 bounds 为 `1079×2200`，但 `layoutParams` 是 `-2×-2`（`WRAP_CONTENT`）。
- CAS 外层页面 `window.innerHeight=839`、`documentElement.clientHeight=839`，但 `body.clientHeight=0`、移动登录 `#loginIframe` 为 `0×0`。
- 外层 `.container` 顶部为 `-230`；表单用户名顶部 `-124`、密码顶部 `-50`。移动登录 iframe 本身高度为 0，页面看起来就是空白。

这不是 tab/Scaffold/Insets 遮挡：Dialog 内容 bounds 为 `[0,63][1079,2400]`，WebView 为 `[0,262][1079,2400]`，父容器和 WebView 都有真实宽高；修复前也没有长期存在的全屏 loading 遮罩。根因是 WebView 子 View 的 `WRAP_CONTENT` 让 CAS 的 100% 高度布局链条塌缩。

同一 CAS URL 加上显式 `MATCH_PARENT` 后：

- `layoutParams=-1×-1`，`#loginIframe=412×839`。
- 用户名 `(126,311,250,24)`、密码 `(126,355,250,24)`、`LOGIN` `(20,434,372,44)`，均在 412×839 视口内可见。
- Release 2.0.1 截图中 CAS 蓝色 `LOGIN` 按钮位于屏幕 `y=1403–1406` 行，说明实际安装包的网页区不是空白。

因此没有照搬图书馆的 CAS iframe 注入修复；本轮在课表页面实测只需补齐 WebView 尺寸并等待首次布局，避免把未验证的 JS 改写带进来。

## 2. 修复

- `TimetableLoginDialog` 为 WebView 显式设置 `ViewGroup.LayoutParams(MATCH_PARENT, MATCH_PARENT)`，并在 WebView 首次获得非零宽高后才发起导航；避免在 `0×0` 时抢跑把 CAS 布局固定为 0。
- 新增 `TimetableLoginPolicy`：只允许 HTTPS、443/默认端口、无 userinfo 的目标；CAS 仅 `/cas/`，课表业务仅 `/a_upc/api/cas/login`、`/site/weekschedule/`、`/timetable/wap/default/`。`about:blank` 只作为 WebView 初始化地址，不能作为登录入口。没有把任何 Chaoxing 域加入课表白名单。
- `shouldOverrideUrlLoading` 只对主框架做放行/拒绝判断；非法主框架显示可恢复错误，非法子框架静默停止。SSL、HTTP 错误和主框架网络错误分别显示错误，不再留下无说明空白。
- 页面完成/错误/渲染进程退出都有明确状态；渲染进程退出会移除死 WebView，重新加载会重建 WebView 和代次。旧代次回调被忽略，Cookie 仍由 `accountId / credentialGeneration / businessEpoch` 和 `adopting` 门闩复核，迟到回调不会给换号后的账号提交。
- 自动登录返回的 CAS 挑战地址只在白名单内沿用，否则回退固定课表入口；不再无条件使用 authenticator 返回的任意地址。
- 顶部只保留 4dp 细进度条，不遮挡网页；错误页提供“重新加载”和“关闭”。“完成”在没有 Cookie 时给出明确提示。

## 8. 2026-11-06 续修：网页有课表、返回原生仍提示“无法识别的数据”

### 8.1 现场边界

- 用户提供 20:13 的错误录屏和 20:15 的诊断 ZIP。两者不是同一次操作，不能逐帧对应；ZIP 只有 7 条 TIMETABLE WebView 事件（同 `operationId`）：`WEBVIEW_VIEWPORT 347×681`、CAS `WEBVIEW_START`、CAS `WEBVIEW_FINISH OK`、`APP_CALLBACK OK`、`APP_PAGE OK` 与两次 `APP_PAGE FINISH OK`。没有 blocked/network/SSL/renderer 事件。
- `WEBVIEW_FINISH OK` 只表示 `onPageFinished`，不等于业务成功，也不能证明原生 API 会话或 DOM 内课表可见。现有 2.0.1 没有记录 `adoptInteractiveCookies → getIndex → getWeek → publish`，因此**没有该用户原始响应，无法确认其具体根因**。
- 录屏中网页已显示学校彩色课表，返回原生先短暂“连接中”再出现“学校返回了无法识别的数据”。该文案在现有代码中只来自 `TimetableErrorCode.SCHEMA_CHANGED` / `RESPONSE_TOO_LARGE`，即索引/周响应的 JSON、结构或字段规则未通过；不是网络、TLS 或 WebView 加载错误的文案。
- 现有真实协议（2026-2027 秋季第 9 周）在本机授权账号上可解析；因此不能把“用户数据一定不兼容”写成已证实事实，也不能用本机数据替代该用户复现。

### 8.2 本轮代码

- 诊断模型升到 schema 2（仅新增可选字段）：固定 `phase`（COOKIE/INDEX/WEEK/PARSE/PUBLISH/CACHE/SESSION/AUTH/RESPONSE）、固定 `detail` 规则码、HTTP 数字状态、响应字节数、条目数；不保存 URL/query/头/正文/字段值/课程名/教师/地点/账号/异常 message。
- 网页登录弹窗生成的 `operationId` 现在贯穿 `adoptInteractiveCookies → getIndex → 会话保存 → 缓存 → getWeek → 发布/失败`；采纳成功后由 Service 直接查当前周，不再由 ViewModel 二次 refresh，避免链路断开与重复索引。
- Cookie 读取从只查 `https://app.upc.edu.cn/` 改为按 `/timetable/wap/default/get-datatmp`、`/timetable/wap/default/get-index`、`/site/weekschedule/index`、`/` 由具体到根合并，避免路径作用域 Cookie 漏读；`onPageFinished` 后延迟 350ms 再自动提交，给页面脚本写 Cookie 的时间；自动提交失败会重置尝试标记，用户点“完成”或后续页面完成可明确重试，不循环认证。
- 失败分类：`TRANSPORT_NETWORK/TIMEOUT/TLS` 与 HTTP/非 JSON/登录页分开；登录 HTML 归为 `LOGIN_PAGE`，映射“登录状态已失效，请重新网页登录”，不再一律 `SCHEMA`。
- 缓存文案按真实状态：有旧周显示“已保留上次缓存”，没有则“暂无可用的旧缓存”；`WeekPanel` 的 ERROR 文案改为“查询失败，暂无缓存”，不再上面说保留、下面说没有。
- 兼容规则（评审后收紧：只保留有语义依据、不改变课程归属/完整性的容错）：
  - `order`、`totalLength`、声明 `weekday`、`c_N` 起始与 `lessArr.min()` 矛盾时忽略该冗余值并记录规则；节次仍以 `lessArr`、日期仍以 `weekdays` 为准。
  - `week` 只保留分隔符/范围格式兼容（逗号、中文逗号、空格、`1-16`/`1~16`）；标签无法解析或明确不包含请求周时**失败** `WEEK_PARSE_WEEK_LABEL`，不补周、不回退。
  - 接受 `6.0`/`"6.0"` 整数值浮点、空单元格和非 `c_N` 元数据键；空 `classes` 日、`c_15` 等超 1–14 且带课程的单元**失败**，不跳过、不扩成 15 节。
  - 缺课程名、缺 `lessArr`、节次越界、条目类型异常均**整周失败**，不产生“部分课程”；重复节次去重只改变同一节次集合的重复项，不丢课程。
  - 源周日期必须精确等于 `term.startDay + (week-1)*7`；相邻周/单日偏移一律 `WEEK_PARSE_DATE_ALIGN` 失败，不再接受 ±1 周。
  - 历史/暑期学期条目单条无效时跳过；`params.week` 无效时置空并记录；当前学期本身不可用时失败，不回退到历史学期。
  - UI 周视窗恢复“周日至周六”固定框架；源周不是周日起时不旋转、不重标日期，未覆盖日期标未知，框架外课程不显示；不把未知日期显示成无课。
  - 不产生 `complete=false` 的部分周：核心规则失败时保留上一份完整缓存/今日/组件状态，不写新缓存、不发布“已更新”。

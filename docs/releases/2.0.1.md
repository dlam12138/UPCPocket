# UPC Pocket 2.0.1 课表网页登录修复（本地构建，未发布）

2026-11-05 真实用户反馈：课表自动登录触发验证码后打开网页登录，WebView 像此前的图书馆登录一样没有正常加载。本文只记录本轮定位、修复和实际验证；不更新 `v2.0` tag、不改写 2.0 发布记录，也不自动 push / merge / publish。

## 1. 根因

课表 `TimetableLoginDialog` 在 Compose `AndroidView` 中创建 WebView 时没有显式 `layoutParams`。API 36 模拟器实测：

- 修复前 WebView 实际 bounds 为 `1079×2200`，但 `layoutParams` 是 `-2×-2`（`WRAP_CONTENT`）。
- CAS 外层页面 `window.innerHeight=839`、`documentElement.clientHeight=839`，但 `body.clientHeight=0`、移动登录 `#loginIframe` 为 `0×0`。
- 外层 `.container` 顶部为 `-230`；表单用户名顶部 `-124`、密码顶部 `-50`。移动登录 iframe 本身高度为 0，页面看起来就是空白。

这不是 tab/Scaffold/Insets 遮挡：Dialog 内容 bounds 为 `[0,63][1079,2400]`，WebView 为 `[0,262][1079,2400]`，父容器和 WebView 都有真实宽高；修复前也没有长期存在的全屏 loading 遮罩。根因是 WebView 子 View 的 `WRAP_CONTENT` 让 CAS 的 100% 高度布局链条塌缩。

同一 CAS URL 加上显式 `MATCH_PARENT` 后：

- `layoutParams=-1×-1`，`#loginIframe=412×839`。
- 用户名 `(126,311,250,24)`、密码 `(126,355,250,24)`、`LOGIN` `(20,434,372,44)`，均在 412×839 视口内可见。
- Release 2.0.1 截图中 CAS 蓝色 `LOGIN` 按钮位于屏幕 `y=1403–1406` 行，说明实际安装包的网页区不是空白。

因此没有照搬图书馆的 CAS iframe 注入修复；本轮在课表页面实测只需补齐 WebView 尺寸并等待首次布局，避免把未验证的 JS 改写带进来。

## 2. 修复

- `TimetableLoginDialog` 为 WebView 显式设置 `ViewGroup.LayoutParams(MATCH_PARENT, MATCH_PARENT)`，并在 WebView 首次获得非零宽高后才发起导航；避免在 `0×0` 时抢跑把 CAS 布局固定为 0。
- 新增 `TimetableLoginPolicy`：只允许 HTTPS、443/默认端口、无 userinfo 的目标；CAS 仅 `/cas/`，课表业务仅 `/a_upc/api/cas/login`、`/site/weekschedule/`、`/timetable/wap/default/`。`about:blank` 只作为 WebView 初始化地址，不能作为登录入口。没有把任何 Chaoxing 域加入课表白名单。
- `shouldOverrideUrlLoading` 只对主框架做放行/拒绝判断；非法主框架显示可恢复错误，非法子框架静默停止。SSL、HTTP 错误和主框架网络错误分别显示错误，不再留下无说明空白。
- 页面完成/错误/渲染进程退出都有明确状态；渲染进程退出会移除死 WebView，重新加载会重建 WebView 和代次。旧代次回调被忽略，Cookie 仍由 `accountId / credentialGeneration / businessEpoch` 和 `adopting` 门闩复核，迟到回调不会给换号后的账号提交。
- 自动登录返回的 CAS 挑战地址只在白名单内沿用，否则回退固定课表入口；不再无条件使用 authenticator 返回的任意地址。
- 顶部只保留 4dp 细进度条，不遮挡网页；错误页提供“重新加载”和“关闭”。“完成”在没有 Cookie 时给出明确提示。

## 4. 模拟器验收

设备：`emulator-5556`（AVD `upcpocket_api36`），API 36，1080×2400。使用 `adb install -r` 覆盖，保留用户数据；未 `pm clear`、未卸载、未更换证书。

已实际检查：

- **CAS 空表单**：课表说明 → 网页登录；网页区显示 CAS 移动登录页，用户名/密码与蓝色 `LOGIN` 按钮在视口内。Release 截图中蓝色按钮位于 `y=1403–1406`。
- **验证码入口**：本轮没有故意触发风控，不声称验证码已完成或已通过；只验证了 CAS 表单/交互入口可见。验证码出现时的页面走同一 WebView 与错误/重载路径，但真实验证码画面未复现。
- **深色**：系统深色下网页仍渲染，蓝色 `LOGIN` 按钮位于 `y=1403–1406`。
- **1.5× 字体**：蓝色 `LOGIN` 按钮下移到 `y=1630` 附近，仍在屏幕内；Dialog 头部/提示未把 WebView 压成 0。
- **键盘**：点击 CAS 用户名后 `mInputShown=true`，页面仍渲染；1.5× 下页面整体下移，键盘可能覆盖底部按钮，需页面内滚动。未把该项当作完整输入链路验收。
- **断网/重载**：断网打开得到“登录页加载失败；请检查网络后重试。”和“重新加载”；恢复网络后重载恢复 CAS 表单，蓝色按钮回到 `y=1403`。
- **返回**：系统返回关闭 Dialog，回到课表页。
- **真实账号**：使用用户已授权的本人账号完成一次正常 CAS/只读课表加载；没有反复试密码，没有预约、取消或签到。真实课程/账号画面未写入仓库或文档。

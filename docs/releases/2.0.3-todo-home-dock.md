## 范围与不变量

- 只做本机独立待办：标题、完成状态、可选一次性提醒；添加、编辑、完成/撤销、删除与撤销误删。不做备注、子任务、项目、标签、优先级、复杂重复、云同步、学校账号依赖。
- 保留现有 Compose Material 3、手动 AppGraph、Room、插件契约、RemoteViews 组件与校园业务；不整体移植外部待办应用，不复制郑大认证/业务路由。
- 待办数据库与学校个人数据清理分离：换学校账号不删除本机待办。
- 首页、待办页和底部 dock 都只从同一 `TodoStore.tasks` Flow 派生；不维护第二份任务状态。

- 只使用合成数据验收；不把用户附图或真实待办文字写入仓库。

## 数据与排序

Room 表 `todo_tasks`（独立库 `upcpocket-todo.db`）：

| 字段 | 说明 |
| --- | --- |
| `id` | UUID 字符串，主键 |
| `title` | 用户标题 |
| `completed` / `completedAt` | 完成状态和完成时刻 |
| `createdAt` / `updatedAt` | 创建/修改墙钟毫秒 |
| `revision` | 每次有效修改递增；通知动作和 Alarm 都带它 |
| `reminderAt` | 当前计划提醒墙钟毫秒；空表示无提醒 |
| `reminderFiredAt` | 实际发送通知的时刻；空表示未发送 |

- 未完成排序：先取“提醒时间早于明天 00:00（本地时区）”的逾期/今天项，按 `reminderAt` 升序；其余未完成项按 `createdAt` 降序（最新在前）；以 `id` 作最终稳定 tie-break。
- 已完成排序：`completedAt` 降序，再 `id`。
- 首页摘要只取未完成排序的前两条；无未完成时显示“暂无待办”+添加入口。
- 个人待办使用设备当前系统本地时区；不套用课表/空教室的上海时区。

## 提醒状态机

- 用户打开提醒时默认当前系统本地日期和时间，明确显示；可改日期/时间。空白标题不能保存。
- 数据是事实来源；AlarmManager 只做调度。无周期 Worker/轮询。
- 通知权限：Android 13+ 在用户首次设置提醒时按需请求；拒绝仍保存待办，页面显示“通知权限未开启，提醒不会显示”。不伪装提醒已就绪。
- 精确闹钟：Android 12+ 检查 `AlarmManager.canScheduleExactAlarms()`；有权限用 exact，没有则用 `setAndAllowWhileIdle`，页面显示“未允许精确闹钟，提醒可能延迟”。不自动跳设置；提供短入口。
- 完成、删除、编辑、稍后提醒都递增 revision 并取消旧 Alarm/通知。Alarm 和通知动作携带 `taskId + revision`；数据库条件更新不匹配时整次动作忽略，旧通知不会完成/延后新任务。
- 到点发送前再次检查：任务存在、未完成、revision 匹配、`reminderFiredAt` 为空、通知权限可用。发送成功记录实际 `reminderFiredAt`；相同任务最多一次正常发送。
- 迟到收敛：重建时仍未完成且未发送的过去提醒只补一次通知，不按错过次数重复；已完成/已发送不再通知。
- 稍后提醒固定 10 分钟：清除 `reminderFiredAt`，以新的 `reminderAt` 和 revision 重新调度。
- 重启、`MY_PACKAGE_REPLACED`、时间/时区变化、精确闹钟授权变化时从 Room 重建全部待办调度；普通进程死亡不依赖重新打开 App。
- 通知提供“完成”“稍后 10 分钟”和点击打开对应待办；渠道、PendingIntent 最小化，不请求定位/联系人/文件权限。

## 首页摘要

- 页头下、常用服务上方全宽摘要卡：标题“待办”+未完成数量，右上独立 `＋`。
- 最多两条未完成任务：勾选框独立切换完成；点击正文进入待办页；`＋` 直接打开新增面板。
- 有提醒才显示短时间；已完成不进入首页摘要。
- 操作通过 Room Flow 即时同步待办页和首页计数。

## 四项悬浮 dock 与整页 Pager

- dock 视觉/覆盖结构直接移植自 [3beuml/ZZUPocket](https://github.com/3beuml/ZZUPocket) 的 `AppNav.kt`（commit `dda318e9b37d8b65991a965e72fd4dd40b630a20`，MIT，Copyright (c) 2026 3beuml）。完整来源、修改说明与许可见 [第三方记录](../third-party/ZZUPocket-dock.md)。原版没有整页 Pager，这一层是本项目补足，不冒充上游已有。
- 保留上游：0.5dp 上亮下描边、56dp 高/28dp 圆角/水平 20dp/垂直 8dp、圆形 40dp 选中泡、浅色 `surface.copy(alpha=0.5f)` + 6dp 窄软影、深色 `surface` + 1dp tonal 微浮起、外层只吞 tap 不吞 move 的留白防穿透。
- 必要差异：四项换成首页/课表/待办/专注；选中泡随 `HorizontalPager` 的连续 `currentPage + currentPageOffsetFraction` 移动，图标 outlined/filled 与颜色按滑动进度交叉过渡；无障碍使用 `selectable(role=Tab)`、完整名称和 selected 语义。
- 四个一级页本身用 Compose Foundation `HorizontalPager`，左滑下一页、右滑上一页，两端不循环；连续跟手、松手吸附/取消回弹，不靠全屏 `detectDrag` 后瞬间导航。胶囊点击只调用 `animateScrollToPage`，不再压 NavController 返回栈。
- Pager 与 NavController 只在 main 容器交界：四个 tab 不注册 NavHost 路由；设置/账号/二级页仍在 NavHost。通知/组件/首页卡片都通过 `switchTab(route) -> pagerIndex` 同步；`BackHandler` 在非首页回首页，首页再交给系统。
- 四页全部保留状态（`beyondViewportPageCount = 3`），但 `LocalPluginPageActive` 只在该页稳定活动时放行：课表 `TimetableViewModel.start()` 才 open/refresh，Focus 才请求通知权限，Todo 才消费 pending 通知任务；预加载不会登录查课表或弹权限/打开编辑器。
- dock 是覆盖层，不再用 Scaffold.bottomBar 占一整条；内容从胶囊下穿过。`LocalDockClearance = 88dp + navigationBars` 注入一级页，滚动容器末尾/FAB/Snackbar/专注底部各自留余量，最后内容能完整滚出。
- 键盘/新增编辑 sheet/二级页/登录 dialog 不参与翻页；Pager `userScrollEnabled` 在 IME 时关闭；课表周网格内部横向滚动优先，不要求所有页面横滑都从横向控件夺手势。

### 评审发现的可靠性修正

1. **旧动作零副作用**：`onActionComplete`/`onActionSnooze` 只在 `completeIfRevision`/`snoozeIfRevision` 真正命中时取消 Alarm/通知；旧 revision 或任务不存在直接返回。`onAlarm` 先校验任务、`reminderAt`、revision，旧 Alarm 不再按 taskId 取消当前新 revision 的提醒/通知。
2. **PendingIntent 身份**：通知动作的 data 为 `upcpocket://todo/action/<完整UUID>/<revision>/<complete|snooze>`；旧 token 不会因新 revision 的 `FLAG_UPDATE_CURRENT` 被重绑定。Alarm 使用 `upcpocket://todo/alarm/<完整UUID>` 的稳定身份（revision 在 extras，便于按 taskId 取消）；通知打开使用 `upcpocket://todo/open/<完整UUID>`。
3. **完整 taskId 替代 hash**：通知使用 `tag = todo:<完整UUID>` + 固定 id，Alarm/动作/打开 PendingIntent 都带完整 UUID；已用 Java hash 相同的两条合法 UUID 验证 schedule/cancel/notification/action/open 互不串扰。
4. **业务串行**：`TodoService` 用 service 级 `Mutex` 覆盖数据变更、reconcileAll、Alarm/通知动作及其调度副作用；内部 locked 方法不重复上锁。`onAlarm` 对过早事件只重建当前调度，不提前通知。
5. **渠道可用性**：`TodoNotifier.post` 除全局权限外检查 `NotificationChannel.importance != NONE`；已存在渠道不再 `createNotificationChannel`，避免覆盖用户关闭设置。发送失败会回滚 `reminderFiredAt`，恢复后只补一次。

新增回归：`TodoServiceTest`（5 项，fake scheduler/notifier/DAO、可控 clock/协程）、`TodoIntentsTest`（3 项，PendingIntent 旧 token/哈希碰撞/独立取消）、`TodoNotifierTest`（2 项，渠道 NONE/哈希碰撞 tag）；app `HostPluginUiTest` 增加打开 Intent 的哈希碰撞覆盖。

### 设备（专用 `upcpocket_probe`，API 36，设备时区 GMT）

- **普通进程死亡**：合成任务设置在 14:58:53；`am kill com.upcpocket.app` 后进程消失，未打开 Activity，14:58:54 系统仍发出 `待办提醒` 通知，标题/“提醒时间”与实际 `when` 正确，含“完成”“稍后 10 分钟”两个动作。
- **通知完成**：点击“完成”后数据库 `completed=1`、revision 递增，通知消失；没有第二次提醒。
- **稍后 10 分钟**：点击后 `reminderAt` 从点击时刻精确变为 +10 分钟（15:01:34 → 15:11:34.886），`reminderFiredAt` 清空，AlarmManager 生成新的 exact 闹钟。
- **点击导航**：从通知正文冷启动进入待办 tab，并打开对应任务的编辑面板；任务标题与通知一致。
- **通知拒权/再授权**：`POST_NOTIFICATIONS` 撤销后到点无通知，待办页显示“通知权限未开启，提醒不会显示。”；授权并回到前台后，未发送的过去提醒只补发一次，随后可正常完成。
- **精确闹钟拒权/恢复**：`SCHEDULE_EXACT_ALARM` 关闭时页面显示“未允许精确闹钟，提醒可能延迟。”，`dumpsys alarm` 为 `window=+1m29s` 的不精确调度；授权后自动重排为 `window=0 exactAllowReason=permission`。
- **重启重建**：未来提醒在专用 probe 重启后仍按原墙钟触发，未依赖打开 App。
- **系统强停边界**：`am force-stop` 后到点没有通知（系统强停会取消 Alarm/阻止广播）；再次打开 App 时 `onAppStart` 从 Room 重建并补发一次未发送的过去提醒。该结果不作为普通进程死亡证据。

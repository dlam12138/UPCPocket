# 2.0.6 校园卡微信充值集成

日期：2026-11-15。状态：**PR #5 已在本地集成，主流程已简化；定向测试、独立审查、Lint、签名 Release 构建和常规模拟器检查完成，candidate3 已生成，未发布。真实微信付款与用户验收待完成。**

版本继续为 **2.0.6 / versionCode 27**，应用标识 `com.upcpocket.next`。首批界面更新提交为 `6c628cf`，其 candidate2 与验证保留在 [原开发记录](2.0.6-development.md)。本轮不覆盖旧候选或正式更新资产；公开版本仍为 2.0.5。

## 来源与范围

- 接入 [PR #5](https://github.com/dlam12138/UPCPocket/pull/5)，固定 head `4a781bb1d05e13a281b3010a98ed43cb8d97baa9`，本地以保留作者归属的 `085ff43` 合入首批界面更新。
- 入口为首页校园卡区的「充值」，由卡插件注册 `card.recharge`。缺少卡插件或认证适配时按钮与路由一起缺省，沿用统一学校账号，不新增凭据入口。
- 用户操作为「输入金额 → 点击带金额的微信充值按钮 → 拉起微信」。去掉正常流程的重复金额确认，实际付款仍在微信内确认；清除未知订单保护标记保留带后果的确认。
- 下单前检查固定微信包的可用支付 handler；不存在时不创建订单。下单后再次解析固定支付 URI、检查并钉住微信组件，启动失败显示真实错误且保留待查订单。
- 学校动态金额上下限、整数/预设规则、单次下单、加密 pending、账号/凭据代次守卫与未知结果防重继续保留。点击时绑定目标账号，排队后切号不能给新账号下单。回到应用只读查学校订单，不把回跳或 `startActivity` 成功当作付款成功。
- 独立审查修复：学校 HTTP 200 内的业务登录失效码同样结束当前会话租约，下一次用户加载/查单才重新认证，不重放当次写请求；加密标记在显式同步并读回核对全部字段后才允许继续 POST，保存失败保留旧防护记录。已补真实临时目录与 AtomicFile 故障注入回归并通过。
- 保留首批 2.0.6 的首页、课表、待办、查询页和设置改动，不改专注、共享样式、组件布局、依赖或主清单权限。协议研究与作者原始验证范围见 [原生充值研究](../research/native-card-recharge.md)。

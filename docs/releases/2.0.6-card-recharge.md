## 来源与范围

- 接入 [PR #5](https://github.com/dlam12138/UPCPocket/pull/5)，固定 head `4a781bb1d05e13a281b3010a98ed43cb8d97baa9`，本地以保留作者归属的 `085ff43` 合入首批界面更新。
- 入口为首页校园卡区的「充值」，由卡插件注册 `card.recharge`。缺少卡插件或认证适配时按钮与路由一起缺省，沿用统一学校账号，不新增凭据入口。
- 用户操作为「输入金额 → 点击带金额的微信充值按钮 → 拉起微信」。去掉正常流程的重复金额确认，实际付款仍在微信内确认；清除未知订单保护标记保留带后果的确认。
- 下单前检查固定微信包的可用支付 handler；不存在时不创建订单。下单后再次解析固定支付 URI、检查并钉住微信组件，启动失败显示真实错误且保留待查订单。
- 学校动态金额上下限、整数/预设规则、单次下单、加密 pending、账号/凭据代次守卫与未知结果防重继续保留。点击时绑定目标账号，排队后切号不能给新账号下单。回到应用只读查学校订单，不把回跳或 `startActivity` 成功当作付款成功。
- 独立审查修复：学校 HTTP 200 内的业务登录失效码同样结束当前会话租约，下一次用户加载/查单才重新认证，不重放当次写请求；加密标记在显式同步并读回核对全部字段后才允许继续 POST，保存失败保留旧防护记录。已补真实临时目录与 AtomicFile 故障注入回归并通过。
- 保留首批 2.0.6 的首页、课表、待办、查询页和设置改动，不改专注、共享样式、组件布局、依赖或主清单权限。协议研究与作者原始验证范围见 [原生充值研究](../research/native-card-recharge.md)。

## candidate4 准备失败修复与验证

用户授权使用本地凭据，已完成修复前复现和修复后复验两次真实只读原生准备。每次原生认证成功，认证请求 4 次、密码提交 1 次、充值准备 GET 5 次，订单/付款网络请求均为 0。凭据只进入一次性应用私有 fixture，读取后先删除再解析；两次均未保存应用账号，owned fixture 清理及本地加密凭据/代次元数据前后哈希检查通过。只保存固定阶段、类型、长度及校验布尔，没有保存原始响应、金额、学号、卡号或 token。

实际 `feeitem` 为对象，`retain_money` / `maxmoney` 均为 `null`，可选 `rechargeMaxAmount` 缺省。旧原生准备失败为 `P_FEE_CONFIG`；修复后原生 `prepare` 为 **PASS**，同次真实响应只在内存中交给两套规则，当前规则接受、冻结旧规则仍拒绝为 `MIN_FORMAT`。已核对[学校公开充值组件](https://mb-xyk.upc.edu.cn/campus-card/js/chunk-1186b329.e153ac09.js)的金额组件缺省语义，按官方 UI 的 0.01 / 9999 输入默认、可选前端上限及后续 feeitem 覆盖顺序兼容；不将 UI 默认称为服务端额度。严格金额语法、明确动态额度、整数/预设约束、下单前重新加载、防重和账号守卫保留，畸形配置仍停止。详细顺序见[原生充值研究](../research/native-card-recharge.md)。真实只读验证运行于使用同一生产源码的 Debug APK，不代表最终 R8 Release 的真账号 UI 已验证。

定向单测实际核对 **34 份 XML、262 项：261 通过、1 跳过、0 失败/错误**；app 为 107 项（106 通过、1 项既有真实下载 gate 跳过），card 为 155 项全部通过，未重复累计未变的 auth 161 项。本轮净增 10 项脱敏合成回归，覆盖双 `null`、缺失/空/零值、front/fee 优先级、尾零、非法配置、下限和整数/预设约束，并断言刷新上限或配置失效后不保存订单标记、不发 POST。模块边界检查通过；app/card Lint 为 73/6 条 Warning，0 Error/Fatal、0 充值源码命中。R8 与资源收缩签名 Release 构建成功，既有微信 SDK 栈映射警告保留；独立静态审查通过。主协调核对了 tester 的原始 XML、日志及最终源码哈希。

默认未授权探针的 P2 测试基建问题已修复：精确 opt-in 的 JUnit assume 位于 try/catch、fixture 和网络访问之前。新测试 APK 编译通过，并在 Debug 目标上实际定向 **skipped（status -4）**，未输出 probe 报告、未使用凭据；该结果不计入上述单测总数。针对 R8 Release 的仪器测试尝试返回 `Process crashed`，未进一步定位该测试启动失败的原因，不将其记为 Release instrumentation 通过或正常使用中的崩溃。最终 Release 已按原字节恢复并完成正常启动检查。

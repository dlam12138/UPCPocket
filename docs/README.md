# 项目文档

当前发布主线为 **UPC Pocket Lightly v0.2.7**；开发分支已推进到 **M5 页面/导航/视觉第一版**，
仅本地评审，未合并 main、未发布。

[模块化与插件化工程方案 v0.1](模块化与插件化工程方案-v0.1.md) 的 M0 已完成工程实现、
自动化回归与模拟器覆盖安装/精简装配验证，记录见 [M0 执行记录](m0/README.md)；真实
校园接口、旧 Keystore 密文与完整组件数据刷新仍待具备条件后补验。

后续按 [统一账号与课表工程方案 v0.1](统一账号与课表工程方案-v0.1.md) 从 M1 推进：
M1 的本机加密账密、脱敏账号状态、代次与失效/清理基础已实现，记录见
[M1 执行记录](m1/README.md)；M2 的校园卡余额绑定、旧快照迁移与页面/组件/Worker 同目标已实现，
记录见 [M2 执行记录](m2/README.md)；M3 的课表真实 CAS 认证、学期/教学周查询、周网格、今日课程与
只读离线缓存已实现，记录见 [M3 执行记录](m3/README.md)；M4 的 `libseat` 统一认证、本人校验、
accountId/凭据代次绑定与最小 UI 已实现，记录见 [M4 执行记录](m4/README.md)。M4 只覆盖
`libseat`；M5 后续曾新增 nspace 独立认证与 Chaoxing 四入口研究，**2026-11-04 用户决定撤下
全部研讨间/空间预约产品功能**：nspace、reservepc A/B 的页面/路由/协议/Service/表单/租户桥接
已删除；现行产品只保留 libseat、Chaoxing seat、Chaoxing seatengine 三个座位入口。研究记录
保留为归档，不代表产品能力。M5 已把首页、课表、专注收束为三个顶级 tab，并将账号/主题/组件/关于
统一到设置入口；记录见 [M5 页面与视觉第一版](m5/README.md)，仍是待用户评审的第一版，
不是最终设计定稿。2026-11-05 晚完成三组件 Apple 式视觉修订、160–360dp/1.0–1.5× 自适应
与 R8 精简 Release 本地验收，记录见 [三组件视觉修订](m5/2026-11-05-组件视觉修订.md)；
release 为开发签名、未发布。

M4 前置的六个图书馆/空间预约入口研究已完成并归档（研讨间产品已撤下），见
[图书馆与空间预约六入口接口研究](research/图书馆与空间预约六入口接口研究-20261103.md)。
研究覆盖公开前端/入口与既有来源核对，并用只读 UI 观察确认求是 `reservepc` 已在现有 Edge
加载研讨室列表；无 Cookie 的 303 探测不能代表现有会话不可用。用户另外提供了五份只读
HAR：nspace 已到 venue/roomType/dates/roomList 浏览（6/11，2 页），seat/seatengine 仅到
入口配置与空 current/near，reservepc 两租户分别到 8/23 个预约项且 user list 为空。六份 HAR
都没有 CAS/passport 登录跳转或写请求，因此它们不是端到端统一认证证据；M4 的 libseat
认证由正常 CAS 重新完成，HAR 只作为只读业务协议证据。2026-11-04 的后续复核在已登录
Chaoxing 会话中确认 seat/seatengine 真实馆区/座位图；reservepc 的稳定 URL 当前 302 到
“未查询到应用”，需要学校业务目录生成的 `reserveIdEnc`，不再把浏览器旧页面当成稳定入口。
这些是历史研究证据；seat/seatengine 仍保留原生只读，nspace/reservepc 产品功能已撤下，见
[M5 六入口记录（归档）](m5/图书馆六入口.md)。M1 保存成功只表示“已保存，尚未验证”，不改变当前
发布版对学校接口的接入方式。

页面安排、导航及视觉设计在核心能力稳定后的 M5 统一落地：三 tab「首页 / 课表 / 专注」，
单一设置入口，旧“更多”目录取消。M5 不重写认证/缓存，只调整插件 tab/入口贡献与原生页面呈现。

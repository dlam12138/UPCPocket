# 空闲教室公开页面核验（2026-10-27）

## 核验范围与结果

使用本机 PowerShell `Invoke-WebRequest` 匿名访问总体计划中的学校页面：

`https://app.upc.edu.cn/freeclass/wap/default/all`

返回 HTTP 200，`Content-Type: text/html; charset=UTF-8`，页面标题“空闲教室”。网页搜索工具未能打开该地址，但本机直接访问成功，不能把工具失败解释为网站故障。

只读取页面和页面直接使用的正常只读查询，没有登录、提供账号、Cookie、Token、修改 User-Agent、探测其他路径或尝试绕过访问限制。初始 HTML 中有 Vue 数据和查询代码，学校实际页使用如下请求：

```text
POST https://app.upc.edu.cn/freeclass/wap/default/search-all
Content-Type: application/x-www-form-urlencoded; charset=UTF-8

xq=校区名称&date=YYYY-MM-DD&lh=教学楼名称或全部&jc[]=节次&jc[]=节次
```

这是页面公开代码展示的地址，不是推测的接口。`POST` 用于查询筛选条件，并非预约或写入业务操作。

## 已观察到的字段

- `xq`：初始页面列出“古镇口校区”“唐岛湾校区”。
- `lh`：`全部`，或学校返回楼宇选项的 `id`。
- `date`：日期，例如 `2026-10-27`。
- `jc[]`：可多选。学校页面上午 1–5 节、下午 6–9 节、晚上 10–13 节，与 App 本地课表的节次数配置无关。
- 响应根对象：`e`、`m`、`d`；实测成功为 `e: 0`。
- `d.listLh`：楼宇筛选项数组，元素有 `id`、`name`。
- `d.all`：按楼宇名称分组的全部房间目录。
- `d.js`：按楼宇名称分组的所选节次占用房间。官方 Vue `watch(dataList)` 按 `code` 匹配并设置 `isUsed`。
- 房间字段：`name`（房间名）、`code`（房间代码）、`num`（容量字符串）、`jxlm`（教学楼）、`xqm`（校区）。

学校 CSS 的颜色命名不应拿来猜空闲语义；实现依照 JavaScript 的 `isUsed` 数据关系，所选节次任一节占用就不列为空闲。

## 本次真实查询

正常提交两次页面筛选：两校区各查询一次，日期 `2026-10-27`、楼宇“全部”、节次 6、7、8、9。两次均 HTTP 200、`e: 0`、`m: 操作成功`。

唐岛湾本次返回楼宇：东廊、东环、南堂、南教楼、综合实验楼、西廊、西环；目录 216 间，所选时段占用 66 间。古镇口返回卓越教学楼。这是本次请求时的页面数据观察，不是永久配置或实时可用承诺，不将这些数量写死在 App 中。

没有拉取房间课程详情，也没有收集学生课程、姓名或个人业务数据。测试中的小型样本仅覆盖公开房间目录字段和占用代码匹配，不携带认证信息。

## 原生实现

- `FreeClassroomScreen(onBack)` 提供校区、日期、教学楼、1–13 节多选与手动查询，原生展示所选节次均未占用的教室和容量；无预约动作、无 WebView。
- `PublicFreeClassroomRepository` 使用系统 `HttpURLConnection` 和已有 kotlinx.serialization；无新增网络依赖、无后台任务、不自动轮询。
- 请求固定学校 HTTPS 地址，禁止跟随重定向，不提交账号或会话参数，不把响应 Cookie 持久化；限制连接/读取超时和响应大小。
- 根字段、业务错误、占用字段缺失、校区或楼宇不一致均作为失败，不能返回“全部空闲”。
- 结果显示查询条件与获取时间。调整筛选后隐藏旧列表，要求重新查询；相同筛选重试失败时仅显示明确标为“上次成功结果，未能更新”的内存结果，不冒充当前状态。
- 查询成功但目录为空时明确表示学校未返回目录；这不同于“所有教室空闲”。网络或服务异常显示重试，不显示假教室。

公开页目前可用不保证后续永远开放。若学校以后增加认证或改变协议，需要重新核验，不能自动跳认证、套用已有凭据或降级为编造数据。

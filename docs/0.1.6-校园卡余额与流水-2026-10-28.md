## 本轮改动

按用户最新要求增加校园卡余额和个人流水。保留已由用户真机确认可用的图书馆功能；本轮暂停课表开发，等待新入口。

校园卡进入学校官方平台登录选择页 `https://mb-xyk.upc.edu.cn/plat/?name=Login`，提供学校页面本身的统一认证、学号登录。学校页面处理密码和验证码；App 不读取密码输入框。App 在限定的官方平台页面读取登录成功后的业务令牌，通过余额接口验证成功后采用；开启“记住学校登录”时复用现有 Keystore 加密会话存储。

余额和流水使用原生界面。流水由用户主动查询，按月、每页 20 条，提供翻页；显示金额、交易时间、摘要及服务返回的交易后余额、记账时间。金额按分解析。流水仅在页面内存保留，不写入磁盘。网络错误保留旧页并标明失败，登录失效只清理校园卡会话。没有添加充值、支付、绑卡或改密操作。

## 公开前端核验与故障修复

使用 REA 分析学校公开发布的 JavaScript 和 HTML。证据保存在本机 `E:\UPCpocket\artifacts\card-native-2026-10-28`。静态分析不代表真实账号业务验证成功。

个人流水来自官方个人账单前端，GET `/berserker-search/search/personal/turnover`，使用业务认证请求头，参数为页码、条数、日期范围与排序，不接受另一个人的学号或证件号。解析学校 `records/pages/total`，结构错误与合法空记录分别处理。

复现并修复两个登录显示问题：

1. 同一模拟器 WebView 访问校园卡 GET 资源连接重置，而 Android 原生 HTTP 访问正常。增加仅校园卡 HTTPS 域名的 GET 传输兼容，保留严格证书校验、超时、大小限制及 App 自己的 Cookie；登录表单 POST 仍由官方 WebView 页面提交。
2. 学校平台登录文档及根容器高度为零，导致已有输入框不可见。仅在校园卡 `/plat` 页面修正根容器高度，未改写表单或读取输入值。

旧的硬编码 CAS 服务曾显示“未注册的信息系统”。本版使用学校平台提供的登录选择页；不声称学校 CAS 注册问题已经解决。若统一认证失败，可选择平台自带的“学号登录”。

## 手机验收

1. 覆盖安装本 APK，确认原日程仍在。
2. 更多 → 校园服务 → 校园卡余额与流水 → 登录。
3. 在官方平台选择登录方式；若统一认证报服务未注册，尝试“学号登录”，按学校页面正常输入本人账号、密码和验证码。
4. 登录后应返回原生余额页。对照学校官方页面核实金额及账户含义。
5. 点击“查询本月流水”，核对金额、收支方向、交易时间；切换上月，数据较多时检查翻页。
6. 断网查询应明确失败，不能变成零余额或“无流水”。恢复网络后重试。
7. 开启“记住学校登录”后退出 App 再打开，检查服务端会话仍有效时能否复用；手动退出学校登录后应重新认证。

反馈失败时请说明停在哪一步及页面提示即可；不要发送密码、验证码、Cookie、令牌或未脱敏流水。若表单能显示但提交失败，下一步应定位官方登录 POST 的真实行为，而非继续修改余额展示。

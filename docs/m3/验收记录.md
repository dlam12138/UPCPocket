### 2.1 环境问题与真实认证

首次真实测试返回 `NETWORK_UNAVAILABLE`。检查发现模拟器 Wi-Fi 处于 disabled，`wlan0` DOWN；
启用 Wi-Fi 后 `ping 8.8.8.8` 成功、`cas.upc.edu.cn` 可解析。随后重新执行，结果：

```text
com.upcpocket.app.timetable.RealTimetableAuthTest.realCasLoginAndOneWeekRead
OK (1 test)
```

实际覆盖：

1. 使用用户授权的本地当前学校账号一组（来自 `E:\UPC-MCP` / `E:\Personal-Assistant`
   的本机 DPAPI 状态，只读、未重绑、未删除）；账号/密码只在宿主机进程内解密，经
   `adb shell run-as ... tee` 标准输入写入 target app 私有临时文件，未进入命令行参数、
   Gradle `-P`、Intent、日志、聊天、截图、源码或 fixture。
2. Android app 用真实 Keystore 保存账号，状态为 `SAVED_UNVERIFIED`；测试只用它完成一次
   正常 CAS 表单登录、票据回调、`get-index` 与单周只读查询。未预约、报名、签到、充值或
   尝试其他账号。
3. 认证与单周读取通过；测试随后用新的 Store 实例重新读取本机加密会话与缓存，二者均非空、缓存含 7 天日期，证明设备上的原子写/读可用；未出现验证码/二次验证，因此没有真实走 WebView 验证码链路。
4. 测试与实际页面均未输出课程原文；验收记录只保留状态、周次和布尔检查。
5. 清理：测试结束删除账号密文、临时凭据、课表会话与缓存；检查 `no_backup/school-account/`
   无密文、`no_backup/timetable/` 为空、临时 `files/m3-credentials.json` 不存在。

## 4. 数据兼容取舍

**选择：保留停用的旧表结构，不做破坏性迁移。**

- Room 仍是 `version = 1`；`semesters`、`courses`、`course_sessions`、`periods`、
  `display_overrides` 五张表只在 `@Database` 里保留实体声明，**没有 DAO 或任何读写路径**
  （见 `data/db/LegacyScheduleTables.kt`）。
- 理由：这些表与 `focus_tags` / `focus_sessions` 同库。直接从 entities 里删表会改变 Room
  的 schema identity，已安装用户升级时会被判为结构不一致，只能 destructive migration
  或清数据 —— 与本轮「不能为了删功能而清数据」的要求冲突。
- 实测：升级前设备数据库 `identity_hash = 62e4b0998501030df70b77a392a012f5`，
  新版本生成的 schema identity 相同；覆盖安装后应用冷启动正常，Room 校验通过。
- 升级前后行数（同一台模拟器，未卸载、未清数据）：

  | 表 | 升级前 | 升级后 |
  | --- | --- | --- |
  | `semesters` | 1 | 1 |
  | `courses` | 6 | 6 |
  | `course_sessions` | 54 | 54 |
  | `periods` | 13 | 13 |
  | `display_overrides` | 0 | 0 |
  | `focus_sessions` | 0 | 0 |
  | `focus_tags` | 0 | 4（打开「专注」时按既有逻辑种入默认标签） |

- 旧 DataStore 中的课表样式键不再读取，也不删文件；主题、记住登录、电费楼号照常读取。
- 课表历史数据仍在数据库里，App 内没有入口读取；本版不主动删除。
- 没有 `destructiveMigration`、没有卸载、没有清应用数据。

## 7. 未验证 / 风险

- **真实账号流程**：图书馆登录与预约、校园卡流水登录没有在本轮重新走一遍（模拟器无用户凭据；
  用户手机在 0.1.10 已验证过余额与图书馆）。删除课表没有改动这些业务的数据层与登录客户端，
  但仍应在本机覆盖安装后点一次图书馆与校园卡，确认会话仍可用。
- **唐岛湾电量值**：只验证到楼号列表加载，没有用真实房间号查询（房间号属于个人居住信息）。
- **古镇口电费**：仍是外部浏览器/微信，学校证书过期；未做原生接入。
- **微信直达**：未配置正式 AppID，仍只有复制/分享兜底。
- **课表旧表**：保留结构属于兼容取舍；若将来确认要彻底清理，需要单独设计一次可回滚的迁移。
- 模拟器为软件渲染（headless），UI 截图未逐像素核对；点测以 accessibility 树与真实查询结果为准。

## 3. 本轮修改

### 3.1 诊断 schema 3

新增可选固定字段：

- `mediaType`：`JSON` / `JSON_SUFFIX` / `TEXT` / `HTML` / `OTHER` / `MISSING`
- `bodyType`：`JSON_OBJECT` / `JSON_ARRAY` / `HTML` / `LOGIN_LIKE` / `EMPTY` / `MALFORMED` / `OTHER`

失败事件同时带 `detail`、`mediaType`、`bodyType`、`responseBytes`；成功接受 MIME 误标时记录 `QUERY_CHANGED OK reason=MIME phase=RESPONSE detail=RESPONSE_MIME_MISMATCH`，与同一 `operationId` 的 WEEK 事件可关联。

仍不导出：URL/query、头原文、正文/HTML/前缀、字段值、账号、Cookie/token、课程/教师/地点、异常 message。导出仍是用户主动生成 ZIP、私有目录、24h/约 1MiB/队列/epoch 清理，诊断失败不影响业务。

### 3.2 响应分类

新增 `TimetableResponseClassification.kt`，只在内存中做有界分类：

- MIME 解析忽略大小写与 `;charset=...`；`application/json` 为 `JSON`，任意合法 `+json` 后缀为 `JSON_SUFFIX`，`text/html`/`application/xhtml+xml` 为 `HTML`，其它 `text/*` 为 `TEXT`，缺失为 `MISSING`，其余为 `OTHER`；多个不一致值归 `OTHER`。
- 正文：空/空白 → `EMPTY`；`<` 开头且 HTML 特征 → `HTML` 或 `LOGIN_LIKE`（CAS URL、密码表单、`loginForm`、`errorDiv`、统一身份认证、CAS login 提示）；`{`/`[` 开头解析失败 → `MALFORMED`；可解析 JSON object/array → 对应类别；JSON 标量 → `OTHER` 但 `validJson=true`，交给协议报 shape；其它 → `OTHER`。
- UTF-8 BOM / UTF-16 LE/BE BOM 在内存中解码；不保留、不输出原始字节。
- `+json`、大小写和 charset 只用于分类；不改变 2 MiB 上限、TLS、固定 host/path、禁止重定向和认证单次恢复边界。

### 3.3 接受与拒绝

对固定受信 endpoint 的 HTTP 200：

1. 先检查大小和空正文。
2. 分类正文；`EMPTY`/`HTML`/`LOGIN_LIKE`/`MALFORMED`/非 JSON 文本直接拒绝，分别给固定 detail。
3. 只有正文整体可解析为 JSON 才继续；有效 JSON 即使 MIME 为 `HTML`/`TEXT`/`OTHER`/`MISSING` 也接受，并记录 `RESPONSE_MIME_MISMATCH`。
4. 之后仍由 `TimetableProtocol` 执行完整 envelope/业务 schema：`e`/`d`/7 天/连续日期/请求周日期对齐/课程名/lessArr/节次/周标签等核心规则不变；核心字段错误仍整周失败，不产生部分周、不假空课表、不覆盖完整缓存。

新增固定 detail：

- `RESPONSE_HTML`：非登录 HTML。
- `RESPONSE_MALFORMED_JSON`：以 `{`/`[` 开头但 JSON 解析失败。
- `RESPONSE_MIME_MISMATCH`：有效 JSON 被非 JSON MIME 标注，已按严格 schema 接受。
- `RESPONSE_NON_JSON`：正文不是 JSON（文本/JSONP/其它）。
- `RESPONSE_LOGIN_PAGE`：登录页。
- `RESPONSE_BUSINESS`：JSON 业务码非 0（非认证失效）；`e=10013` 单独标 `AUTH_REQUIRED`，不再混成 `RESPONSE_NON_JSON`。

### 3.4 UI 文案

- 登录页：`登录状态已失效，请重新网页登录。`
- 普通网页：`课表返回了网页内容；已保留上次缓存。` / `…；暂无可用的旧缓存。`
- malformed/non-JSON/空：`课表响应格式异常；…`
- 过大：`课表响应过大；…`
- 网络/TLS/超时/服务 HTTP：沿用原有明确文案。
- 有/无缓存仍分别用“已保留上次缓存”/“暂无可用的旧缓存”，不把格式错误归因于用户、密码或学校风控。

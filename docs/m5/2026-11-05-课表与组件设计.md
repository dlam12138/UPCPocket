# 课表、桌面组件与超星预约设计

2026-11-05，用户新要求，供 @4 实施与验收。以现行 M5 为基础，不恢复研讨间，不迁移 Glance / Navigation / Gradle 架构。

## 1. 课表页面

顺序：固定页头 → 紧凑学期/教学周选择条 → 今日课程 → 周网格。大段只读说明收进信息按钮，不占主页面。今日课程始终是上海时区实际今天，不随查看其他教学周假装变成今天。

今日课程使用一张紧凑卡片：标题「今日课程」与日期同行，每条显示课程名、实际起止时间、地点；教师放详情，不在窄屏挤占主信息。进行中标「上课中」，未来下一门标「下一堂」，已结束弱化。课程色条复用持久颜色映射。无课程显示「今天没有排课」；无缓存/未查询不能当作无课程。

周网格列顺序：日、一、二、三、四、五、六。保留 ISO weekday 模型和源数据，不把 Sunday=0 写回领域数据。必须核对学校教学周日期边界：不能简单旋转旧周日到最左导致周日期错序、跨周课程归错；优先按真实日期构建连续周日到周六视窗，必要时合并相邻源教学周，禁止重标课程日期。界面选择周与学校教学周的对应关系须明确。

普通手机七列同屏。左轴约 44–48dp，显示节次（强调）和开始/结束时间（次级、两行）；每节约 44–48dp 起，优先可读，不以缩到不可辨认来追求整天同屏。横向保持完整一周，纵向可滚动；星期头与左轴保持对齐，顶栏不遮挡。窄分屏/大字体允许可发现的横滑兜底。正常字体课程名 11–12sp 左右，详情补全；不继续收窄字号。

时间优先用学校官方作息/响应，并按校区/学期适用范围建独立配置；缺失显示「时间待确认」，不凭节次等差推算。用户 WakeUp 参考仅用于布局，12–15 节有明显重叠，不能照抄为 UPC 官方时间。时间不影响源节次与日期归属，模型不得为迎合参考图擅自新增第15节。

## 2. 今日课表 RemoteViews 小组件

新增一个可调整大小组件：默认 2×2，与现有余额/电力统一圆角、背景、内边距和主题。支持扩到4×2，不为尺寸另建多个入口。整体点击进入课表 tab；右上小刷新按钮有独立 PendingIntent 与48dp点击区域，不误触整卡。无额外复杂配置页。

信息草图：

```text
今日课表                 11.5 周四  ↻
┃ 下一堂 · 14:00–15:35
┃ 化工原理（2–2）…
┃ 卓越 B205
──────────────────────────
  15:55  数据处理与实验设计…
         卓越 B325
```

2×2：标题12–13sp，主课名16–18sp最多两行，时间13–14sp，地点12–13sp；次课一到两行。4×2留足空间显示2–3条，非机械拉大字体。浅色沿现有组件浅底，深色近实底炭黑；色条沿用同一课程槽位，正文保持对比度。只在有可靠时间时显示「下一堂/上课中」，否则按节次排序且显示节次。不展示教师/学号，减少桌面暴露。

状态：上课中、下一堂、今日已结束、今天无排课、需先同步课表、缓存/离线、账号清理中。缓存标上次同步；断网保留本账号旧数据并标旧，不清成「无课」。未同步今天不推断无课；不遍历全学期拉取。

组件从持久化、绑定账号/凭据代次/学期的最小本地快照冷启动渲染，不能依赖 Activity/ViewModel/StateFlow 已初始化。换号、删号、个人数据清理立即清除快照与旧任务。渲染和更新保持插件依赖边界，不让 feature 反依赖 app。

跨日、时区/时间变化、组件更新与尺寸变化重新计算本地显示，应用普通进程死亡后仍能工作；按需用现有 WorkManager 安排本地重绘，不承诺系统保证分钟级精准、不周期性登录学校。用户点刷新可触发一次受控当前课表读取，验证码仅提示打开应用。明确区分「刷新显示」和「同步学校」的实现，避免刷新按钮没有实际效果。

## 3. 余额组件后台刷新故障

验收目标：移除最近任务/正常进程被回收后，不先打开 Activity，点击余额组件刷新仍能初始化账号绑定、执行单次查询并更新所有组件实例。检查 Application/AppGraph 冷启动、插件注册完成时序、账号绑定恢复、BroadcastReceiver/Worker生命周期、唯一任务与 refreshing 残留、PendingIntent 身份。

Worker应等待有限的持久状态恢复，不把「尚在初始化」当作「无账号/功能未启用」。保留旧值与时间，失败结束 loading 并提供简短状态，不能复活旧账号快照。不要常驻服务/保活/无限重试，也不把让用户关闭省电作为代码修复。系统设置“强行停止”会限制后台执行，需单独报告，不与普通进程死亡混为一谈。

## 4. 超星原生预约

现状只读解释清楚，但本轮目标补齐用户手动选座→选真实可约时段→确认→原生提交的闭环，seat/seatengine分别核对契约。真实已用状态未知时不得标「可选」或允许确认。查看区间不等于预约规则，不能仅用 timeUnit/开放时间推导可约时段。

以正常官方页面公开脚本、既有 HAR、已授权账号只读数据核对提交字段/校验/响应/幂等边界；实现阶段可用合成服务测试写协议，不执行真实预约、取消、签到。只在用户最终确认时发送，不自动重试提交；超时结果不明先提示核对预约记录，不能双重占座。会话本人和账号代次校验沿用现有门闩，选择校区/日期/座位/时间变化清空旧确认；提交前刷新规则/状态，不承诺消除服务端并发占用。

若确有验证码/位置/必须官方交互等规则，只对该分支明确回退，不能再次把“全部跳官方页”当作原生预约完成。真写验收另需用户确认具体座位和时间，本轮不创建真实预约。

## 5. 交付验收

- 同一门课在网格/今日/组件颜色一致；7列周日开头、日期连续且正确跨教学周，含周日/周六/跨月/学期边界测试。
- 时间来源、未知时间与参考图差异如实记录；截图使用合成数据，禁止把用户真实课程/姓名截图入库。
- 360dp与约400dp宽、浅深色、1.0/1.5倍字体，页内与组件实机Launcher安装/resize/点击验收。
- 余额/电量/课表：正常杀进程后刷新、断网收尾、跨日、换号清理、重复点击、多个实例检查。不要 pm clear/uninstall；避免 connected 全套导致卸载。
- 相关测试、assemble、lint、模块边界；原生预约只做协议/服务合成测试，真实认证和读取独立记录。
- 更新现行README/AGENTS中“课表不含组件”的范围；本地提交、APK绝对路径与未验证项，不push/merge。

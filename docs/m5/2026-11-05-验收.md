## 1. 超星座位图空白

### 根因

真实 `GET /data/apps/seat/getdrawseat?id=8548` 返回 48 个座位，字段是浮点：

- `xleft: 166.0..2736.0`
- `ytop: 129.0..292.0`
- `width/height: 75.0`
- `rotate: 90 / 270 / 630`

旧 `ChaoxingProtocol.parseSeatPlaces` 用 `intOrNull()` 读取；`166.0` 既不是 Int，`"166.0".toIntOrNull()` 也失败，于是 x/y/width/height 全部退化为 0。`ChaoxingSeatMap` 再把 `maxX/maxY` 收敛到 1，地图只有约 17dp，48 个座位叠在左上角；标题、时段、图例、底栏都正常，所以看起来正是“图区域空白、不能点”。

### 修复

- `ChaoxingSeatPlace` 的坐标/尺寸改为 `Float`，旋转归一化到 `[0,360)`；缺字段或宽高 ≤ 0 的座位跳过，全部无效时返回 `chaoxing_protocol`，不再静默画空图。
- 地图按真实包围盒（减去 `minX/minY`）缩放；优先适配宽度，但保留 0.28 的最小比例与 22dp 的最小可点尺寸，长排座位图允许横滑。
- 已用座位与座位图分开落地：图先显示；`getusedseatnums` 失败时图仍在，但状态明确为“已用座位未取得”，图例显示“已用未知”，不能用空集合冒充“0 个已用”。
- 合成回归固定真实结构（浮点、`rotate=630`、长排范围）；座位号和 id 已替换，见 `feature/library/src/test/resources/chaoxing/getdrawseat-synthetic.json`。

### 证据

- 真实 Android 进程内 `RealChaoxingAuthTest`：本人核验 → seat 区域（6 个：48/44/52/44/66/66 座）→ 首个区域详情（48 个座位，`timeUnit=30`，08:00–21:30）→ 已用座位查询 → seatengine 区域（21 个）。测试通过，3.173s，未跳过。

## 2. 登录后“跳转到了未允许的地址”

### 实际链路

用本机保存凭据走正常官方链路（只记录 host/path，不记录 query/ticket/cookie）：

```text
office.chaoxing.com /front/third/apps/seat/index
  -> tyrzfw.chaoxing.com /auth3/upc/cas/init
  -> cas.upc.edu.cn /cas/login
  -> tyrzfw.chaoxing.com /auth3/upc/cas/index        (CAS 成功后)
  -> passport2-api.chaoxing.com /api/v2/casreceive
  -> i.chaoxing.com /base                            <-- 原先被拦
  -> office.chaoxing.com /front/third/apps/seat/index (应用回跳，建立 office Cookie)
```

`casreceive` 成功页通过 JS 把主框架送到 `https://i.chaoxing.com`；旧允许列表只有 office/passport2/tyrzfw/cas/app.upc，没有 `i.chaoxing.com`，所以登录成功后立即显示“未允许的地址”。

### 修复

- 允许列表新增 `i.chaoxing.com`，但只放行 `/`、`/base`、`/base/` 子路径；仍要求 HTTPS、端口 443/-1、无 userinfo。没有放开任意域或 TLS。
- 到达该官方落点且尚无 `oa_uid/oa_deptid` 时，WebView 只回跳一次座位入口，让官方前端建立应用 Cookie，再走既有 `tryFinish` → 本人学号核验 → 账号代次/epoch/revision/清理门闩。旧入口回调、换号、清理失败隔离不变。
- 错误提示补充被拦 host（不含 query/ticket/cookie），便于以后定位。

### 边界

- 完整“App 内 WebView 输入账密并点登录”的交互本轮没有再次人工重放；本体链路证据是：官方 CAS HTTP 全链路成功 + 同一 Cookie 在真实 Android 进程内通过生产 `ChaoxingService` 的本人核验和座位读取 + 允许列表/回跳的单元回归。不能把这次记录写成“App 内完整登录已人工验收”。
- 没有把学校密码提交到 `passport2` 学习通；没有执行预约/取消/签到。

## 4. 课程颜色

- 颜色身份：`courseId` 优先，缺省 `courseName`；不含日期/节次/教师/地点，因此同课跨日/跨周稳定。
- `coursePaletteIndex`：UTF-8 的 SHA-256 前 4 字节 → 16 色相（约 22.5° 间隔）。不再使用 `String.hashCode()%4`。
- 浅色容器 `HSL(h,0.55,0.88)` + 深色前景 `HSL(h,0.45,0.17)`；深色容器 `HSL(h,0.45,0.27)` + 浅色前景 `HSL(h,0.25,0.95)`。16 组浅/深组合全部通过 ≥4.5:1 对比度测试；文字始终保留。
- 合成预览 12 门课采样到 9 种容器色；仍有 3 组哈希同槽（16 桶的生日碰撞），但不是原来的 4 色/两色大量撞色。此剩余碰撞已记录，未用“完全无碰撞”表述。

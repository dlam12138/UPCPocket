## 7. 追加：空闲教室“假空闲”

### 根因

学校 `POST /freeclass/wap/default/search-all` 的响应有两个房间集合：

- `d.all`：所选校区/教学楼的**全部教室目录**；
- `d.js`：**空闲教室列表**；多节查询时是“所选每一节都空闲”的交集（不是占用列表）。

旧代码把 `d.js` 命名为占用列表并计算 `occupied = code in js`，语义整体反转：未进入全时段空闲交集的教室被当成“空闲”。卓越 B328 第 1–2 节有课、第 3–5 节空闲；查询第 1–5 节时 B328 不在 `js`，旧代码因此显示绿色“空闲”，与实地有课一致地暴露了根因。

2026-11-05 10:54（Asia/Shanghai）当前同一天/同校区/同楼/同节次只读响应：`js` 89 间、`all` 179 间，B328 **不在** `js`。这是当前响应，不是 09:19 的历史重现；09:21 官方截图是 A 系列，不能作为同教室对照。官方页脚本把 `js` 命中项渲染为绿色（`is-used` 类名与颜色含义相反），09:21 截图可见的 17 个绿色 A 教室全部在当次 `js`，15 个红色教室均不在；该事实与“`js`=空闲列表”一致。

### 修复

- `available = code in js`，只有完整成功响应中明确命中的教室才可显示空闲；未命中、空 `js`、缺字段、未知码、解析失败、网络失败一律不默认空闲。
- `availableRooms`、分组空闲计数、绿色/红色、详情“空闲（所选节次均无排课）/占用（至少一节有课）”、仅看空闲筛选全部跟随同一语义。
- 默认日期固定 `Asia/Shanghai`；筛选变化取消在途请求并递增代次；只展示完整查询键相同的缓存，读取时间按上海时区显示；不同条件的旧结果不再作为当前结果展示。
- 页脚明确“绿色表示所选每一节都无排课；仅反映学校排课，临时占用/调课以现场为准”，不把公开页当成临时占用保证。

## 8. 追加：超星保存学校账号自动登录

### 协议与实现

已确认真实链路（只记录 host/path，不记录 ticket/query 值）：

```text
office.chaoxing.com /front/third/apps/seat/index
  -> tyrzfw.chaoxing.com /auth3/upc/cas/init
  -> cas.upc.edu.cn /cas/login
  -> tyrzfw.chaoxing.com /auth3/upc/cas/index
  -> passport2-api.chaoxing.com /api/v2/casreceive
  -> office.chaoxing.com /front/apps/seat/index

```

- 新增 `UpcChaoxingAuthenticator`（`core:upc-auth`），复用 `SchoolCredentialAccess` 与公共 `UpcCasLogin`。密码只提交给精确的 `https://cas.upc.edu.cn/cas/login`；不提交给 passport2 手机号/超星号表单，也不提交给任何非 CAS 主机。

### 本地跨日/时间重绘与进程死亡

- 新增 `TimetableWidgetTicker` + `TimetableWidgetTickWorker`：**只重绘本地缓存，不恢复账号、不联网、不打开 Activity**。每次组件更新/刷新后安排一个唯一一次性 WorkManager 任务，目标是最早的下一次本地上课开始、当前课结束或上海时区午夜；若没有可靠当天快照则安排到午夜。
- `nextBoundary` 单测覆盖：当前课结束、下一课开始、过期的日期/无快照回午夜、全部结束后仍安排午夜。工作名 `timetable-widget-local-redraw`；最后一个实例删除时取消。
- API 36 实测 `dumpsys jobscheduler` 有 `Trace tag: TimetableWidgetTickWorker` 的 WorkManager job（无数据时为 `Minimum latency: +10h46m`，即上海午夜）；`am kill com.upcpocket.app` 后进程消失、job 仍在，说明普通进程死亡不是靠 Activity/点击才刷新。系统“强行停止”会移除/禁止该包后台任务，不能用它来证明 WorkManager 一定执行；Doze/app-standby/厂商调度还可能延后，所以这是 best-effort 本地重绘，不承诺分钟级精准，也不做周期登录。
- 未把 `updatePeriodMillis` 改成周期网络刷新；所有联网仍只由用户点击刷新触发。

### 超星未知结果的服务层防重

- `ChaoxingService` 在内存中记录 **(用户 sno + kind + room/date/start/end/seat)** 的 `Unknown` 提交；关闭详情页、重建 ViewModel 后再次提交同一请求会直接返回 `Unknown`，不再 GET select 或 POST submit。只有会话清理/退出登录会清空该集合（明确开启新会话后才能重试）。
- 合成测试 `unknown submit is blocked again in the same service session`：第一次 fake POST 返回 500 → `Unknown`；第二次同参数调用不再发 POST；断言 POST 次数为 1。没有真实预约、取消或签到。
- 边界：普通进程死亡会清掉这个内存集合；这是“会话范围”而非跨重启持久化。若进程在未知提交后被杀，用户仍应先在官方记录核对；代码不会在重启后自动重发。

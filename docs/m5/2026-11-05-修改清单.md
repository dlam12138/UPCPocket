## 6. 空闲教室假空闲（2026-11-05 追加，优先）

- 现象：用户 2026-11-05 09:19 在 App 查询古镇口/卓越 B328/第 1–5 节，结果绿色“空闲”；实地该教室有课。09:21 官方截图是卓越 A 系列，不是同教室/同参数对照，不能直接据此判断哪一层错误。
- 根因：学校 `search-all` 的 `d.js` 是**空闲教室列表**，多节查询返回“所选每一节都空闲”的交集；`d.all` 才是全部教室目录。旧实现把 `d.js` 当占用列表，`occupied = code in js`，于是 B328 因第 1–2 节有课、未进入 1–5 节的全时段空闲交集，反而被标为绿色“空闲”。这是客户端字段语义反转，不是校方数据错误。
- 修复：改为 `available = code in js`；只有完整成功响应中明确命中的教室才可显示空闲。未命中、空 `js`、缺字段、未知码、解析失败、网络失败一律不默认空闲；`availableRooms`、分组计数、颜色、详情文案、筛选全部跟随同一语义。默认日期改用 `Asia/Shanghai`；筛选变化取消在途请求并递增代次，旧响应不能覆盖新筛选；只展示完整查询键相同的缓存，读取时间按上海时区显示；不同条件的旧结果不再作为当前结果展示。
- 验证：同一天/同校区/同楼/同节次的当前真实响应（2026-11-05 10:54，古镇口/卓越/1–5）返回 `js` 89 间、`all` 179 间，B328 **不在** `js`；App 端到端显示“空闲 89 / 全部 179”，B328 为“占用”，详情为“占用（至少一节有课）”；同页 B341 明确为“空闲（所选节次均无排课）”。这是当前响应与 App UI 的交叉核对，不冒充 09:19 历史重现。合成回归覆盖混合时段、空/缺失 `js`、错误码、不同日期/校区/楼、迟到响应与默认时区。
- **状态：已完成。**

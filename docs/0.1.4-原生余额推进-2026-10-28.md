## 2. 唐岛湾电费：这一条已经跑通

### 真实请求链（2026-10-28 核验，只读）

```text
GET  http://dfcz.upc.edu.cn/ShiYou/Default.aspx            → 302 到 open.weixin.qq.com（缺 code）
GET  http://dfcz.upc.edu.cn/ShiYou/Default.aspx?code=0     → 200，返回查询表单
      表单含 __VIEWSTATE / __VIEWSTATEGENERATOR / __EVENTVALIDATION + 楼号下拉（42 个选项）
POST http://dfcz.upc.edu.cn/ShiYou/Default.aspx
      __VIEWSTATE=…&__VIEWSTATEGENERATOR=…&__EVENTVALIDATION=…&lou=01号楼(1)&yonghu=1101&chaxun=查询
     → 200，页面出现 <table id="yongdianGrid">：当前剩余电量 17.34度 + 系统编号 + 房间号
```

关键事实：

- `code` 只用于“有没有”，不校验内容：`code=0`、`code=app`、`code=STATE` 都能拿到表单；**缺省**才 302。
- 服务端按房间号**模糊匹配**。输入 `101` 时，页面会同时给出候选表（`1101`、`商铺101校园文化`）
  **和**第一间房的电量。只看 `yongdianGrid` 会把别人的电量显示成你的。
- 页面里的“充值”按钮是同一表单的另一个 submit；本 App 只发 `chaxun=查询`，从不发 `chongzhi`。

### 本轮因此修掉的真缺陷

真机实测发现“输入 101 却显示 1101 的 17.34 度”之后，解析改成**必须用用户输入的房间号做精确比对**：
候选表里恰好有一条与输入完全一致才直接返回；其余一律回到“请选择是哪一个”，绝不代猜。
回归测试 `模糊命中时即使页面带着别的房间电量也不能当成用户的结果` 钉住这条。

### 设备实测（Android 36 模拟器，2026-10-28）

- 楼号列表来自学校页面本身（`01号楼(1)` 等），不是写死的常量。
- 输入 `1101` → 原生显示 `17.34 度`、`01号楼(1) · 1101`、系统编号 `0022250003`、读取时间。
- 输入 `101` → 列出两个候选并让用户确认，不再显示 17.34 度。

## 3. 校园卡：认证链查清了，代码接上了，本人数据还差一次登录

### 本轮查到的真实链路

学校旧地址 `jhzf.upc.edu.cn:20081/wechat/query/balance.html` 只有微信入口，
返回“无效token”，**不是**可用入口。真正在用的是新中新“慧新E校”移动平台：

```text
GET  https://mb-xyk.upc.edu.cn/berserker-auth/cas/redirect/wislearn?targetUrl=<平台首页>
     → 302 到 https://cas.upc.edu.cn/cas/login?service=<上面那个地址>  （学校统一认证）
登录成功 → 回调 /berserker-auth/cas/login/wislearn?ticket=…
     → 平台在 URL 上带回 synjones-auth=<token>，落到 /plat/?name=loginTransit
GET  https://mb-xyk.upc.edu.cn/berserker-app/frontInfo                     （公开）
     → getEcardConfig.type 决定金额口径
GET  https://mb-xyk.upc.edu.cn/berserker-app/ykt/tsm/queryCard
     Header: synjones-auth: bearer <token>
     → {"code":200,"data":{"card":[{account, cardname, db_balance, unsettle_amount, accinfo[] …}]}}
```

金额口径（平台前端 `chunk-0fdb9c48` 原文逻辑，单位为**分**）：

- `type=0`：`db_balance + unsettle_amount + Σ accinfo[].balance`
- `type=1`：`Σ accinfo[].balance`
- `type=2`：`db_balance + unsettle_amount`（学校当前配置）

`queryCard` 未带令牌时返回 `401 {"code":401,"message":"缺失令牌,鉴权失败"}`，所以它确实受保护。

### 已实现

- `data/ecard/CampusCardProtocol`：按上面三个口径算余额；字段缺失、类型不符、口径未知一律报错，
  **不会把“没读到”显示成 0 元**。金额用整数分，展示时才换算成元。
- `data/ecard/CampusCardClient`：只发两个 GET；401/403 归类为“会话失效”，其余网络错误归类为“暂时不可用”。
- `data/ecard/CampusCardService`：登录令牌接管、密文恢复、换号隔离、断网保留。
- `ui/ecard/CampusCardLoginScreen`：WebView 只放行 `https://*.upc.edu.cn` 与
  `http://mb-xyk.upc.edu.cn/{plat,berserker*}`；令牌只从回跳 URL 的查询参数读。
- `ui/ecard/CampusCardScreen`：卡余额、待圈存、口径、读取时间、挂失/冻结、上次成功值、退出与换号说明。

## 12. 追加：图书馆并未停用（一次差点误判的纠正）

第一次用脚本复算签名时，我把 AES 解密结果**连 PKCS#5 填充一起**当成了 HMAC 密钥，服务端返回：

`
{"status":"fail","code":"20","message":"请检查手机时间是否准确,另外手机app已停用,请使用微信小程序\"一考即过座位预约\"等方式预约"}
`

这句话足以让人得出“学校已停用网页/App 预约、只能走小程序”的结论。但它是**签名不匹配的统一提示**，不是服务状态：

| 密钥 | 同一请求的结果 |
| --- | --- |
| 带填充（10 字节，尾部 0x07） | code 20 + “手机app已停用…” |
| 剥掉填充（9 字节 6c656f733363723374） | code 12 + “登录失败: 用户名或密码不正确” |

code 12 是业务级“未登录”，说明接口在线、签名有效、只是没有会话。
Java 的 AES/CBC/PKCS5Padding 会自动去填充，所以现有 Kotlin 实现一直是对的；
错的是我那次 Python 复算。

因此：

- **不改** configKey()；新增测试钉住“密钥必须是剥掉填充的 9 字节”，长度一变就会退回 code 20。
- nsureBusinessSuccess 对 code 20 保留学校原文，并追加一句本地判断
  （“这是请求签名或手机时间不匹配，不是预约功能停用；请先校准手机时间后重试”），
  避免用户看到“已停用”就放弃。
- code 12 仍按会话过期处理。

图书馆的真实登录、查询、预约与取消**仍然只差本人账号**，但它并没有被下架。
## 13. 追加：上次成功值改为跨重启保留

计划要求“失败但有旧值”“断网保留成功时间”。审计发现原实现的 lastSuccess 只存在
Compose 内存状态里：**重启后遇到断网，界面会退化成“从没查过”**，用户会以为余额丢了。

已改为独立加密快照（SchoolSessionStore.SavedCampusCardSnapshot）：

- 只存展示所需字段（分、待圈存、口径、卡名、账号、读取时间），**不存令牌**；
- 每次成功读取后写入；lastSuccessAt() 返回服务端那次读取的时间，界面不再用本地时钟冒充；
- 退出校园卡时与令牌一起清掉——换人后不能看到上一个人的余额；
- 令牌密文损坏时**只丢令牌、保留快照**（快照带账号与时间，不会被误当成实时值）；
- 新增 2 项测试：重启+断网仍能读到旧值且退出后为空；从未成功时不伪造旧值。

界面读取顺序：持久快照 → 恢复会话并验证 → 失败时显示“上次成功 + 时间（不是实时值）”。
## 14. 追加：校园卡登录令牌的三种漏读方式

平台自己的参数解析器（dist 里的 getRequest）在 ? 出现在 # **之后**时会解析
# 后面的查询串；而 CAS 回调实际会落到 /plat-pc/#/...。原实现只读 ? 到 # 之间，
三种情况下会“登录成功却读不到令牌”，并被错误地显示成“令牌无效”：

| 形态 | 原实现 | 现在 |
| --- | --- | --- |
| …/plat/#/loginTransit?synjones-auth=… | 读不到 | 能读到 |
| …/plat-pc/#/?synjones-auth=… | 读不到（且 /plat-pc 不在白名单） | 能读到 |
| 令牌含 %2B / %2F 等编码 | 未解码，值就是坏的 | 按 decodeURIComponent 解码 |

另外把 http 明文白名单从 startsWith("/plat") 改为**按路径段**判断：
子串匹配会把 /platform-evil/x 也放行，属于开放重定向面。现在只接受
plat / plat-pc / erserker / erserker-* 作为第一段。

## 15. 追加：“记住登录”关闭时不能留下余额痕迹

原先 efresh() 无条件调用 saveCampusCard 与 ememberSnapshot，
**即使“记住学校登录”是关的**，余额与令牌仍会被加密写进磁盘。
开关的含义因此是假的：用户以为关掉就不留痕，实际盘上还有。

已改为显式 persistAllowed：

- 由接管令牌时的 emember 决定，恢复会话时置为 	rue，退出时置为 alse；
- 为 alse 时内存里照常可查、可显示，但令牌与快照都**不落盘**；

## 16. 追加：earer 前缀重复会把登录变成必然 401

平台前端里同时存在两种写法：

- 传令牌时写成 "&synjones-auth=bearer "+this.token（值自带 earer ）；
- 读令牌时直接取 URL 参数当令牌用：state.token || getRequest(...)["synjones-auth"]。

客户端原实现无条件拼 "bearer " + token。如果回调参数已自带前缀，发出去的就是
earer bearer xxx，服务端必然判为无效——用户看到的是“登录成功但令牌无效”。

已改为 uthorizationValue()：先**反复**剥掉已有的 earer 前缀（可能是两层），
再拼一次。令牌本身不变，只修正头部形态。不用登录即可用单元测试固定。

（同时修掉一个编译细节：辅助函数放在 private companion object 里时连测试模块都
访问不到，已移到文件级 internal。）
